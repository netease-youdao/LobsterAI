# LobsterAI 一次升级替换 OpenClaw

**建议发一个只带 DeepSeek Harness（DSH）的大版本。** 用户照常点一次升级。新版第一次打开时，在本机备份和转换旧数据，核对通过后直接进入原来的龙虾界面。此后新任务和旧聊天的下一条消息都由 DSH 处理。不兼容的功能按名称列在“升级备份”里，用户可以查看和导出。

## 用户点升级之后

| 用户看到什么 | 程序实际做什么 |
|---|---|
| **准备升级** | 安装包自带适合本机的 DSH。提示将停用的功能和所需空间。遇到正在执行的任务，允许用户等它结束或主动停止。旧客户端无法提前显示个人清单的，先在更新说明列出受影响功能，首次启动再展示本机具体对象。 |
| **正在备份和整理数据** | 新程序确认旧应用及其后台进程已停止写入，再为旧数据建立可校验的本地快照。将聊天、智能体、附件、设置等在新位置整理好。进度按对象显示，例如“已检查 320 / 480 个附件”。中断后从已完成的位置继续。 |
| **升级结果** | 列出“已迁移”“需要重新连接”“已备份并停用”和原来就缺失的文件。每条都有名称和处理入口。例如某个飞书机器人需要扫码，直接提供重连按钮。 |
| **继续使用龙虾** | 用户打开昨天的聊天，输入“把上次的表格按金额排序”，DSH 从该对话的近期内容、已确认要求和相应文件开始工作。完整旧记录仍可翻看、搜索，必要时可补选更早的消息。历史里的邮件、命令和群消息只作记录。 |

迁移结束时，所有发现的对象都应有去向。核心历史或产品托管文件出现无法解释的缺失，就保留快照并进入修复页，用户可以重试、查看或导出可读历史。磁盘不足时可先释放空间或选择备份位置。没有旧数据的新用户直接进入新引擎。

## DSH 从零怎么设计

**龙虾保存用户的工作，DSH 负责完成下一项任务。** 聊天、智能体、文件、账号、积分、权限和对外发送的结果由龙虾管理。DSH 在一个独立后台进程里运行，负责调用模型、执行获准的工具、报告进度和停止任务。未来升级 DSH，用户的历史和工作文件仍由同一套龙虾数据管理。

- 龙虾主进程用一套接口对接 DSH，先接通新建、发送、进度、追问和审批、停止、重连及文件结果。优先采用 DSH 原生会话控制接口，版本随安装包固定。原生接口已有会话取消、实时输出、断线补读和按请求标识识别重复提交的能力。涉及扣费或对外发送的结果仍分别核实。[DSH 官方会话接口](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/api/session-controller/README.zh.md)
- DSH 使用龙虾专属目录与配置，按用户或企业身份隔离，账号切换时结束旧身份的执行。模型和工具按用户原来选择的账号与授权接入。工具里需要访问浏览器、Office、文件、群聊或付费服务的操作，由龙虾确认该会话有权使用。
- 每条聊天保留自己的龙虾编号。旧历史一次性整理为龙虾可读的记录。用户第一次继续时，在这条聊天底下创建新的 DSH 任务，带入当前选中分支的必要内容。无需把 OpenClaw 内部执行日志伪造成 DSH 运行过的任务。
- 只保留一个正式执行入口。旧格式读取器只负责解析文件；可以在多年后直接读取老备份。新版安装、启动、修复与更新均独立于 OpenClaw。打包时移除原网关、解包和启动脚本，并检查升级后遗留的旧程序文件。用户安装在其他位置的独立软件不属于清理范围。[原运行包位置](../../../electron-builder.json#L163)

## 迁哪些，备份哪些

| 对象 | 处理办法 |
|---|---|
| 聊天、分支、编辑过的回复、智能体、个性指令、记忆 | 作为正式数据迁入，保留原顺序、关联和可见范围。读取龙虾数据库以及 OpenClaw 各代数据库、文本记录和工作区文件，核对旧编辑版本与子会话。仅存在于磁盘的已删除项目维持原删除状态。[旧会话发现](../../../src/main/libs/openclawSessionLegacyMigration.ts#L93) · [编辑历史](../../../src/main/libs/coworkMessageVersionStore.ts#L63) |
| 附件、项目、生成文件 | 龙虾托管的附件和生成文件核对实际内容，并验证能够打开。用户选的项目目录保留原位置，不整份复制或删除。原来就丢失或移走的外部文件标明原因，允许重新选择。[现有备份范围](../../../src/main/libs/dataMigration/dataMigrationService.ts#L1130) |
| 模型、套餐、自带密钥、技能和外部工具 | 保持原账号、模型选择、权限和启停设置。普通技能迁入并检查所需工具。需要重新授权的具体列名，重连前暂停。账号归属无法确认的数据只留在原本可见的本机范围，等待用户确认。 |
| 群机器人和定时任务 | 能准确还原目标账号、群、权限、时区、原启停和离线补跑规则的，在全部迁移提交后才启用。登记已处理的消息和触发时间，避免重复发。原先关闭的继续关闭；外部结果不明的标为“待核对”。例如“每周一 9 点发项目群”的任务，验收要看到原群实际只收到一份。[旧任务存储](../../../src/main/libs/openclawCronLegacyMigration.ts#L70) · [任务绑定](../../../src/scheduledTask/metaStore.ts#L3) |
| 不兼容的渠道、插件、特殊技能和后台整理功能 | 归档名称、版本、配置、关联对象、已有结果，以及适合留存的原文件。插件代码作为档案停用。用户可以查看旧设置、导出或按替代方案重建；可重新绑定的功能单列。完整备份仅限本机用户访问，敏感凭据按原保护方式保存，普通导出清单隐藏密钥。长期未完成的操作记录为中断，旧授权弹窗作废。 |

用户资料备份和旧程序清理分别处理。升级包可以马上移除旧引擎，升级前的数据快照继续保留，由用户在确认后单独清理。企业必用功能若只能归档，要在发布前明确告知并允许推迟安装。

## 团队怎么交付

| 工作 | 谁牵头 | 交付标准 |
|---|---|---|
| 做一个只带 DSH 的安装包 | 引擎、客户端和发布负责人 | 在从未安装 OpenClaw 的机器上，用原账号、套餐和主界面完成读表、生成 Excel、重启后继续修改。再验证拒绝授权、停止指定任务、账号切换和用量归属。每个对外支持的平台分别通过。 |
| 做首次启动迁移和恢复页 | 数据迁移负责人 | 在打开正式数据库、启动机器人和定时任务之前完成互斥检查。旧库和媒体取一致快照，在新位置转换，按对象记录来源与去向。校验数据并试启 DSH 后，一次切换到新数据。迁移期间可以离线，不调用付费模型、不执行旧工具或定时任务。[已有快照校验](../../../src/main/libs/dataMigration/dataMigrationService.ts#L896) |
| 定下兼容清单 | 产品、渠道和客服负责人 | 按活跃用户与客户承诺为每项旧能力定下“支持、需重连、备份停用”，给出名称和用户说明。新版本正式启用前完成已支持渠道和自动化的开发、核对和演练。 |
| 用同一个候选安装包模拟真实升级 | 测试负责人 | 覆盖近版、跨多个版本、大数据量、多个账号、直接从老备份恢复。备份、转换、切换前后分别断电，再次启动都能恢复。验证附件与不同编辑版本可读、授权不扩大、消息只发一份。验证磁盘空间不足时原数据还在。 |

**一次切换的关键是失败后仍能恢复。** 切换前失败就重试，旧原件和备份仍在。切换后优先修复新版；严重故障需要降级时，先另存新版生成的聊天与文件，再用旧版安装包配升级前快照恢复。已经发出的消息和外部项目的改动仍以实际结果为准。[现有整库恢复逻辑](../../../src/main/libs/dataMigration/dataMigrationService.ts#L1667)

发布前应在干净电脑上验证独立运行，在旧设备上验证一次升级和数据对账，再验证升级中断后重开不会丢数据或重复执行。团队可以分工开发、内部演练再发布；每位用户只需升级一次。
