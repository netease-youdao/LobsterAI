# Word 编辑第二阶段实现记录：接近原生的排版与 AI 实时编辑

日期：2026-09-27。在[第一阶段](./2026-09-13-word-editing-stage1.md)基础上，目标是让右侧 Word 编辑器在排版上尽量接近 Word，并让 Agent 直接修改正在显示的文档。本阶段没有生成安装包，也没有在 Windows、Linux 或真实 Microsoft Word 上做对比。

## 1. 编辑内核升级

`@docx-editor.dev/core`、`@docx-editor.dev/i18n` 从 2.17.0 升级到 2.22.0，传递依赖只变了 `bidi-js` 1.1.0 与 `harfbuzzjs` 1.6.1，许可证类型不变。2.22 带来中文两端对齐提前换行的修复、浮动对象避让、长文档输入提速，以及本阶段用到的按需字体解析接口（`defineFontResolver`）和自动化协议（`createBrowserAutomationHost`、`createServerAutomationHost`）。`resources/word-licenses` 已重新生成并通过 `npm run verify:word-licenses`。

## 2. 字体：接近 Word 的换行、行高与分页

第一阶段把所有字体换成三套内置字体：Arial 被映射到 Calibri 的替身 Carlito（同一段英文窄 7.4%、行高 1.22 对 1.15），宋体、楷体、仿宋都显示成思源黑体，并且完全不用系统已装字体。本阶段改为按 Word 在本机能找到字体的方式解析：

| 顺序 | 来源 | 行高 |
| --- | --- | --- |
| 1 | 本机已安装的同名字体，含中英文别名（宋体 = SimSun） | 按字体自身的 Windows 度量计算 |
| 2 | 字宽兼容替身：Arial→Liberation Sans、Times New Roman→Liberation Serif、Courier New→Liberation Mono、Calibri→Carlito、Cambria→Caladea | 替身与原字体度量一致 |
| 3 | 中文衬线：按宋、楷、仿宋分别找本机已装的同风格字体（如 Songti SC、汉仪楷体简、仿宋-简），否则用内置思源黑体 | 用原字体的已知度量 |
| 4 | 其余中文用内置思源黑体，西文按 serif/sans/mono 类别用 Liberation | 同上 |

**Word 行高规则。** 内核按 `hhea` 计算行高，Word 用 Windows 度量（`usWinAscent + usWinDescent` 加 GDI external leading），并对声明 CP932/936/949/950 代码页的字体再放大行高。放大系数取 1.3、上下平分（ONLYOFFICE DocumentServer#487 对 21 款中文字体的实测；也符合“小四宋体单倍行距 15.6 磅”）。LibreOffice 的 Word 兼容实现（tdf#129808）用的是 1.27，二者差约 2%，常量 `WORD_CJK_LINE_HEIGHT_FACTOR` 集中在 `src/shared/artifactPreview/wordFonts.ts`，应在 Windows 上用真实 Word 校准。

每个字体面都以私有字体名注册，文档里的字体名通过带 `lineMetrics` 的替换规则指向它；若用文档字体名直接注册，内核会跳过替换规则，Word 行高就不会生效。本机缺失的 Windows 中文字体使用内置的度量表（宋体系 1.0em、微软雅黑约 1.32em、等线据公开 PDF 描述约 1.04em，后两者需在 Windows 上复核）。

**伪粗体与伪斜体。** 宋体、楷体、仿宋在 Windows 中没有粗体字重，Word 会合成粗体。应用全局样式设置了 `font-synthesis: none`，本阶段只在 Word 页面区域重新打开 `weight style`；中文衬线替身也只加载常规字重，省掉约 22 MB 的 Songti SC Bold。

**系统字体目录。** 主进程 `src/main/libs/wordFonts/` 读取 sfnt 表头（字体名含中文本地化名、字重、斜体、度量、代码页），`.ttc` 按需拆出单个字面；扫描结果缓存在 `userData/word-fonts/catalog.json`。macOS 额外扫描 Office 和 WPS 应用包内的字体目录。本机 377 个字体文件首次扫描约 65–104 ms，读取 21 MB 字面约 50 ms。渲染进程只能按字体名查询和按目录中的 ID 读取，不能指定任意路径。系统字体只用于本机排版，不写入文档、不随包分发。

**界面。** 底栏显示“使用原字体排版”或“N 个字体已替代”，悬停列出替代关系；字体下拉框列出文档字体与常用 Word 字体（宋体、黑体、微软雅黑、等线、楷体、仿宋、Calibri 等），不再出现 Carlito 等替身名；选用新字体时内核会再次按需解析。

## 3. 只读打开审阅类文档

批注、修订（含格式修订）、编辑限制、嵌入对象、数字签名、宏和外部链接资源，不再退回旧的 docx-preview，而是用同一内核真实分页地只读显示，顶部说明原因并提供“用系统应用打开”。主进程按会话记录可写状态，只读会话的恢复副本和保存都会被拒绝；外部刷新后按新内容重新判定。加密、ZIP64、DTD 实体等仍然拒绝打开。

## 4. AI 实时编辑正在显示的文档

链路：OpenClaw 原生 MCP 服务 `lobster-word`（生成于 OpenClaw state 的 `generated/lobster-word-mcp`，用 Electron Node 运行）→ 主进程回环桥接 `/word/tool`（进程密钥鉴权）→ 主窗口顶层 frame → 渲染进程的编辑器会话。工具：

- `word_read`：打开或复用文档会话，返回 revision、段落 ID/样式/文字、表格单元格位置和用户当前选区；当前任务中已有该文件的产物时，右侧面板会切到该文档。
- `word_edit`：按段落 ID 执行 `replace_text`、`set_text`、`insert_paragraph`、`delete_paragraph`、`format_text`、`format_paragraph`、`insert_table`，自动保存。

内核同一批自动化操作是原子的，但不允许同一段落在一批里既改文字又改格式、同一锚点连续插入等。转换层把编辑按依赖和冲突排成多轮；多行文字先作为一段插入，下一轮用私有分隔符拆分。为保证“要么全改、要么不改”，先在当前文档导出的无界面副本上完整试跑，全部成功才作用到正在显示的编辑器。插在标题后且未指定样式的段落改用正文样式，与 Word 回车后的行为一致。

内核把每一轮记为一步撤销，且历史分组对自动化批次无效。会话记录每次 AI 调用的提交轮数，用户在其后第一次按撤销（工具栏或 Cmd/Ctrl+Z）时一次撤回整次 AI 修改，重做同理；用户之后又改过文档则回到逐步撤销。`expectedRevision` 不匹配（用户在 AI 读取后编辑过）时拒绝并要求重新读取；同一文档的 AI 调用串行执行。`SKILLs/docx` 说明了何时使用这两个工具，并要求新建文档时显式设置 `eastAsia` 字体，否则中文在 Word、WPS 与 LobsterAI 中会各自回退到不同字体。

## 5. 验证记录

- 单元测试：sfnt 解析与 `.ttc` 拆分、字体目录与缓存、Word 行高（用内核无界面排版实测宋体 12pt 行高 15.6pt、微软雅黑 1.716em、已安装 Arial 1.15em）、准入分类、只读会话拒写、AI 编辑转换（多轮、原子性、歧义、表格、样式告警）、MCP 脚本子进程收发、桥接鉴权与超时、配置同步注册。10 个文件 185 项通过。
- 完整 `npm test`：3 项失败（`openclaw-im-sdk-compat`、`openclawConfigDiagnostics`、`openclawGatewayLock`），在暂存全部改动后的干净代码上同样失败，与本阶段无关。
- `npm run build`、`npm run compile:electron`、改动文件 ESLint：通过。
- 端到端（macOS，Vite 开发服务器 + Electron + CDP，隔离数据目录）：
  1. 真实 `WordFileEditor` 打开中文报告：shaped 测量；Arial、Times New Roman 用本机字体，宋体→Songti SC、楷体→汉仪楷体简、微软雅黑/黑体→思源黑体、Calibri→Carlito；热打开约 1.4 s。
  2. 光标处输入、模拟中文输入法组合输入（无拼音残留）、自动保存落盘（python-docx 独立读取校验）、工具栏撤销/重做。
  3. 页面内调用 AI 工具：读取含选区；一次调用内替换、加粗标红、插入两段、两端对齐、插表格，编辑器实时显示并落盘；4 轮提交一次撤销撤回；过期 revision 和无效编辑均不改动文档；带批注文档只读且拒绝 AI 编辑。
  4. 配置指向本地脚本化模型的自定义模型后，OpenClaw 注册 `lobster-word__word_read/word_edit`；模型依次调用读取、编辑并回复，发起任务约 1.1 s 后修改出现在编辑器中并落盘。
  5. 带批注文档显示只读说明、隐藏工具栏和保存按钮；工具栏改用“仿宋”时按需解析到仿宋-简，文档中写入的是“仿宋”，没有内部字体名。

开发构建新增 `LOBSTERAI_DEV_USER_DATA_DIR`：仅在未打包时生效，用于端到端测试使用临时数据目录，避免触碰真实配置。

## 6. 试用反馈修复：回车与输入法下看不到光标和文字

试用反馈：文末多按几次回车后看不到光标，输入时也看不到，有时输入的内容像没输入一样。用 Agent 生成的带页眉页脚文档复现，定位到五个原因（`src/renderer/services/wordComposition.ts`、`wordEditorSession.ts`、`wordDocument.ts`）：

1. **空段落里的输入法组合文字不可见。** 内核把每行画成 `font-size: 0` 的容器，文字在其中的 run 里；中文输入法组合期间，Chrome 把拼音直接插进行容器，空段落没有 run，拼音字号为 0。内核组合期间又隐藏自绘光标，于是回车后打拼音时屏幕上既没有光标也没有字。组合期间给宿主加 class，并按选区字号和缩放给空行设字号（`wordEditor.css`）。
2. **新一页第一行的输入法组合被 Chrome 丢弃。** 每页的页眉页脚是不可编辑元素，DOM 顺序在该页正文之后、下一页正文之前。在下一页第一行开始组合时，Chrome 只保留第一个拼音字母，后续更新和上屏的汉字都丢失（稳定复现；无页眉页脚的文档正常）。光标位于某页第一行时，把上一页的页眉页脚设为 `visibility: hidden`，在可编辑层外放一份静态副本保持显示，页面重绘后重新覆盖。必须在组合开始前处理：组合过程中改样式会让 Chrome 把组合文字滚到视口顶端。
3. **保存后的无效刷新会重设编辑模式。** 文件监听在每次自动保存后都会通知刷新，刷新即使发现文件没变，也会在 `finally` 里重新 `setMode`，内核每次都重建编辑状态并发出选区变化。改为只在真正重新载入时切换，`setReadOnly` 对相同模式不再调用内核。自动保存遇到组合进行中则等组合结束再导出（最多 10 秒），与内核自身外部刷新流程的做法一致。测试中组合期间重设模式或保存都没有造成丢字，这两处属于减少干扰的防御性修改。
4. **光标贴着视口底边。** 内核只把光标滚到距底边 24px，文末连续回车时下方一片空白。输入后（按键或输入事件 1 秒内）的光标移动，会在光标下方保留视口高度的 20%（48–160px）。
5. **用中文输入法打英文，按回车上屏后字母丢失并多出一行。** 内核的按键处理不检查输入法组合状态：组合中用来上屏字母的回车被当成分段，组合随之被打断；编辑拼音时按退格会删除文档里的字。Chrome 把输入法消耗的按键报告为 `isComposing` 或 keyCode 229，这类按键在宿主捕获阶段停止向内核传播，只由输入法和组合事件处理。

验证（隔离数据目录，CDP 模拟按键与 `Input.imeSetComposition`）：新页第一行连续组合输入“中国人”在 3 个新页上均正确；回车与组合的 48 组随机时序压力测试从 2–3 次失败（均为第 2 条的新页首行）降为 0，另 72 组跨页测试 0 失败，python-docx 读取落盘内容无拼音残留；组合期间拼音在空段落可见、视图不跳动；普通与展开面板中光标下方均保留约 20% 视口；每次按键到光标移动约 16–17 ms。输入法组合中按回车上屏英文、按退格改拼音、按方向键选词都不再改动文档；普通按键输入、回车分段、退格、方向键和英文折行不受影响。第二阶段原有端到端场景（打字、撤销、AI 编辑、只读文档）复测通过。

## 7. 已知限制与后续

- 未与 Windows 上的 Microsoft Word 做像素或分页对比；CJK 系数 1.3、微软雅黑和等线度量需要在 Windows 上校准。
- 内核仍未实现文档网格的“对齐到网格”行高吸附（2.22 只把行跨度用作“段前/段后 N 行”的单位），中文 Word 默认模板生成的文档分页仍可能不同；应向上游反馈或打小补丁。
- 批注、修订、协作需要商业 Pro 模块，本阶段仍只读；公式只显示、图表和 SmartArt 占位、不支持竖排。
- 内核插入的表格单元格行高偏大；插表格固定单独占一轮。
- 第 6 节第 1、2、5 条是内核 DOM 结构、按键处理与 Chrome 输入法实现的相互作用，LobsterAI 侧的处理依赖内核的类名与页面结构（`.docx-line`、`.docx-page`、`.docx-hf`），升级内核时需复测；应向上游反馈：按键处理跳过输入法组合、页眉页脚移出可编辑层、空行给出可见字号。
- Windows、Linux 实机、原生输入法候选窗、完整安装包未验收；输入法问题只用 CDP 模拟组合事件验证过。
