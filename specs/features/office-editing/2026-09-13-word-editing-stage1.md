# Word 编辑第一阶段实现记录

日期：2026-09-13。范围：本地 DOCX 的人工编辑、保存与恢复。PPT、Excel 编辑及结构化 Agent 文档操作接口留在后续阶段。字体、Word 行高、只读准入和 Agent 实时编辑见[第二阶段记录](./2026-09-27-word-editing-stage2.md)。

## 使用方式

更新依赖后运行 `npm run electron:dev`，从任务产物右侧或“我的文件”中打开本地 `.docx`。符合当前编辑范围的文件直接进入编辑器，无需 Office、WPS、文档服务器或商业授权密钥。

支持正文输入、段落样式、字体与字号、加粗/斜体/下划线/删除线、段落对齐、列表以及撤销/重做。文档默认适配面板宽度，缩放由内核统一管理，保持显示与光标命中位置一致。可以编辑已有表格中的文字；本阶段没有新增图片、表格和复杂页面布局的工具栏。

停止输入约 700 ms 后自动保存，也可以使用保存按钮或 Cmd/Ctrl+S。切换文件、关闭预览面板不会销毁未保存的文档会话；重新打开仍能继续编辑和撤销。

磁盘文件由其他程序或 Agent 更新时：没有本地修改则自动刷新；存在本地修改则暂停覆盖，显示“保留我的编辑 / 使用文件版本”。这两项操作需要再次点击确认。重新启动后若发现恢复副本，同样先展示选择，不会仅因打开文件就覆盖磁盘版本。

## 实现和文件边界

| 责任 | 实现 |
| --- | --- |
| Word 编辑内核 | 固定 `@docx-editor.dev/core`、`@docx-editor.dev/i18n` 2.17.0，只使用已审查的开源入口 |
| 产品界面 | `src/renderer/components/artifacts/renderers/word/`，自有工具栏、保存状态、冲突选择及预览降级 |
| 文档会话 | `wordEditorSession.ts` 保存编辑器 DOM、撤销栈与路径别名；React 面板卸载时将 DOM 移到离屏容器 |
| 保存协调 | `wordDocument.ts` 管理 revision、异步导出、保存队列、外部刷新和恢复状态 |
| 本地文件通道 | `wordEditing.ts` IPC 与 `wordFileEditing.ts`，不把任意文件写入能力直接交给编辑器 |
| DOCX 准入 | `wordPackage.ts` 检查 ZIP 目录、实际解压大小、CRC、路径、XML 实体及本阶段不支持的内容 |
| 离线排版 | `wordFonts.ts`，本地 HarfBuzz WASM 与独立整理的 OFL 字体 |

只有应用主窗口的顶层 frame 可以调用新增的文件 IPC。打开文件后使用绑定窗口的随机句柄；窗口导航、销毁或渲染进程退出时释放句柄和监听。按真实文件路径串行化写入，保存前核对内容哈希，并在替换前再次检查版本和符号链接目标。同目录临时文件写入、同步后再 rename，避免直接截断正在使用的文件。

恢复副本保存在 Electron `userData/word-drafts`。最新编辑成功写入恢复副本之前，会被视为尚未安全保存并参与现有退出保护。正常保存后清理对应恢复副本。第一次改写某个编辑会话的文件时，在 `word-drafts/originals` 保留本次编辑前副本，界面提供定位入口；同一文件在后续新会话中的首存会更新这份副本，它不是完整版本历史。

目录监听可识别外部程序通过 rename 替换文件的保存方式；当前会话自己的保存通知不会重新加载编辑器或清空撤销栈。保存回执、外部读取和新输入并发时，通过 revision 和版本比较避免旧回执将新输入误标为已保存。一次读取或恢复写入错误也不能解除已经存在的冲突确认状态。

生产打包与开发依赖预编译共用 ES2022 目标，以支持内核的 WASM 模块初始化。Vite 的 `build.target` 不会自动覆盖 `optimizeDeps.esbuildOptions.target`，两处必须保持一致。只在应用主窗口的入口文档 CSP 中添加 `wasm-unsafe-eval`，没有开放 JavaScript `unsafe-eval`，其他页面不因此获得这项许可。

## 商业发行与开源材料

LobsterAI 自有集成代码保持现有 MIT 许可。新增第三方代码和字体分别保留各自许可，不把它们重标为 MIT。

- 引入的 Word 依赖图共 25 个包；包括 Apache-2.0、MIT 及需要同时保留声明的 MIT AND Zlib 材料。
- 没有引入 `@docx-editor.dev/pro`、`editor-api` 或整个混合许可字体包。
- 独立内置 Carlito、Caladea、Noto Sans SC 共 10 个字体文件，附三份 OFL 声明；字体文件合计约 19 MiB，未修改或做子集化。
- 固定直接依赖和内核的传递依赖版本；仓库原有 `package-lock.json` 忽略规则保持不变。
- `resources/word-licenses/NOTICE.txt` 与 `manifest.json` 记录实际依赖、许可材料、字体来源和哈希、WASM 哈希；补充了上游发布包遗漏的一份完整许可证。
- `npm run verify:word-licenses` 在构建前检查实际依赖与已审查材料是否一致。依赖更新后须审查再重新生成记录，不在普通构建中静默更新。
- macOS、Windows、Linux 的打包配置均包含 `licenses/word`。本次没有生成完整安装包，尚未把配置检查当作最终发行物检查。

此清单只覆盖新增 Word 功能，不代表已经审查了 LobsterAI 的全部历史依赖。

## 当前准入与兼容性范围

本地 `.docx` 才会进入编辑路径；旧 `.doc` 和没有本地文件的内容继续使用原有预览方式。最大压缩文件 25 MiB、总解压内容 100 MiB、单个部件 25 MiB、4096 个 ZIP 项目。超出限制或不能安全打开时提供预览、系统应用打开与重试入口。

本阶段明确拒绝进入编辑模式的内容包括实际批注及批注引用、修订、受保护文档、宏、数字签名、嵌入对象、altChunk、外部链接资源（普通超链接除外）、加密 ZIP 和 ZIP64。生成器附带的空 `word/comments.xml` 可以保留并编辑；会解析 XML 确认没有批注记录或其他内容，不再仅按文件名判断。普通文本、基础样式、图片、表格、页眉页脚及未修改的自定义 XML 做了样本往返验证，不能由此推导任意复杂 DOCX 都能无损往返。

字体不足时使用内置字体替代，分页与 Microsoft Word 可能不同，界面保留该提示。当前不承诺 Word 全功能、精准打印一致性、大文档性能、多人协作或任意两款外部编辑器之间的无冲突合并。对完全不配合文件锁的外部进程，校验与 rename 之间仍有很短的竞争窗口；恢复副本和编辑前副本降低损失风险，但不是操作系统级的条件替换事务。

### 开发启动白屏修复

此前生产 `file://` 验收和单独的组件开发配置未覆盖根配置的依赖预编译。用户运行 `npm run electron:dev` 后出现白屏；使用根配置复现了 HarfBuzz 的 `Top-level await is not available in the configured target environment` 错误。原因是只设置了生产 `build.target`，开发优化器仍使用 Vite 的旧目标。

修复后两处共用 `rendererTarget`。新增 `tests/wordDevelopmentBuild.test.ts`，通过根 Vite 配置、实际 Word 会话入口和空临时缓存执行依赖预编译，不启动 Electron，也不复用开发缓存。移除开发目标的对照检查能重现同一错误；修复后的此项检查与 Word 文件/会话测试共 29 项通过，相关文件 ESLint 通过。

完整 `npm run electron:dev` 启动已实际验证：应用首页与任务窗口正常显示，renderer 日志到达 `shell ready`。同一个 5175 开发服务也成功加载了完整 Word 编辑组件、正文、图片、表格、页眉页脚和工具栏；此组件加载检查使用内存文件桥，不代替上述生产环境的真实磁盘保存验收。当时已有任务中的示例文档显示预览降级，后续确认这是下面记录的空批注部件误判，不能算作该文档编辑验收通过。

### 2026-09-14：普通生成文档的空批注部件误判

用户实际生成的 11,271 字节 DOCX 带有空的 `word/comments.xml` 和空的批注关系文件，没有批注记录。此前准入代码只要发现 `word/comments*.xml` 就拒绝，导致普通生成文档无法编辑。

现在使用已有许可清单中的 `fast-xml-parser` 5.11.1 校验并解析该部件，只有结构合法、根为 comments 且内容为空才放行。此包列为主进程显式依赖，仍固定到已审查的版本。非空批注、空白批注记录、未知批注元数据及缺少批注部件的引用/范围标记继续使用预览。

新增空部件变体、实际批注及孤立引用的准入回归，以及打开—保存—重开的文件测试。修复前新增覆盖中 7 项失败，修复后 Word 与开发预编译共 40 项测试通过；ESLint、Electron 类型检查、25 个依赖包及字体/WASM 许可校验通过。

对用户文件的副本使用隔离原生窗口、真实 preload、Word IPC 和文件存储验证：标题、正文、列表、表格、页眉页脚成功加载；输入 `QA0914` 后自动写入磁盘。随后重新读取磁盘并打开编辑组件，文本仍存在。独立 ZIP 校验确认导出包可再次准入，表格行列及列表节点数量未变，批注空部件、页眉页脚、脚注尾注及编号部件保留。用户原文件的 SHA-256 保持不变。
