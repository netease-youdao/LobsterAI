# 模型上下文长度选择设计文档

## 1. 概述

### 1.1 问题与背景

较长的上下文窗口可以保留更多对话信息，也可能增加积分消耗。客户端需要让有明确需求的用户主动选择更长的窗口，同时让未作选择的用户持续跟随模型当前默认值。

默认窗口是随模型配置变化的有效值，用户偏好则是一次主动选择。两者即使暂时数值相同，也必须分别表达，避免打开菜单、切换模型或恢复历史会话时意外固定窗口。

### 1.2 目标

- 为支持该能力的套餐模型及模式提供离散档位滑动选择，最大支持 1M。
- 仅保存用户明确确认的选择；恢复默认后重新跟随模型当前默认值。
- 让上下文长度与思考强度独立设置，并复用模型详情的二级菜单交互。
- 保持会话执行、上下文用量展示和分叉时使用的窗口一致。

## 2. 用户场景

### 场景 1：始终跟随默认

- **Given** 用户从未设置上下文长度，当前默认窗口为 400K。
- **When** 用户查看菜单、重新启动客户端，或模型默认窗口随后更新。
- **Then** 客户端不生成固定偏好，会话继续使用该模型当前默认值。

### 场景 2：主动选择并恢复

- **Given** 当前模型支持 400K、600K、800K、1M 四个档位。
- **When** 用户将滑块调整到 800K 并确认。
- **Then** 当前会话使用 800K，同一账号后续手动新建该模型的会话可恢复这一选择；已有的其他会话不被批量修改。点击恢复默认后清除该偏好。

### 场景 3：独立调整思考强度

- **Given** 同一模型同时支持思考强度和上下文长度设置。
- **When** 用户调整其中一项。
- **Then** 另一项保持不变，当前模型不会被当作一次重新切换而重置会话窗口。

## 3. 功能需求

### FR-1：区分默认与主动选择

未设置和恢复默认均使用空偏好表达。用户明确选择 400K 时保存固定的 400K，不能因为它恰好等于当前默认值而改为跟随默认。历史会话迁移时不从旧的窗口数值推断用户意图。

### FR-2：离散滑动与二级菜单

模型详情中的“上下文长度”行仅展示当前值或“默认 · 当前值”。悬浮、点击或键盘聚焦该行后展开滑动面板，滑块吸附到当前模型允许的档位。四档示例显示 400K、600K、800K、1M 全部刻度，具体档位由模型能力决定。

拖动中只更新预览，松开指针或完成键盘选择后才提交。取消、失焦、查看菜单及聚焦控件均不保存偏好。保存期间禁用重复操作，失败后保留原选择并展示错误提示。

### FR-3：清晰展示与独立设置

思考强度和上下文长度使用独立设置行，二级面板互斥展开。复用浅色、深色主题变量，并根据窗口边界调整弹层位置。文案支持中英文，说明较长窗口可能消耗更多积分，以及已压缩的历史不会因增大窗口而恢复。

## 4. 实现方案

### 4.1 渲染层状态

`ModelSelector` 负责模型详情和二级面板的展开、定位及互斥；`ModelContextWindowControl` 负责已保存值、临时滑动值和保存状态；`contextWindowSlider` 负责档位构建、索引和数值展示。

控件分别读取当前默认值与已保存偏好，不把界面展示的有效值反写为偏好。模型、账号、会话或可选档位变化时重新读取状态，并丢弃旧请求的迟到结果。没有有效档位时隐藏入口，保留原有模型选择行为。

### 4.2 主进程与本地持久化

渲染进程通过 preload 桥提交选择，主进程重新确认当前账号、目标模型、可选档位和会话状态。已有会话先等待运行时更新成功，再写入本地会话与偏好；运行中的会话拒绝修改。异步操作期间账号或会话模型发生变化时，不保存过期结果。

偏好按环境、账号归属和模型或模式分别保存。会话使用独立的可空覆盖值及归属标记，恢复历史会话时读取其自身状态。新建手动会话只恢复仍然有效的明确偏好，历史默认会话不会因另一会话的新选择而改为固定值。

恢复默认时删除对应偏好，并清空当前会话的覆盖值。IM、定时执行和自动创建的非分叉子任务不读取手动聊天偏好。

### 4.3 运行时窗口同步

客户端配置同步将模型默认值与允许的用户选择分别交给 OpenClaw。运行时适配层只为当前会话更新选择，不通过改写共享模型默认值实现，也不因单次窗口调整重启网关。

版本补丁让执行预算、上下文预检查、记忆整理、用量展示和分叉预算采用一致的窗口解析逻辑。选择必须仍在当前模型允许的档位内；能力变化后失效的选择回落到当前默认值，不把回落结果保存成新的主动偏好。其他模型提供商继续使用原有逻辑。

显式分叉可继承父会话的窗口选择及相应历史预算，自动创建的非分叉子任务保持各自默认行为。发布客户端时需要同时构建包含该补丁的运行时。

## 5. 边界情况

| 场景 | 处理方式 |
| --- | --- |
| 模型没有有效可选档位 | 隐藏选择入口，继续使用默认窗口 |
| 默认值不在固定档位中 | 展示跟随默认的位置，不新增可保存的固定档位 |
| 主动选择的值等于当前默认值 | 保留明确选择；只有恢复默认操作才清除偏好 |
| 可选档位被撤回或账号归属变化 | 不沿用失效或其他账号的选择，回到当前默认逻辑 |
| 会话运行中、更新失败或异步请求过期 | 不覆盖原有本地会话和偏好 |
| 只调整思考强度或重新选择同一模型 | 保留会话已有的上下文选择 |
| 增大窗口前已经发生历史压缩 | 使用新预算继续执行，不恢复已丢弃的原始历史 |
| 客户端未获得可选窗口能力 | 保留原有默认行为，不要求用户主动配置 |

## 7. 验收标准

- 未操作、查看菜单、刷新模型能力和重启均不会生成固定偏好；默认值变化后仍跟随当前默认。
- 指针和键盘可以选择多个离散档位，拖动预览和取消不会提前保存。
- 主动选择可跨重启恢复；恢复默认会清除偏好，已有其他会话保持各自状态。
- 同一模型的思考强度和上下文长度互不重置，浅色、深色和窄窗口下控件可用。
- 运行时实际窗口与当前会话选择一致；缺失能力、失效选择及更新失败不会扩大窗口或写入错误偏好。
