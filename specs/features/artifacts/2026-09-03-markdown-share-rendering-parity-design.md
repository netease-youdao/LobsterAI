## 1. 概述

### 1.1 问题与根因

示例分享：[AI-Agent 扩展机制文档](https://lobsterai-server.inner.youdao.com/s/shr_8997a99103904147)。

原文 `tool_calls` 和 `tool` 使用单反引号，客户端显示为行内代码，分享页却显示成带工具栏的代码块。只读排查确认文件为 21,414 个 UTF-8 字节、12,149 个 JavaScript UTF-16 码元，32 字符样例也能复现。

分享页仍依赖 code 组件的 `inline` 属性，react-markdown 自 v9 起已移除该属性；当前构建使用 10.1.0。客户端按节点起止行做兼容判断，截图场景正确，但跨行行内代码等边界仍应改用结构识别。[官方迁移说明](https://github.com/remarkjs/react-markdown/blob/main/changelog.md#remove-extra-props-passed-to-certain-components)

最近服务端将默认完整渲染阈值从 8K 提高到 64K，暴露了这个既有问题；阈值不是代码块误判的根因。除代码节点外，两端还存在标题字号、正文间距、代码高亮、公式预处理、化学公式和图片处理差异。

### 1.2 目标

对齐对象是 [MarkdownRenderer](../../../src/renderer/components/artifacts/renderers/MarkdownRenderer.tsx) 的**文件预览**。它当前传入 `enableLargePreview={false}`，因此不能把通用聊天组件的 8K 折叠作为文件分享基线。

同一 Markdown、同一图片快照，在相同正文宽度、字体、主题和缩放比例下，语义结构、正文排版、公式、代码展示和可发布图片一致。文件在服务端预览准入范围内默认全文渲染。

默认视觉基线为 classic-light、UI 字号 15、代码字号 14、normal 间距。分享页不存储发布者的个性化主题或字体偏好；窗口、侧栏和分享 Header 不参与正文像素比较。

## 2. 用户场景

| 场景 | Given / When | Then |
| --- | --- | --- |
| 句中代码 | 列表内有行内代码，创建分享后访问 | 行内 code 不拆断句子，无块级工具栏 |
| 大文档 | 超过 64K 字符且通过服务端准入 | 默认展示完整 Markdown |
| 公式和表格 | 同一份含公式、化学式、任务列表的文件 | 两端语义、布局和插件行为一致 |
| 图片 | 目录内本地图或可公开获取的远程图 | 发布时形成资源快照，公开页同源加载 |
| 无法发布资源 | 图片越界、需鉴权、失败或超限 | 发布者得到 warning，公开页有缺图占位 |
| 旧分享 | 老包已有完整原文和图片 | 新服务端改善渲染；历史缺图或原图损失需重新发布 |
| 后台预览 | 管理员通过现有 token 打开分享 | 使用同一正文渲染入口 |

## 4. 实现方案

### 4.1 共享模块

新增 `packages/markdown-renderer/`，拟名 `@lobsterai/markdown-renderer`。模块只包含文档展示能力：

| 入口/文件 | 职责 |
| --- | --- |
| src/MarkdownDocumentView.tsx | 文件模式入口，不包含整篇折叠 |
| src/markdown.ts | 代码保护、URL/公式预处理和只读解析工具 |
| src/components.tsx | 共同的标题、列表、表格、图片位置和行内代码结构 |
| src/CodeBlockView.tsx | CodeMirror、高亮、diff 和代码交互 |
| src/styles/ | 正文局部 CSS、默认主题与字号、代码样式 |
| src/host.ts | 图片解析、链接、复制/保存的宿主类型 |
| fixtures/ | 语义、图片、性能和视觉对照材料 |
| package.json、package-lock.json、构建/测试配置 | 独立安装、构建、验证和打包入口 |

核心不导入 Electron、Redux、客户端服务单例或埋点。纯解析入口不依赖 document，供 Node 测试及主进程打包器使用；显示入口可以依赖浏览器和 CodeMirror。

文件 `MarkdownRenderer` 接入共享入口，保留文件目录上下文和外层选中文本操作。`MarkdownContent` 继续承载会话折叠，将可共享的显示规则委托给模块，不能将所有聊天消息改为文件全文模式。`CodeBlock` 保留客户端包装器，共用展示组件；操作事件通过可选回调交给原埋点。

### 4.2 宿主适配

共享组件输入 `content`、`host` 和 `labels`。host 提供：

- `resolveImage(source, alt)`：返回已解析 src 或不可用原因。
- `renderLink`：渲染已解析的链接信息，不重新解析整篇正文。
- `copyText(text)`、`saveCode(text, language)`：操作成功或明确失败。
- 主题和字号通过局部 CSS 变量注入，不依赖客户端全局 reset。

客户端沿用文件目录解析、外链打开、文件菜单和剪贴板能力；保存代码可沿用现有 Blob 下载实现。分享页采用同源资源、浏览器链接/Clipboard API/下载。全屏代码弹层是浏览器组件，不要求 Electron。

labels 由客户端 i18n 注入，覆盖复制、下载、换行、折叠、全屏、搜索及错误提示；分享页使用对应中文文案。两端交互方式可由宿主实现，不能改变正文语义。

### 4.3 解析与代码结构

1. 在允许的正文区间执行 file URL 空格兼容、LaTeX 分隔符转换、块公式规范化；保护反引号/波浪线围栏、多反引号跨度和嵌套代码。
2. 统一 react-markdown、remark-gfm、remark-math、rehype-katex 和 mhchem。
3. pre 读取内部 code 文本及语言并输出 CodeBlockView；普通 code 只输出行内元素。
4. 不把 node 等解析器元信息透传 DOM，不按换行数量推断代码类型。
5. 复制保留缩进和空格，仅沿用去除解析器补充的一个尾换行规则，不能 trim 全文。

代码初始展开；文本类代码默认换行；保留当前客户端 100,000 字符及 1,000 行的高亮上限。超过上限只降级该块高亮，正文和原始代码仍完整。未知语言、异步语言包失败显示普通代码；CodeMirror 只读。

不执行 raw HTML，不新增 MDX、多文档站点或 Markdown 内 Mermaid 图形渲染。不复制客户端历史边界错误，跨行行内代码等以正确 Markdown 语义验收。

### 4.4 样式与全文策略

共享正文默认值：15px / 24px、字重 445；代码 14px / 22px、字重 400；H1/H2/H3/H4 为 21/19/17/16px。列表、引用、表格和段落采用客户端 normal 间距；图片保持比例、默认最大高度 384px。

CSS 限定在正文容器，包含字体回退、代码主题和弹层变量，避免导入整份 Tailwind 或让旧分享 CSS 覆盖新正文。

服务端 max-file-bytes 和 max-render-bytes 默认均为 2,097,152 字节：前者管上传，后者管预览。准入内文件不使用旧 64K 纯文本卡片；超过准入沿用服务端下载页。默认新上传超过 2 MiB 会被拒绝，不能承诺所有超限新文件都可以先上传再下载。

### 4.5 图片快照与精确重写

扩展 `artifactFileSharePackager.ts`，保留入口 MD + `_lobster_assets/` + version=1 manifest 结构：

1. 使用与渲染一致的 AST 识别 image、imageReference、definition，排除代码示例与未使用定义。
2. 预处理若改变文本长度，保留到原文的区间映射；用同版本 tokenizer 定位 URL 源区间，按位置倒序修改。不能拿 mdast 整个节点 position 当 URL 范围，不能全局替换或重新序列化全文。
3. 普通链接和图片共用定义时，为图片分配独立定义或等价直接图片引用，保持普通链接目标不变。
4. 覆盖中文、空格、括号、编码、title、完整/折叠/快捷引用式图片。定位失败给出 warning，不猜测替换。
5. 本地图仍按 MD 所在目录和 realpath 边界校验；允许目录内绝对路径，禁止扩大到目录外或公开本机路径。
6. 公开 HTTP(S) 图片在发布时下载；支持的 data URL 解码、校验后打包；鉴权资源、blob 和不支持的类型给出遗漏原因。
7. 新路径使用 `_lobster_assets/<sha256>.<ext>` 的 ASCII 内容 hash，同字节去重；manifest/log 去除绝对路径、URL 用户信息和敏感查询值。
8. 最终入口重写后重新检查大小，再计算现有 sourceSha256 和 zip。源码、图片、路径均以最终上传包为准。

远程下载复用已有能力并补齐限额：不携带 Cookie/Authorization，每跳检查 HTTP(S) 和目的地址，最多 3 次重定向、15 秒单项超时、建议并发 3；地址检查约束实际连接，排除回环/私网/保留地址。流式限制单图大小，不仅信 Content-Length；再做 MIME、魔数、SVG 校验。

同时满足服务端限制：入口 2 MiB、单图 10 MiB、资源总量 50 MiB、100 张、zip 默认 20 MiB。客户端当前 22 MiB 临时 archive 限额不等于服务端承诺。无路径的 inline artifact 不猜基准目录，仍可收集明确远程/data 图片。

与服务端配套：新建/更新的 Markdown 图片通过校验后保留原始字节及包内路径，停止该分支的图片重编码和全局字符串替换。普通图片分享继续原有优化；历史图片不能靠渲染升级恢复原图。

### 4.6 API、hash 与权限

继续通过 `POST /api/html-shares`、`PUT /api/html-shares/{shareId}` 发送 multipart：sourceType=markdown_file、title、entryFile、sourceSha256、archive，以及现有可选字段。客户端继续 JWT Bearer 和稳定来源标识，响应封装不变。

sourceSha256 保持“最终入口字节 + 按包内路径排序的路径/资源摘要”规则，不加入渲染包版本。新资源名为 ASCII，避免 localeCompare 和 Java 排序在非 ASCII 路径上的分歧。

访问仍通过 `/s/{shareId}/` 和其 content 路径。公开、分享码、管理员预览、审核、状态、额度、失效与缓存保持现有校验。缺失资源不能通过浏览器读取访问者本机补齐，也不能绕过审核去直连外链图片。

MySQL 5.7 无表、字段、索引、SQL 或连接配置变更。测试环境凭据不写入文档、配置或样例。

### 4.7 构建交付

采用客户端要求的 Node.js 24。当前安装快照为 React/ReactDOM 18.3.1、react-markdown 10.1.0、remark-gfm 4.0.1、remark-math 6.0.0、rehype-katex 7.0.1、KaTeX 0.16.33；实施时先核对提交锁文件再固定。

共享包输出 ESM、类型、局部 CSS 和 fixture 清单。React/ReactDOM 为 peer 依赖；两端锁定解析器、高亮依赖及 KaTeX JS/CSS/字体版本，避免重复 React 或 KaTeX 副本。

首版 npm pack 生成不可变 tgz，客户端实际消费该版本，服务端在 `src/main/share-preview/vendor/` 通过固定 file 依赖消费同一产物。包源码更新需递增版本、重建并同步两端锁文件，记录来源 commit 与校验值；不从兄弟仓库借用 node_modules，不依赖私有包仓库才能交付。

服务端前端独立 package/lock/build 生成 MD 入口、CSS、字体、语言 chunk 和精确资源清单，Java 控制器按清单开放资源。入口与全部传递资源成组部署，运行时不需要 Node。独立 Mermaid 保持原入口，不把其业务迁移到共享 MD 模块。

包新增自己的 Vitest 配置，并接入客户端默认验证命令。当前根配置只包含 src/tests 路径，packages 内测试不会自动被发现；不能以根测试通过代表共享包已验收。

## 5. 边界情况

| 场景 | 处理方式 |
| --- | --- |
| 跨行行内代码、无语言/缩进代码 | 按 pre/code 结构判定 |
| 公式标记出现在代码中 | 保留原始代码文本 |
| 字体、语言 chunk 尚未就绪 | 保持正文可读，资源就绪后再做视觉对照 |
| 复制失败、图片下载失败 | 明确局部状态，其余内容可用 |
| 图片引用同时用于普通链接 | 独立图片重写，普通链接不变 |
| 文件路径不存在或越界 | warning + 占位，不扩大读取范围 |
| 图片地址内容后来变化 | 分享显示发布时快照，不保证与客户端旧缓存相同 |
| 历史缺图或有损图片 | 重新发布原始文件，不批量重写旧分享 |
| 文档接近 2 MiB | 全文和性能单独验收，不按字符切片破坏结构 |
| 原始 HTML、本地附件链接 | 保持现有能力边界，不新增执行或打包 |
| 个性化主题、窗口宽度不同 | 按默认基线和相同正文宽度比较 |
| 独立 Mermaid、会话消息 | 按原产品模式验证，无非预期迁移 |

## 7. 验收与发布

### 7.1 验收矩阵

用例编号与跨系统方案一致：

- MD-01～03：真实文档、最小样例、跨行/多反引号行内代码、各类围栏/缩进/空代码。
- MD-04～07：标题、列表、引用、表格、任务列表、公式/化学式、代码高亮/diff/降级。
- MD-08：8K/64K 字符边界、256K 和接近 2 MiB 文档；区分字节准入和字符长度。
- AS-01～02：中文/空格/括号/编码路径、三类引用式图片、图片与链接共用定义。
- AS-03～04：远程重定向/失败/超限、data、鉴权、目录越界、危险 SVG。
- AS-05～06：图片字节保留、去重、hash 稳定、旧包/旧路径/历史缺图。
- RT-01～02：复制/保存、换行/折叠、全屏/搜索、语言包失败，独立 Mermaid 与其他分享类型回归。

一个 fixture 目录供两端包装器使用，先断言正确语义、文本、资源请求和 computed style，再比较截图，不能仅比较两端是否“同样错误”。正文宽度固定 960px，补充 375px/768px；浏览器、字体、DPR=1、zoom=100%、主题和语言高亮状态一致，图片字体完成加载后截图。

### 7.2 性能与环境

拟定目标而非测试结果：真实文档桌面连续 5 次中位数 ≤ 1 秒；64K 常规混合文档桌面 ≤ 1 秒，移动端 4 倍 CPU 降速 ≤ 3 秒。计时从正文和入口模块可用到完成挂载，下载时间单列。256K/密集公式/近 2 MiB 记录耗时、长任务、DOM 和内存，近上限必须完整可见且不崩溃。

未通过时定位解析/高亮/挂载开销，不恢复隐含 64K 降级；如需 Worker 或分批挂载，另补设计，不按字符切分。首版不引入 Worker 或放宽现有 CSP。

前端验证使用本地 fixture/桩，不依赖 Redis、MySQL、NOS 或审核服务。本轮不执行服务端测试；后续真实分享码、管理员 cookie、状态和审核需要环境验证，不可用时记录未验证，不能用前端桩代替结论。

### 7.3 完成标准

- [ ] 两端消费同版本共享包及对齐依赖，根验证入口包含包测试。
- [ ] 行内/块级代码语义、排版、公式和代码交互对照通过。
- [ ] 文件全文、性能与准入边界通过，会话模式无非预期变化。
- [ ] 图片快照、精确重写、原图保留、缺失警告和 hash 通过。
- [ ] 公共、分享码、管理员预览和独立 Mermaid 有验收记录。
- [ ] 入口、CSS、字体、chunk、清单能成组发布及回滚。
- [ ] 集成说明记录实际版本、旧分享处理和未验证项，数据库无需迁移。

### 7.4 发布顺序与回滚

先交付共享包和完整产物，先发布服务端渲染/清单/原图保留能力并验证旧分享，再发布客户端文件入口与图片快照。旧客户端完整包直接受益；新包结构兼容旧协议，但落到旧服务端时不能承诺渲染和图片保真一致。

服务端保留当前及上一版不可变静态资源，避免旧页面异步 chunk 404。渲染接入与 Markdown 原图保留分开提交；优先回滚渲染入口和整组资源，保留原图逻辑。客户端回退不会使已发布同源图片失效，不修改历史分享状态或 sourceSha256。

回退旧渲染/64K 策略属于功能回退，应注明未满足本 spec。旧分享缺失和重编码后的原图无法通过回滚恢复，需重新发布。
