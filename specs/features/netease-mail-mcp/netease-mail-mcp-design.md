# 网易邮箱 MCP 接入设计

## 功能目标与范围

用户在连接器中授权网易邮箱后，可以在 LobsterAI 对话中查询、搜索和阅读邮件，并继续要求助手提取信息或生成摘要。邮件结果以卡片展示，便于核对原始内容和助手结论。

连接与重新授权、凭据保存和刷新、文件夹与邮件查询、正文卡片、断开连接已接入。真实服务验收覆盖读信、草稿保存与更新、附件读写、确认后发信及自发自收、发送/回复/转发的预检与取消，以及运行中刷新到期凭据。读写扩展默认申请 `profile:read mail:read mail:compose mail:send`，删除权限 `mail:delete` 默认关闭，需用户单独勾选后重新授权。旧账号保留原有只读权限，不能因客户端升级自动获得发信能力。回复、转发和删除的最终执行仍需单独验收，不能把确认卡片可操作等同于操作已完成。

本功能由用户主动发起查信，不做新邮件订阅、后台轮询或来信自动触发任务。它与既有 IMAP/SMTP 邮箱渠道独立，不要求用户填写邮件服务器或授权码。

## 用户流程

1. 进入「套件·技能·连接器」的连接器市场，选择「网易邮箱」并点击「连接邮箱」。
2. 系统浏览器打开邮箱登录与授权页，用户核对账号和本次权限后允许授权。
3. 浏览器回跳本机回调地址，客户端保存凭据、注册连接器并同步运行时配置，等待网关完成凭据热更新后显示已连接状态。
4. 用户在对话中提出查信、搜索、阅读或摘要需求。助手按需调用邮件工具，客户端呈现真实返回的列表和正文。
5. 用户可在已安装连接器中重新授权或断开连接。断开会删除本地凭据并停用服务；它不代表已撤销邮箱服务端的授权记录。
6. 获得草稿权限后，助手可以保存或更新草稿。发送、回复、转发和移入已删除会先展示操作卡片，用户检查内容后点击相应按钮，客户端才执行这一次操作。

首次授权和重新授权均通过热更新生效，无需重启网关。同步失败时显示错误，不能仅凭本地已有令牌就报告连接成功。

## 授权与凭据生命周期

Electron 主进程负责预注册客户端的 OAuth 授权码流程，使用 PKCE S256、随机 `state` 和固定 loopback 回调 `http://localhost:8989/oauth/callback`。回调只监听本机 IPv4/IPv6，校验路径、Host、state 和一次性消费，处理取消、拒绝、超时、端口占用以及退出清理。

凭据由独立 Node 子进程通过 OpenClaw 公共 `provider-auth` API 保存到原生凭据库。Renderer 只能获取连接状态、权限和有效期；令牌不经 UI IPC 返回，也不写入 MCP 配置或日志。该方案复用运行时存储，不宣称已经接入系统钥匙串。SDK 不保留自定义 scope 字段，因此非秘密的授权权限和授权批次标识另存于 LobsterAI 管理的状态文件，重新授权和断开会使旧批次失效。

已配置邮箱接入时，客户端在网关启动前使用同一 SDK 初始化共享凭据库，保留已有凭据和 SDK 管理的旧库归属。这样首次授权不会在网关运行中改变凭据库位置。授权后先同步 MCP 配置，再调用网关 `secrets.reload` 刷新凭据快照；重新授权即使未改变 MCP 配置也执行刷新。断开会删除凭据、停用 MCP 服务并刷新运行时，删除连接器也会刷新凭据状态。

MCP 配置通过 `oauth.authProfileId` 引用 `netease-mail:default`。本地 provider 扩展提供 `refreshOAuth`，由 OpenClaw 统一协调刷新、加锁和持久化，兼容 refresh token 轮换及响应省略新 refresh token 的情况。Electron 不启动另一套刷新定时器。刷新不能扩大权限；若服务端收窄权限，要求重新授权，避免保留过大的本地权限声明。

客户端注册信息由环境提供：`LOBSTER_NETEASE_MAIL_CLIENT_ID` 为必需项；缺失时连接入口显示未开放。开发环境可通过 `LOBSTER_NETEASE_MAIL_MCP_URL` 指定 HTTPS 服务地址，打包应用忽略该覆盖并使用产品服务地址。测试账号、测试 client ID、hosts 映射、诊断脚本与验收记录仅在本地维护，不作为产品默认值或随仓库发布。

## 运行时接入

读取和草稿复用 OpenClaw 原生 Streamable HTTP MCP 通道。受保护的写操作由本地邮箱扩展提供工具，使用同一原生凭据库和刷新机制连接服务，等待桌面确认后执行；不修改运行时核心。

| 层次 | 责任 |
| --- | --- |
| 连接器面板与 renderer service | 发起授权、展示连接状态、重新授权与断开 |
| 主进程连接管理与 IPC | OAuth 生命周期、凭据保存、连接器注册及同步 |
| OpenClaw 邮箱扩展 | 刷新凭据；冻结写入参数，等待可信界面确认并执行 |
| MCP 配置 | 引用授权 profile，按实际权限开放读取、账号资料和草稿工具 |
| 工具结果适配与卡片 | 将真实邮件字段转为稳定展示模型，保留原始工具结果 |

工具发现返回更多名称不代表当前授权允许调用。原生 MCP 通道始终排除发送、回复、转发和删除；这些操作只能通过邮箱扩展提供的确认工具执行。确认工具仅对 LobsterAI 桌面对话开放，IM、定时任务和子任务不具有桌面确认入口。没有 `profile:read` 时，不推断邮箱身份。

## 邮件展示

列表卡片展示主题、发件人、时间及可用的分页提示；正文卡片展示发件人、收件人、抄送、主题、日期、正文和附件信息。真实字段适配覆盖嵌套 `header`、`received_date` / `sent_date` 毫秒时间、`flags.read` 及附件 `part_id`。草稿回执的 `draft_id` 与实际提交内容组成保存卡片；更新草稿可能返回新的编号，后续操作应使用新编号。

正文按 PLAIN、HTML、MARKDOWN 区分处理。HTML 经宿主净化后展示，不执行脚本或自动加载远程内容。纯文本为空时提示用户可以继续读取 HTML，不能直接认定原邮件没有正文；列表缺少摘要时也不展示「无正文」。空 `flags` 保持已读状态未知，截断的搜索结果提示缩小范围，不伪装成可翻页结果。

卡片用于展示邮件内容。邮件内的文本、链接和附件均为不可信数据，不构成用户指令或执行授权。只读查询应显式使用 `mark_read=false`，避免读取时改变邮件状态。

## 错误与使用边界

- 授权失效时提示重新连接；权限不足不通过刷新隐式扩权。
- 达到服务调用额度时直接提示用户，不自动排队、重试、缓存邮件结果或改存草稿以规避限制。
- 附件随草稿写入及原始内容下载已通过小文件样本验证；按服务约定限制单附件 1 MiB、最多 3 个、总计 3 MiB。元数据大小与下载实际大小的差异、边界尺寸和其他文件类型仍需确认。
- 单个已连接邮箱使用稳定的服务与凭据标识；多账号、按 IM 发送者隔离和远端撤销授权需要单独设计。

## 写操作确认与结果

发送、回复、转发和删除需要独立于模型的用户确认流程：冻结操作内容，在客户端展示收件人、主题、正文和附件，由用户明确点击后执行。聊天中的“确认”、模型参数或持有确认 token 本身都不能代替可信批准。

服务预检返回 `42801` 后，扩展在网关内存中保存冻结参数和确认令牌，仅向界面发送摘要、过期时间和操作编号。账号身份来自 `get_profile.primary_account`，发送内容来自冻结参数；兼容服务端 `error.details` 中的预检结果。Renderer 经主窗口 IPC 和网关审批 RPC 提交编号；不接受界面传入的邮件内容或确认令牌。网关接口与 Agent 工具共享同一授权实例的待确认状态。一次确认只能消费一次；取消、过期、中止、断开或重新授权会阻止旧操作执行。

转发确认展示补充正文、原邮件内容与原附件名称，并标明引用原文或作为附件转发。原文按纯文本、HTML 依次读取，使用扁平展示字段避免运行时截断深层结构。最终结果优先于流式预检信息，完成后的历史卡片不会恢复为待确认状态。

界面区分等待确认、已确认等待结果、已提交至邮箱、取消和结果未知。发信成功回执中的 `saved_sent_mid` 表示已发送副本编号，与 `request_id`、`operation_id` 一并保留；客户端将其识别为已提交至邮箱，不将副本编号伪装成完整 `message_id`，也不据此声称收件人已经收到。服务端 `40904 / operation_outcome_unknown`、网络异常或无法识别的执行结果均不自动重试，也不换新请求编号重发；保留原请求与操作编号以供对账。邮箱中暂未查到邮件不能证明没有发送。服务端操作状态查询接口仍需确认，以支持可靠的自动对账。
