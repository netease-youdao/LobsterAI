# 网易邮箱 MCP 接入设计

## 功能目标与范围

用户在连接器中授权网易邮箱后，可以在 LobsterAI 对话中查询、搜索和阅读邮件，并继续要求助手提取信息或生成摘要。邮件结果以卡片展示，便于核对原始内容和助手结论。

连接器支持邮件查询、草稿、已读和红旗状态、附件收发，以及确认后发送、回复、转发和移入已删除。默认申请 `profile:read mail:read mail:compose mail:send`。用户可在首次授权或重新授权时勾选 `mail:delete`。旧账号升级后保留原有权限。

本功能由用户主动发起查信，不做新邮件订阅、后台轮询或来信自动触发任务。它与既有 IMAP/SMTP 邮箱渠道独立，不要求用户填写邮件服务器或授权码。

## 用户流程

1. 进入「套件·技能·连接器」的连接器市场，选择「网易邮箱」并点击「连接邮箱」。
2. 系统浏览器打开邮箱登录与授权页，用户核对账号和本次权限后允许授权。
3. 浏览器回跳本机回调地址，客户端保存凭据、注册连接器并同步运行时配置，等待 DSH 报告邮箱 MCP 已连接后显示已连接状态。
4. 用户在对话中提出查信、搜索、阅读或摘要需求。助手按需调用邮件工具，客户端呈现真实返回的列表和正文。
5. 用户可在已安装连接器中重新授权或断开连接。断开会删除本地凭据并停用服务；它不代表已撤销邮箱服务端的授权记录。
6. 获得 `mail:compose` 权限后，助手可以保存或更新草稿、标记已读/未读，以及设置/取消红旗。发送、回复、转发和移入已删除会先展示操作卡片，用户检查内容后点击相应按钮，客户端才执行这一次操作。

首次授权和重新授权均通过热更新生效，无需重启 DSH。同步失败时显示错误，不能仅凭本地已有令牌就报告连接成功。

## 授权与凭据生命周期

Windows、macOS 和开发构建共用分支内的默认注册配置：`client_id=fa384257dd9b8c3612`，MCP 地址为 `https://egw-test.mail.163.com/openapi-gateway/mail/mcp`。安装后不需要设置邮箱环境变量；测试环境的 hosts 由使用者配置，邮箱账号仍需自行登录并完成授权。正式注册就绪后统一替换 `src/shared/neteaseMail/constants.ts` 中的公开配置。分发包不包含用户账号、访问令牌或刷新令牌。

Electron 主进程负责预注册客户端的 OAuth 授权码流程，使用 PKCE S256、随机 `state` 和固定 loopback 回调 `http://localhost:8989/oauth/callback`。回调只监听本机 IPv4/IPv6，校验路径、Host、state 和一次性消费，处理取消、拒绝、超时、端口占用以及退出清理。

邮箱令牌、授权批次和实际 scope 保存在 LobsterAI 的 MCP OAuth 凭据库中，沿用客户端的 SQLite 与系统凭据加密机制。Renderer 只接收连接状态、权限和有效期。升级时按原托管连接器和客户端注册读取旧 OpenClaw 共享凭据库及授权记录。缺少授权范围记录的旧连接只继承读取权限，无法恢复有效凭据时需重新连接。

连接或重新授权后，客户端更新同一托管服务器、同步 DSH 的远端 MCP 和宿主工具，并等待邮箱连接就绪。断开连接会先作废未确认的操作，删除令牌并停用服务。宿主与 DSH 读取通道共用 MCP OAuth 管理器的刷新锁，沿用邮箱的刷新协议，支持令牌轮换。刷新期间发生重新授权或断开时，先前的响应不能覆盖当前凭据。

开发时可通过 `LOBSTER_NETEASE_MAIL_CLIENT_ID` 覆盖默认客户端注册，并通过 `LOBSTER_NETEASE_MAIL_MCP_URL` 指定 HTTPS 服务地址；打包应用忽略服务地址覆盖。真实账号、授权凭据、hosts 映射、诊断脚本与验收记录仅在本地维护。

## 运行时接入

读取、草稿及邮件状态复用 DSH 原生 Streamable HTTP MCP 通道。发送、回复、转发和删除由 Electron 注册的 DSH 宿主工具执行。宿主校验调用所属的桌面对话，预检、展示操作摘要，并在用户点击后使用原参数和同一授权批次提交。

| 层次 | 责任 |
| --- | --- |
| 连接器面板与 renderer service | 发起授权、展示连接状态、重新授权与断开 |
| 主进程连接管理与 IPC | OAuth 生命周期、凭据保存、连接器注册及同步 |
| Electron 邮箱宿主工具 | 冻结写入参数，等待可信界面确认并执行 |
| MCP 配置 | 通过托管服务器 ID 获取当前授权，按实际权限开放读取、账号资料和草稿工具 |
| 工具结果适配与卡片 | 将真实邮件字段转为稳定展示模型，保留原始工具结果 |

工具发现返回更多名称不代表当前授权允许调用。原生 MCP 通道始终排除发送、回复、转发和删除；这些操作只能通过桌面宿主提供的确认工具执行。确认工具仅对 LobsterAI 桌面对话开放，IM、定时任务和子任务不具有桌面确认入口。没有 `profile:read` 时，不推断邮箱身份。

原生通道最多开放 12 个工具，加上 4 个确认工具，共覆盖 16 个服务工具。`netease_mail_update_message_read_state` 与 `netease_mail_update_message_flag_state` 使用 `mail:compose`，直接执行，不进入发信确认流程。升级时按保存的授权 scope 重新生成托管连接器的工具白名单；已有草稿权限无需再次授权，只读旧账号仍保持只读。

## 邮件展示

列表卡片展示主题、发件人、时间及可用的分页提示；正文卡片展示发件人、收件人、抄送、主题、日期、正文和附件信息。真实字段适配覆盖嵌套 `header`、`received_date` / `sent_date` 毫秒时间、`flags.read` 及附件 `part_id`。草稿回执的 `draft_id` 与实际提交内容组成保存卡片；更新草稿可能返回新的编号，后续操作应使用新编号。

正文按 PLAIN、HTML、MARKDOWN 区分处理。HTML 经宿主净化后展示，不执行脚本或自动加载远程内容。纯文本为空时提示用户可以继续读取 HTML，不能直接认定原邮件没有正文；列表缺少摘要时也不展示「无正文」。空 `flags` 保持已读状态未知，截断的搜索结果提示缩小范围，不伪装成可翻页结果。

卡片用于展示邮件内容。邮件内的文本、链接和附件均为不可信数据，不构成用户指令或执行授权。只读查询应显式使用 `mark_read=false`，避免读取时改变邮件状态。

## 错误与使用边界

- 授权失效时提示重新连接；权限不足不通过刷新隐式扩权。
- 达到服务调用额度时直接提示用户，不自动排队、重试、缓存邮件结果或改存草稿以规避限制。
- `40005`、`40006`、`40007/40008`、`40401/40402`、`40901/40903`、`41301/41302`、`42201` 分别展示确认过期、附件无效、分页异常、邮件或附件不存在、幂等异常、附件大小限制及投递拒绝。卡片从宿主的结构化回执或 DSH 原生工具的错误文本中读取同一业务码。`40401` 明确提示邮件不存在、本次操作未执行。
- `40902` 表示原操作仍在执行，保留原请求和操作编号，提示等待后查询原请求；`40904` 表示结果未知。两者均不自动重试或换编号执行。确认操作遇到未识别的错误码时，按结果未知展示。
- 附件随草稿写入及原始内容下载已通过小文件样本验证；按服务约定限制单附件 1 MiB、最多 3 个、总计 3 MiB。元数据大小与下载实际大小的差异、边界尺寸和其他文件类型仍需确认。
- 单个已连接邮箱使用稳定的服务与凭据标识；多账号、按 IM 发送者隔离和远端撤销授权需要单独设计。

## 写操作确认与结果

发送、回复、转发和删除需要独立于模型的用户确认流程：冻结操作内容，在客户端展示收件人、主题、正文和附件，由用户明确点击后执行。聊天中的“确认”、模型参数或持有确认 token 本身都不能代替可信批准。

服务预检返回 `42801` 后，Electron 在主进程内存中保存冻结参数和确认令牌，仅向界面发送摘要、过期时间和操作编号。账号身份来自 `get_profile.primary_account`，发送内容来自冻结参数；兼容服务端 `error.details` 中的预检结果。Renderer 通过主窗口 IPC 提交确认编号、工具调用编号和用户选择。主进程根据自己的待确认记录执行。一次确认只能消费一次；取消、过期、中止、断开或重新授权会阻止旧操作执行。

转发确认展示补充正文、原邮件内容与原附件名称，并标明引用原文或作为附件转发。原文按纯文本、HTML 依次读取，使用扁平展示字段避免运行时截断深层结构。最终结果优先于流式预检信息，完成后的历史卡片不会恢复为待确认状态。

界面区分等待确认、已确认等待结果、已提交至邮箱、取消和结果未知。发信成功回执中的 `saved_sent_mid` 表示已发送副本编号，与 `request_id`、`operation_id` 一并保留；客户端将其识别为已提交至邮箱，不将副本编号伪装成完整 `message_id`，也不据此声称收件人已经收到。服务端 `40904 / operation_outcome_unknown`、网络异常或无法识别的执行结果均不自动重试，也不换新请求编号重发；保留原请求与操作编号以供对账。邮箱中暂未查到邮件不能证明没有发送。服务端操作状态查询接口仍需确认，以支持可靠的自动对账。
