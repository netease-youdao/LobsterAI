# LobsterAI 桌面龙虾设计建议

2026-09-13 · 设计研究稿 · 未改动产品代码

建议将悬浮球定义为「桌面龙虾」：一个用户主动开启、能接收材料、交代任务、查看进展和取回成果的桌面入口。根据用户补充的形象方向，采用大头小身体的可爱机器人，胸口保留龙虾徽标，旁边配可收起的短标签。展开后承载轻量任务面板，复杂成果进入现有主窗口。首要目标是增加完成并采用成果的用户，而不是增加启动、窗口曝光或悬浮球点击。

**问题判断。**「捆绑后打开率上升、使用率没有明显提升」支持继续研究从打开到完成任务的转化，但尚不能证明原因就是用户忘记使用。至少要区分：不知道能做什么、知道但不知道如何交材料、登录或模型等准备失败、任务执行或成果质量不足、完成后没有再次使用场景。悬浮球主要改善可见性和回到任务的便利性；具体场景与材料入口改善首次提交；可靠交付决定后续复用。此次没有重新查询线上数据，也没有把过去的统计作为本次实验基线。

**本次证据边界。**检查了用户提供的三个 macOS 安装包、当前 test2 工作区的相关源码，以及官方网页。本次桌面控制工具未能取得可用于验证的实机状态，因此以下竞品结论分为包内实现/文案证据与官方说明，不声称已完成三款应用的登录后操作实测。编译资源可能包含受平台、用户设置或远端开关控制的路径；资源存在不等于所有账号都已开放。

**外观与位置。**用户指出 v2 与 Codex 默认机器人过于相似，并提供橙色笑脸、奶油白机身的新参考图。v3 以这张用户参考图为准：奶油白圆角电脑头、蜜橙色脸、有白色高光的大眼睛、开心的小嘴和淡淡腮红，采用大头小身体、短手短脚与轻微歪头，胸口保留一枚橙色龙虾。去掉参考图中的帽子、手机、星星、接口、宣传卡片与背景场景。面部表情承担主要识别，胸口图标负责品牌点缀。

最终悬浮素材应使用透明背景，让机器人直接站在桌面上；短标签单独承载文字。建议悬浮图形先以 56–64 个逻辑像素验证，小尺寸优先保证轮廓与眼睛可识别。32 像素以下的托盘等用途应另做简化头部图标。当前 v3 仍为形象稿，生成工具未产出真实透明通道，尚不能作为最终悬浮素材；交互示意暂保留 v2 图标，仅用于查看流程。

刚开启时旁边带「交给龙虾」短标签，帮助识别用途；用户熟悉后可以切换为仅机器人。执行任务、等待输入或成果到达时，标签位置承载简短状态。不要在用户尚未理解图标时自动缩成几乎不可见的边缘细条。默认靠右侧下半区，避开任务栏、Dock 和常见滚动条；允许拖动、靠边停放并记住位置。每台电脑只出现一个入口，外接显示器移除后回到可见工作区。

形象由内置 imagegen 基于用户参考图生成，现阶段用于确认比例、表情与品牌位置。当前棋盘格是图片内容，不是透明底。量产前需制作透明素材、核对小尺寸显示并补齐状态表情；本稿未完成动画或生产素材验收。完整生成提示与边界保存在同目录 `robot-mascot-v3-prompt.md`。

可爱通过小幅表情与少量状态切换体现。首发只需待命、执行、等待输入、完成四类视觉状态，错误以清晰文案表达。持续摆动、满桌移动、宠物养成、签到或推广红点，会增加复杂性和打扰，暂不列入首发。

**默认关闭与首次开启。**初始为关闭，只有用户明确开启后才持久显示。设置和托盘里始终能找到「桌面龙虾」开关；关闭后重启、升级都保持关闭。开启悬浮球与开机启动分别设置，不捆绑。

默认关闭意味着没有开启的人不会被悬浮球触达，所以开启引导必须成为设计的一部分。建议首次主动进入 LobsterAI 时展示一次可跳过的成果示例：「把文件拖给龙虾，整理成要点、表格或周报」，按钮为「开启桌面龙虾」和「暂不开启」。先展示材料与成果的对应关系，避免只介绍 AI、模型或功能名。用户选择示例时应明确标注示例材料，并保留其自己的输入草稿。

对于有道词典捆绑渠道，更贴近工作时机的入口是词典内的「把这段资料整理成汇报」等场景卡，先看成果示例、再自愿开启。该部分依赖词典侧配合，作为独立渠道实验；不要假定 LobsterAI 的默认关闭悬浮球能覆盖从未主动进入过应用的人。已经选择暂不开启的人不在每次启动时重复被邀请，仍可从常驻设置入口主动找到它。

**点开后的任务面板。**宽度初稿约 400 像素，空态约 300–360 像素高，随屏幕工作区收敛。点球后直接在附近打开小面板；用户点击完整预览、文件编辑或完整任务记录时才进入主窗口。球、快捷键、托盘打开的是同一个面板，任务、草稿和附件一致。

面板主文案：「把什么交给龙虾？」输入提示：「拖入文件、粘贴内容，或说说想完成什么」。首屏提供三个具有明确交付物的候选场景：

| 用户给什么 | 入口文案 | 交付内容 | 需要验证的质量 |
| --- | --- | --- | --- |
| PDF、文档、资料摘录 | 整理资料要点 | 一页要点、来源与待办 | 信息准确、来源对应；没有依据的待办不编造 |
| 多份同类表格 | 合并并找出异常 | 可编辑汇总表、重复或缺失清单 | 行数与总额核对、异常定义清楚 |
| 一周工作记录 | 整理成周报 | 可编辑周报、下周计划草稿 | 不编造进展，待确认内容明确标记 |

这些是首批验证候选，不是已经由真实需求占比证明的最佳排序。应以捆绑新用户访谈、实际材料和交付通过率调整。词典本身已有翻译价值，悬浮入口更应展示整理材料与交付成果的用途。

点击场景后应出现目标、所需材料与成果预览，选择材料后继续；不要仅把一段很长的提示词塞回输入框。拖入材料后，先按文件类型给出最多三个适合的操作，选中后自动填好可读的任务目标。只有确实缺少关键信息时才提问，例如表格按月份还是部门汇总。用户始终可以直接输入自由任务。

材料用可删除的来源卡表达，明确显示已附加的文件、图片、文字或网页链接。点击发送才提交任务。点击球、悬停、打开面板不自动读取全部桌面、剪贴板或当前应用；对用户主动添加的来源，显示其范围。截图只能提供画面，网页链接不代表继承浏览器登录态，文件读取失败要明确提示，不能声称已经理解全部内容。

**任务执行与成果返回。**小面板本身能完成简单提交、补充信息和查看短结果。长任务创建后可收起，用户继续当前工作；状态来自同一个 Cowork 会话和运行记录，不另造一套聊天历史。短问题与长任务使用同一个入口，首版不要求用户先选聊天、Agent、模型、技能或运行模式。

| 状态 | 球或胶囊展示 | 点击后的内容 |
| --- | --- | --- |
| 待命 | 交给龙虾 | 新任务输入及三个候选场景 |
| 已提交、处理中 | 正在整理资料 | 最近一个可信阶段、材料、继续补充与停止 |
| 等待用户 | 需要你确认 1 项 | 明确的问题或待批准操作，可直接回答；复杂审批打开完整页面 |
| 已完成 | 周报已做好 | 成果卡片、快速预览、完整打开、继续修改 |
| 失败或受阻 | 需要处理 | 简明原因、保留材料与草稿、适用的恢复动作 |

只有在成果实际生成并可访问时才显示「已做好」和相应成果名称。普通文本任务显示「回复已完成」。阶段和数字必须由真实事件支持，不展示虚构的百分比或剩余时间。恢复后的状态以最新任务记录为准。

多任务时聚合数量，面板优先展示需要用户输入、需要处理的失败、未查看成果，再展示执行中任务。新事件不覆盖正在编辑的草稿，不抢焦点、不自动弹主窗口。收起面板会保留任务和输入；停止执行有单独且明确的动作。完成卡提供摘要和小型预览，复杂表格、文档与编辑操作进入现有产物面板，并定位到对应成果。

**关闭与打扰控制。**面板的关闭按钮只收起面板；桌面入口菜单提供「关闭桌面龙虾」，立即关闭并持久保存，无挽留弹窗。此操作不等于停止任务或退出 LobsterAI。关闭后，用户仍可从托盘或自己设置的快捷键临时唤起小面板，临时唤起不重新打开常驻球。真正退出应用遵循现有本地任务生命周期，不承诺退出后仍可运行。

借鉴豆包的全屏避让：其他应用全屏时默认隐藏，主动快捷键可临时唤起。演示与屏幕共享提供易发现的手动隐藏入口；不要把跨软件检测共享并自动隐藏作为未经验证的首版承诺。系统免打扰时减少提示，完成消息与现有系统通知去重。为球本身截屏时先隐藏其覆盖，避免把入口截进用户提供的材料。

全局快捷键可改、可清空，并显示注册冲突；macOS 的 Option+Space 与用户已安装的其他 AI 入口可能冲突，不直接照搬。键盘聚焦、Esc 收起、中文输入法发送、多显示器、缩放和任务栏/Dock 避让需做平台验证。此处的尺寸与交互时限都是初稿目标，不是已测试结果。

**分期建议。**首发将范围限制在一条完整链路：自愿开启 → 拖文件/粘贴文字或截图 → 一个明确任务 → 真实执行状态 → 可检查成果 → 下一次再用。包含默认关闭、位置记忆、关闭持久化、轻量面板、草稿与材料保持、三类任务候选、任务状态、成果入口、全屏隐藏、可配置快捷键和必要统计。第一阶段无需宠物商城、主题市场、语音唤醒、全局划词、持续读屏或复杂跨应用自动化。

后续在首发任务证明有效后，再加入一键系统截图、用户指定的当前应用内容、词典上下文转交、自然语言保存常用任务和更丰富的角色反馈。把系统截图延后不影响首版接收用户粘贴的截图。加入新入口时复用同一条材料到成果的流程。

**验证方式。**先招募约 8–12 名没有稳定使用 LobsterAI 的捆绑渠道用户，使用其真实材料做任务观察。展示约 10 秒后让其说明能做什么、需要给什么、如何关闭；观察是否能完成首个任务、切回原应用工作、找到成果并提出修改。不能只询问「喜不喜欢这个球」。候选场景需通过任务级核对：原始材料、生成结果、错误与返工、是否实际采用。

线上在同一批符合条件的新用户中随机分组，三组均保持悬浮球默认关闭：A 为现有入口；B 为首页/快捷入口加入同一套场景与材料流程；C 在 B 的基础上加入桌面龙虾及一次自愿开启邀请。B 与 A 帮助判断任务可理解性的价值，C 与 B 评估可见入口及其邀请的增量价值。主分析按最初随机分组计算，保留没有开启悬浮球的用户，避免直接比较自愿开启者与未开启者产生选择偏差。

主指标可定义为「首次符合实验条件后 7 天内，完成至少一个真实任务且出现成果采用信号的去重用户数 / 同组全部符合条件的去重用户数」。预览、复制、导出、继续编辑属于采用代理信号，需要样本访谈确认，不能直接当作满意或真实业务使用。另看 7 天内至少两天产生真实任务使用的比例、材料到可用结果耗时、任务失败和取消。等待完整 7 天观察窗成熟后比较；如采用 D7 留存，另行固定第几天或时间窗的定义。

漏斗记录入口邀请曝光、主动开启、面板曝光、材料提交、任务开始、完成、成果预览/采用、后续复用。将进程启动、主窗口主动进入和悬浮球展示分开，避免悬浮球常驻再次抬高「打开」指标。统计以随机组、渠道、首次用户/已有用户分层；首轮先建立基线和样本量，再约定需要达到的提升及置信范围。

护栏包括 24 小时内关闭比例、失败率、打扰反馈、可观测的退出/卸载信号，以及相对现有应用的空闲 CPU/内存增量。预热面板的响应目标可以先定为机器范围内 p95 小于约 300 毫秒，但应由目标 Windows 设备与 macOS 设备实测修正，不把模型启动时间混入唤起速度。
