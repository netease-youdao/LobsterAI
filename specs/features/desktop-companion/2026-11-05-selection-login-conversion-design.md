# 划词登录转化 P0 设计文档

日期：2026-11-05 · 状态：已实现，待实机验收

## 1. 概述

### 1.1 问题/背景

划词翻译免登录后，用户能用的只有翻译。解释、总结、追问、朗读、转为任务都要登录。用户点到这些功能时，现在的体验有三个问题：

1. 登录提示套用错误样式：红色感叹号，一句「请先登录 LobsterAI，再使用此功能。」和带下划线的「去登录」，没有说明登录能得到什么。
2. 点「去登录」打开系统浏览器后，未固定的卡片失去焦点就关闭。登录换取凭证成功后，主进程还会重置翻译/朗读卡片。用户回来时原文和动作都没了，要重新划词、重新点。
3. 划词和翻译卡片的登录提示没有任何埋点，无法区分「没看到提示」「看到没点」「点了没登完」。

### 1.2 目标

- 登录提示说明登录的收益，并给出一个主按钮。
- 从卡片发起的登录，完成后自动接着做用户原本要做的事。
- 能统计 `login_shown → login_click → login_success` 漏斗。

不改变翻译免登录、各功能的登录要求和额度规则。

## 2. 用户场景

### 场景 1：划词回答卡

**Given** 未登录用户划词后点「解释」，卡片显示登录提示。

**When** 点「登录」，在浏览器完成登录。

**Then** 卡片一直留在原处（自动固定）；登录后直接开始解释。

### 场景 2：翻译卡里的追问或朗读

**Given** 未登录用户在翻译卡里追问，或打开朗读卡，被登录提示拦下。

**When** 点「登录」，在浏览器完成登录。

**Then** 卡片在原位置重新打开并保持固定，用新账号重新执行原工具（重新翻译，或开始朗读）；之前被拦的追问在译文返回后自动发出。焦点留在登录结束时所在的窗口。

### 场景 3：用户放弃

**Given** 用户点了登录，但随后关闭了卡片，或划了新的内容。

**When** 之后登录成功。

**Then** 不再弹出旧卡片。

## 3. 功能需求

### FR-1：权益卡

替换原错误样式，做成一行轻量提示：左侧标题「登录后即可使用「{功能}」」和副标题（复用主窗口的新用户权益文案 `loginIntroductionPromo`），右侧一个胶囊主按钮「登录」。不再放 LobsterAI 标识，卡片头部已有。浏览器打开后，副标题换成带等待动效的「请在浏览器中完成登录，之后会自动继续」，按钮降为灰色「重新打开」；打开失败时副标题显示红色失败文案。

位置：翻译卡里被拦的追问，提示放在问题下方（回答的位置）；被拦的翻译或朗读放在结果下方；划词卡放在原文和问题下方。

### FR-2：登录期间保留卡片

渲染层打开浏览器前先调用 `desktop-companion:login-start`。主进程按发送窗口识别来源，只接受划词卡和翻译/朗读卡：

- 划词卡：仅回答模式固定，不上报 `pin` 交互。
- 翻译/朗读卡：固定，并记下工具、原文和被拦的追问（`question`）。这份记录不受登录引起的会话重置影响；用户关闭卡片、发起新的翻译/朗读或窗口销毁时丢弃。

### FR-3：登录后续做

主进程在登录换取凭证成功、广播会话变化后调用 `handleLoginSucceeded()`：

- 划词卡：卡片仍在，渲染层看到新会话后照常自动发起请求，不需要主进程介入。首次登录必然紧跟一次网关重启（同步服务端模型），重启期间悬浮球不可用；固定的回答卡在网关重启和暂停划词时保留，只在关闭划词工具条、关闭悬浮球或截图时关闭，进行中的回答也不中止。
- 翻译/朗读卡：仅当登录可归因于卡片的点击（见 FR-4）时，用原位置、固定状态重新打开（`showInactive`），请求按新账号重新执行；否则丢弃续做记录。续做不再上报 `run`。被拦的追问只随这次重开投递一次，主进程保存的输入不含追问，渲染进程之后重新加载不会重发。
- 追问的"需要登录"状态归属于它所在的对话，卡片重开的第一帧不会残留旧的登录提示，也就不会重复上报 `login_shown`。

### FR-4：埋点

沿用 `lobsterai_desktop_companion_action`：

| 事件 | 上报方 | 参数 |
| --- | --- | --- |
| `login_shown` | 渲染层，经现有分析 IPC，仅允许划词卡和翻译/朗读卡 | `tool`、`journeyId` |
| `login_click` | 主进程处理 `login-start` 时 | `tool`、`journeyId` |
| `login_success` | 主进程在登录成功后 | `tool`、`journeyId`、`durationMs` |

同一提示的三个事件共用渲染层生成的随机 `journeyId`。登录归因给 30 分钟内最近一次点击；超时或没有点击时不上报 `login_success`。不上传原文或追问内容。

## 5. 边界情况

| 场景 | 处理方式 |
| --- | --- |
| 登录在主窗口完成，但 30 分钟内点过卡片的登录 | 归因给卡片，翻译/朗读卡照常续做 |
| 点击后超过 30 分钟才登录 | 不上报成功，不弹出旧卡片；仍固定着的划词卡会照常执行 |
| 多次点击 | 以最近一次为准 |
| 账号切换（A → B） | 旧结果随会话重置清除，原文和动作按新账号重新执行 |
| 续做后的译文失败 | 不发出追问，显示原有错误 |
| 浏览器没能打开 | 显示失败文案，卡片保持固定，可重试 |

## 6. 验收标准

1. 未登录时，划词卡和翻译/朗读卡的登录提示为权益卡样式，中英文文案正确。
2. 点击登录后切到浏览器，卡片不关闭。
3. 登录成功后：划词卡自动出结果；翻译卡重新翻译并自动发出追问；朗读卡重新打开并开始朗读。
4. 关闭卡片后再登录，不弹出旧卡片。
5. 埋点按上表上报，`journeyId` 一致。
6. 相关 Vitest、改动文件 ESLint、Electron 编译和 renderer 类型检查通过。

### 6.1 实机验收记录（2026-11-05）

Windows 下用独立用户目录运行 worktree 的 Electron 开发版，连接生产服务。翻译卡通过与工具条相同的 IPC 打开；划词卡由真人在记事本中划词并点击。登录由真人账号在系统浏览器完成（门户已有会话时自动回调）。埋点在主进程拦截实际发出的 rlog 请求读取。

| 场景 | 实测结果 |
| --- | --- |
| 未登录翻译 | 返回真实译文 |
| 翻译卡追问被拦 | 权益卡「登录后即可使用「追问」」；`login_shown`（`source=language_tools`、`tool=ask`） |
| 点「登录」 | 卡片固定，进入等待状态；浏览器占据焦点后窗口仍可见；`login_click` 与曝光同一 `journeyId` |
| 登录成功 | `login_success` 同一 `journeyId`；卡片固定重开、重新翻译，追问自动发出并得到模型回答 |
| 重开后重新加载渲染进程 | 只重新翻译，不重发追问，仍保持固定 |
| 划词总结被拦 → 登录 | `open → run → login_shown → login_click → login_success`（同一 `journeyId`），随后总结自动发起并成功 |
| 登录后的两次网关重启 | 总结请求恰在第一次重启开始时发起，3.3 秒后完成；两次重启后卡片仍可见、固定，回答保留 |

实机过程中发现并修复三处问题：续做时多报一次 `login_shown`；渲染进程重新加载会重发追问；登录后的网关重启关闭固定的划词卡并中止回答。修复后复测通过。
