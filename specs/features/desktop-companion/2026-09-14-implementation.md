# 桌面小助手：首版试用

这版已接入 Electron 应用，使用用户选定的橙白大头机器人方向。角色胸前保留龙虾标记，并按用户参考图戴上黑色博士帽和橙色流苏。运行资源为 384 × 384 的透明 WebP；原始透明 PNG 和生成提示词同目录保存。

## 怎么试

运行当前源码后，进入 **设置 → 通用 → 桌面小助手**，开启「显示桌面小助手」。

- 默认关闭，只有主动开启才常驻。右键「关闭桌面小助手」或设置关闭后，重启仍保持关闭。
- 拖动角色调整位置，单击展开/收起任务面板。用途提示可单独关闭，切换时保持角色位置。
- 托盘和设置都可直接打开轻量面板。可录入可选的全局快捷键；关闭角色后，快捷键仍可临时唤出面板。
- 拖入文件、添加材料或粘贴截图，说清想拿到的结果，选择任务文件夹后提交。
- 提供文档整理、表格合并、工作周报三个材料驱动的示例，点击只填入需求，不自动执行。
- 使用现有主 Agent 和模型配置执行，结果入口返回同一主会话。面板展示任务状态、最新回答预览和最近五个任务。
- 未发送的文字、材料路径、任务文件夹及选中的会话会保留。提交成功才清空已发送草稿；关闭面板不停止任务。停止任务使用现有会话停止接口。
- 权限确认和复杂问答转到主窗口。首版不自动读取屏幕或剪贴板。

普通开发启动仍使用项目既有的 `npm run electron:dev`。如 5175 已被另一个 checkout 占用，不要直接结束其进程。可在空闲端口分别启动 Vite 和 Electron，并给 Electron 设置一致的 `ELECTRON_START_URL`。

## 实现边界

- `src/main/desktopCompanionManager.ts`：管理独立的角色窗口、面板窗口、位置、快捷键、草稿持久化及 IPC。关闭这些窗口不会调用停止任务接口。
- `src/shared/desktopCompanion/`：跨进程契约、位置计算和中英文文案。
- `desktop-companion.html` 与 `src/renderer/components/desktopCompanion/`：独立 React 入口，直接消费既有会话桥接接口；不启动另一套 Cowork 服务或任务队列。
- 主窗口只增加窗口管理器初始化、清理、托盘和设置入口；任务执行仍走现有 OpenClaw 接口。
- IPC 限定主窗口及两个助手窗口的主 frame；窗口保持 sandbox、contextIsolation，禁止页面导航和新窗口。
- 面板优先在角色上方/下方展开，中间位置空间不足时向屏幕内侧展开；显示器变化和旧位置越界会重新限制到可用工作区。

## 验证记录

使用 macOS arm64、Electron 43.5.0 和当前源码的生产构建，在独立测试用户数据目录中启动完整应用。没有替换已安装的 LobsterAI，也没有关闭其他 checkout 的开发实例。

已验证：

1. 新配置默认不出现角色；从设置开启后角色和面板正确创建。
2. 真实鼠标拖动后，窗口位置与保存坐标一致；关闭用途提示时角色右侧位置不变。最终构建的实际位置检查确认，角色位于屏幕中部时面板在其左侧展开，两者不重叠。
3. 粘贴测试图片后，通过既有附件接口保存到磁盘；修正后显示原文件名。
4. 收起后文字和材料保留；真实退出并重启后，关闭状态及未发送草稿/材料恢复。
5. 真实会话接口接受一次测试提交，选中会话持久化，已发送草稿清空；收起面板后该任务仍处于运行状态；显式停止成功；结果入口打开同一主会话。
6. 中文浅色、中文深色和英文面板截图检查通过。
7. 22 项针对性 Vitest 测试通过，覆盖窗口生命周期、持久化、快捷键冲突、IPC 来源校验、显示器边界、状态预览和现有附件准备逻辑。
8. Electron 编译、完整生产构建、全部修改 TypeScript 文件的零警告 ESLint 检查通过。

尚未完成的验收：

- 测试网关出现既有 `vydra` 插件能力授权校验错误，后续连接还出现 `AUTH_TOKEN_MISMATCH`。已经验证到任务接收、运行状态、停止和主会话跳转，没有验证模型成功产出最终文件。
- 全局快捷键已通过实际注册和冲突处理检查；自动化合成按键未稳定触发系统级快捷键，仍需人工用真实键盘验收。
- Windows/Linux、跨屏不同 DPI、全屏应用和长期资源占用仍需后续验收。当前 macOS 设置了不覆盖全屏 Space。
- 尚未做使用率实验。是否改善真实交付和复用，应在接通任务成功率、产物打开/修改、再次使用等指标后评估。
