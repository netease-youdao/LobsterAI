# 本地产物网格按任务折叠设计

## 1. 背景与范围

本地产物已经按任务最近活动时间排序。网格中如果一个任务产出数百个文件，该任务会占用大量空间，降低用户浏览其他任务的效率。

本次给**本地产物的网格视图**增加任务级预览、展开、继续加载与收起。列表视图继续使用现有文件级分页；云端文件不变。仅修改 LobsterAI 客户端的 Main 查询、IPC/preload 和 Renderer，不修改服务器、OpenClaw 或数据库结构。

参考图用于表达“三个卡片 + 下方剩余文件按钮”的交互，不要求重做现有卡片缩略图、尺寸、分类和工具栏。

## 2. 用户场景

### 2.1 快速浏览多个任务

Given 第一个任务有 10,000 个产物，后面还有多个任务；When 打开网格；Then 首批显示最多 8 个任务，每个任务最多 3 张卡片，第一个任务不会占满首批数据。

### 2.2 按需查看产物

Given 一个任务匹配 120 个文件；When 点击“还有 117 个文件”；Then 重新读取该任务的前 24 个文件，替换原来的 3 个预览，显示“继续显示 24 个”按钮，右侧独立显示“还有 96 个文件”。继续点击则追加下一批，直至全部展示。

### 2.3 收起后继续浏览

Given 任务已经展开；When 点击标题或底部的“收起”；Then 只保留前 3 个，定位到该任务标题或保留的可见内容，其他任务展开状态不变。已经打开的文件预览不因收起而关闭。

## 3. 功能规则

### FR-1：数量与排序

- 本地产物每次进入页面默认使用网格模式，用户仍可手动切换为列表；当前页面内保留手动选择，不持久化到下次进入。云端文件继续使用列表模式。
- 固定预览数量为 3，不跟随响应式列数变化。窄窗口可以换行，宽窗口可以留空列。
- 当前筛选下 0 个文件的任务不出现；1～3 个全部显示且无折叠按钮。
- 超过 3 个时，下方左对齐显示“还有 N 个文件”，其中 N = 匹配文件总数 - 3。
- 展开首批为前 24 个，**不是在原有 3 个后追加 24 个**；后续每次最多追加 24 个。API 单次最多 100 个。
- 匹配总数是当前分类、关键词、收藏筛选下，归属于该任务且没有标记 missing 的文件数。permission_denied 文件仍保留现有展示。不能使用 relatedSessionCount，它表示某个文件关联的会话数。
- 任务按 updatedAt、createdAt、sessionId 倒序；任务内按 sortTime、itemId 倒序。时间保留小数，字符串使用与 SQLite BINARY 一致的 UTF-8 比较。
- 文件在所有有效会话关联中先选唯一归属：lastRelatedAt、会话 updatedAt、sessionId 倒序。不能先按目标会话筛选关联再选归属。

### FR-2：交互与无障碍

- 使用原生按钮，支持键盘与焦点；折叠控件声明 aria-expanded 和目标关联。
- 加载和失败只影响对应任务，保留已有卡片；提供本地重试，阻止重复请求。
- 展开后的标题提供“收起”，无需滚到全部文件末尾。正在加载时仍可收起，收起使未完成的响应失效。
- 每个任务独立展开；不增加全局“展开全部”，不自动读取所有隐藏文件。
- 新增可见文案提供中文和英文。
- 展开、继续显示、收起和重试使用预览卡片式的中性浅灰样式，不使用主题色；深色模式使用独立灰阶。交互状态、具体色值与验收见[中性色控件设计](./2026-09-07-library-grid-neutral-controls-design.md)。

### FR-3：状态生命周期

| 事件 | 展开状态与数据处理 |
| --- | --- |
| 首次进入、查询条件变化 | 默认折叠；查询之间不混用缓存或游标 |
| 同页面网格 → 列表 → 网格 | 保留网格任务前缀及展开意图；失效时重新校验 |
| 标题、时间变化，任务跨日期移动 | 以 sessionId 标识，保留展开意图 |
| 收起 | 只显示前 3 个，取消旧任务请求的提交资格 |
| 会话删除或不再匹配 | 从有效结果中移除，旧请求不得恢复该任务 |
| 离开页面、应用重启 | 重置，不写 localStorage/SQLite |
| 手动刷新 | 回顶部并恢复默认折叠，重新读取首批任务 |

## 4. 数据接口与查询

### 4.1 两级独立分页

现有 listLocal 返回全局文件前缀，不能在此结果上简单 slice(0, 3)：它不知道完整任务数量，还会导致全局加载触发器不断读取被隐藏的文件。

新增网格协议 Version 1，与原文件列表协议 Version 2 独立：

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| listLocalTaskGroups | category、keyword、favoritesOnly、taskCursor、taskPageSize（默认 8，最大 32） | groups、nextTaskCursor、hasMoreTasks、counts、protocolVersion、sort |
| listLocalTaskItems | sessionId、同一组筛选、itemCursor、pageSize（默认 24，最大 100） | session、matchedFileCount、items、nextItemCursor、hasMoreItems、protocolVersion、sort |

每个 group 包含 session、matchedFileCount、previewItems（最多 3 个）。counts 仍表示整个匹配结果的文件数量，不改成任务数或当前已显示卡片数。

首批及后续任务页采用 SQL CTE/window ranking 批量获得任务计数与每任务 top 3；只补全被返回文件的对象，不逐任务 N+1 查询、不在 Renderer 拉全量后裁剪。同一 IPC 的 counts、预览、游标和文件对象在一个只读事务快照内获得。不同 IPC 之间不承诺冻结快照，Renderer 负责检查和失效刷新。

### 4.2 游标与兼容性

- 任务游标独立 kind = task_groups，绑定查询及末任务的 updatedAt、createdAt、sessionId。
- 任务内游标独立 kind = task_items，绑定查询、sessionId 及末文件的 sortTime、itemId。
- 校验版本、类型、字段、时间、标识符、查询身份、排序及严格分页边界，拒绝跨筛选、跨任务、跨接口游标。
- 不用旧文件列表游标继续任务分页，也不把不连续的任务预览拼成旧列表分页状态。
- 缺少新 API 或协议不匹配时明确提示重启应用，不静默退回文件级裁剪方案。
- 不改原 listLocal 调用方，不需要持久化数据迁移。应用升级后应重启 Electron，使 Main/preload/Renderer 使用同一套协议。

## 5. Renderer 与滚动

### 5.1 独立网格状态

网格控制器保存任务前缀和外层游标；每个任务独立保存展开意图、当前可见文件前缀、内层游标、加载/错误及请求代次。列表数据仍由原有流程管理。状态和校验逻辑放入独立文件，LibraryView 只负责连接入口、预览、事件及呈现。

虚拟行只包含当前可见卡片。折叠按钮作为独立虚拟行，不能把隐藏文件仍挂在 DOM 中再使用 CSS 隐藏。列表底部触发器仅加载更多**任务**，绝不加载任务隐藏文件。

### 5.2 稳定位置

- 展开及追加在提交前捕获可见锚点，新增内容位于已有内容之后。
- 收起使用任务标题锚点，不能依赖即将隐藏的文件。标题当前不在 DOM 中时，通过虚拟行索引定位。
- 展开、收起及位置恢复同步暂停底部自动加载，布局导致的 intersection 不能读取下一页。只有新的向下浏览意图或显式“加载更多”才能继续。
- 用户滚轮、触摸、键盘或滚动条操作使旧恢复失效；窗口变化不应让过期恢复夺回滚动控制。
- 后台恢复按任务单位额外寻找最多 2 页（默认每页 8 个任务）的主锚点；不会展开隐藏文件来追逐锚点。

### 5.3 数据变化与预算

收到本地文件/收藏/会话变化事件时，立即使外层和内层旧游标失效。后台先准备完整候选结果：任务摘要和已展开文件前缀均校验完成后，一次替换，不混合新摘要和旧任务文件。

后台刷新复用有界协调策略：一次立即重试、真实变更持续到来时等待 1 秒安静窗口、每次自动重建窗口的软预算 2 秒。持续的无效游标或前后矛盾数据在一次立即重试后停止，不在没有新事件时无限轮询。展开、文件追加及任务追加共用这次重试额度。

软预算在请求边界检查，不假装可中断已经进入 Main 的同步 SQL。首次加载和手动刷新已限定只读取首批 8 个任务，不套用后台重建的 2 秒预算；否则较慢设备会一直丢弃合法首屏。它们仍校验协议、页大小和请求代次。

如果已展开内容过多，无法在预算内安全恢复，则保留旧快照、禁止旧游标继续分页，显示“文件有更新，点击刷新将回到顶部并恢复默认折叠”。不能在普通更新中偷偷收起，也不能无限读取。

## 6. 主要实现边界

- shared/library：网格类型、限制、协议、游标 guard 与查询身份。
- main/library/libraryLocalTaskQuery：批量任务和任务内文件查询；libraryLocalStore 小范围委托；libraryIpc 注册和输入校验。
- main/preload 与 renderer/types/electron.d.ts：桥接两种新查询。
- Renderer 新增网格控制器、校验、hook；LibraryView 按本地网格/列表选择独立状态。
- LibraryVirtualizedGroups：任务头与底部控件虚拟行；scrollAnchor/hook 增加任务锚点和同步加载门控。
- services/i18n：双语提示；单元/集成测试覆盖接口、状态机与位置恢复。

## 7. 验收标准

- 0、1、3、4、7、24、25、120 个文件的边界正确；3 → 24 → 48 → 收起为 3。
- 首任务 10,000 个文件时，首批仍能看到后续任务，文件对象补全数量受 3 × 任务页大小约束。
- 分类、搜索、收藏计数正确；唯一归属、时间小数、同时间 BINARY 排序、权限异常行为一致。
- 两种游标不可互用，也不能跨查询或任务使用；旧协议缺失时明确报错。
- 重复点击、展开后立即收起、切换筛选/视图、会话删除和旧响应返回不会污染新状态。
- 普通更新保留展开意图，完整候选统一提交；超预算旧快照保留且禁止旧游标使用。
- 收起长任务时定位正确，预览保持打开，布局变化不自动读取隐藏项或连续触发任务分页。
- 列表和云端回归、触及文件 ESLint、相关 Vitest、Renderer 构建和 Electron 编译通过。
- 浏览器验证真实虚拟行/滚动交互；完整 Electron 与跨平台体验需要单独验证，不以纯函数测试代替。

## 8. 实施记录

### 8.1 已落地

- 新增独立任务查询模块 `libraryLocalTaskQuery.ts`，桥接 `listLocalTaskGroups` / `listLocalTaskItems`，不影响原 `listLocal` 协议。
- 新增 `libraryTaskGridController.ts`、`libraryTaskGridValidation.ts` 和 `useLibraryTaskGrid.ts`，隔离网格与列表数据及异步生命周期。
- 会话底部控件作为独立虚拟行；会话标题提供收起；通过 sessionId 恢复标题位置与必要的键盘焦点。
- 同步暂停布局导致的自动加载；禁用已失效的分页操作，始终保留收起能力。
- 使用成功数据提交的 `dataRevision` 驱动预览校验，折叠/加载提示变化不会清空预览；本地变更同时清理关联会话菜单缓存。
- 已增加双语文案和各层测试。没有创建提交；此前按任务时间排序的改动保留。

### 8.2 验证记录

- 最终全量 Vitest：415 个测试文件通过，4157 项通过、2 项跳过，包含慢首屏/手动刷新预算测试。
- 相关 TypeScript 文件 ESLint：零错误、零警告。`git diff --check` 通过。
- `npm run build` 与 `npm run compile:electron` 通过。构建仍有仓库现有的 Browserslist、Vite CJS、第三方 eval 及分块提示，没有为此做无关修改。
- 隔离 Chrome 使用合成文件与真实 hook/虚拟列表验证：首批 8 任务各 3 个；3 → 24 → 48 → 3；收起后的标题位置及焦点在 5.5 秒观察期内稳定；预览保留；延迟响应取消；局部重试；视图切换与普通更新保留展开；筛选/手动刷新重置。
- Chrome 补充验证真实 IntersectionObserver：收起导致页面变矮不会追加任务；300/540/1080 px 宽度变化仍只显示每任务 3 个，不触发额外分页。
- 查询测试覆盖首任务 10,000 个文件、固定 5 次批量 SQL prepare、同事务元数据及按需文件对象补全；这不是完整客户端性能基准。

重启 Electron 后验证完整“我的文件”页面、真实文件缩略图/预览、搜索和收藏及 Windows/macOS 交互。未重启用户正在运行的客户端、未访问其真实会话数据库，也未启动 OpenClaw 做无关操作。隔离组件验证不等价于完整应用及跨平台人工验收。
