# 专家广场设计文档

## 1. 概述

### 1.1 问题与背景

原 Agent 模板藏在创建弹窗中，用户需要先理解配置才能使用；“专家套件”又容易与角色型专家混淆。模板内容写在客户端，更新依赖发版，示例问题还常以“我会提供材料”开头，首次发送后停在追问或方案阶段。

本功能基于现有 Agent 引入专家广场，由远程目录组织角色、场景和示例，降低发现与首次使用门槛。kit 保留为能力套件，不引入专家团或新的多 Agent 编排运行时。本文统一记录广场、配置下发、交互与头像、首问交付，以及本轮验收发现的配套修复。

### 1.2 目标

- 用户能发现专家、召唤并原样发送首问，直接体验实际成品；也能携带已有草稿切换专家。
- 专家内容、排序和头像可独立发布与回滚，客户端负责校验、展示和安装。
- 复用普通 Agent 与 OpenClaw 会话链路，保留旧模板实例、用户配置和历史会话。

## 2. 用户场景

| 场景 | Given | When | Then |
|------|-------|------|------|
| 首次体验 | 未安装目标专家、没有准备附件 | 在广场召唤并发送默认问题 | 安装 Agent 并完成配置同步，使用示例素材生成可打开的成品；召唤本身不发送消息 |
| 带草稿切换 | 新任务页已有输入或附件 | 从专家入口选择已安装专家或自建 Agent | 切换到对应新任务页，保留草稿和附件，展开其侧栏分组 |
| 复用旧模板 | 已有同一 presetId 的 Agent，可能改过指令、技能或头像 | 再次召唤或刷新目录 | 复用实例，示例来自新目录；业务配置保留，头像按归属处理 |
| 内容更新或失败 | 维护者发布新目录，或配置暂时不可用 | 客户端访问广场 | 获取通过校验的新目录；失败时使用本环境有效缓存，无缓存则提供重试 |

## 3. 功能需求

### FR-1：入口与发现

原“专家套件”入口改为“专家广场”，使用人物与星芒线性图标。kit 更名为“套件”，放到“套件·技能·连接器”的首个 tab，保留原安装能力。

广场由精选场景和全部专家组成，支持名称、描述、标签搜索及分类筛选。精选场景隐藏横向滚动条，保留翻页按钮、滚动吸附、触控板/触摸及键盘操作。卡片右上角常驻“召唤”，其余区域均打开详情；去除底部“查看介绍与示例”。详情展示范围、标签筛选和三个中英文示例，旧的两问目录仍可显示。

### FR-2：召唤与会话定位

召唤新建或复用普通预设 Agent，完成 OpenClaw 配置同步后进入新任务页，将示例作为未发送草稿。新任务页提供已安装专家和自建 Agent 选择，以及前往广场的入口。选择已有 Agent 保留输入和附件；召唤、首条消息及会话导航展开目标侧栏分组，消息流不能反复打断用户手动收起。

### FR-3：头像与用户配置兼容

内置专家使用中性机器人默认底图和分类图片，保留既有三个专属示例。头像直接展示，去除灰白外框；精选、列表和详情分别使用 32、48、64 px。主 Agent、自建 Agent 和用户明确选择的头像不参与默认头像替换。

目录更新不重写已安装 Agent 的名称、指令、身份、模型、技能或工作目录。只有仍受预设管理的头像可随目录更新；示例更新只影响新会话草稿。

### FR-4：首问可直接交付

首问自带任务、素材或模拟数据、合理默认值、输出格式和自检要求，用户原样发送即可体验成果，第二、第三问保留业务任务模板。要求文件时应实际生成并验证，不能仅交付大纲、计划或口头承诺。

模拟材料须标注；文件整理仅操作新建演示目录，网页演示只读公开信息。真实业务缺少关键材料或授权时仍应询问，“无需追问”不授权编造业务数据或越过操作权限。

### FR-5：可配置与可回滚

内容通过“独立 Git 仓库 → 不可变 CDN 目录 → Overmind 清单 → 客户端”下发，分类、场景及专家数组顺序即展示顺序。依据匿名聚合需求优先展示办公、内容、日常电脑操作等场景，同时保留校园、求职、金融、法务等覆盖；不将原始线上请求写成公开示例。

新增专家须有独立工作方法、明确交付物和可用能力。`skillIds` 只引用目标客户端已有技能，目录不自动安装技能、插件或授予权限。数量、排序与示例条数是内容版本数据，不写死在客户端。

## 4. 实现方案

### 4.1 内容协议与维护

原始内容位于私有 `lobsterai-expert-store` 仓库：

| 内容 | 作用 |
|------|------|
| `catalog.json`、`experts/<id>.json` | 版本、分类、场景、顺序及专家元数据、技能、头像、示例 |
| `prompts/<id>.zh.md` / `.en.md`、`prompts/first-delivery.*.md` | 双语工作方法及构建时拼接的通用交付原则 |
| `assets/category-avatars.json` | 分类头像文件与 CDN URL；专家专属 icon 优先，未设置时继承分类图片 |
| `dist/experts-<version>.json`、`releases/<version>.manifest.json` | 确定性构建的完整目录与发布清单；已发布目录不可覆盖 |

Overmind `expert-store` 支持以下对象或其 JSON 字符串：

```json
{
  "schemaVersion": 1,
  "version": "<content-version>",
  "catalogUrl": "<supported-https-cdn-url>",
  "sha256": "<sha256-of-raw-utf8-catalog-bytes>"
}
```

目录包含同版本的 `schemaVersion`、`version`、`categories`、`scenarios`、`experts`。专家 ID 唯一、稳定，不复用为不相干的角色；场景引用必须存在。schema v1 最多允许 100 个分类、100 个场景、1,000 位专家，每位最多 20 个标签、12 个示例及 50 个技能。视觉色调来自客户端有限枚举，不执行远程 HTML、CSS 或 JavaScript。

### 4.2 拉取、校验与缓存

`getExpertStoreUrl()` 与 skill-store、kit-store 沿用相同的 `app.testMode` 规则。主进程 `ExpertStore` 合并同端点并发请求，先读取对应环境缓存，再下载并校验：

- 清单不超过 32 KiB，目录不超过 4 MiB，每次请求超时 10 秒。
- 仅接受允许的 HTTPS CDN 来源，不跟随重定向；校验原始字节 SHA-256、schema、引用关系和版本一致性。
- 校验成功后通过临时文件原子替换 `userData/expert-store/<endpoint-sha256>.json`，再返回渲染进程。

缓存按完整端点隔离。成功后 5 分钟内复用，之后在访问时刷新，无后台轮询；有缓存时刷新失败保留有效内容，30 秒后可重试。首次无缓存且失败则返回错误。主动空目录合法，回滚允许较低版本号，内容由摘要识别。

### 4.3 安装、草稿与侧栏

渲染进程通过 `AgentIpcChannel.ExpertCatalog` 获取目录，召唤仅传专家 ID，主进程选择校验后的模板。`agents:presets` 和 `agents:presetTemplates` 保持数组契约。

`AgentManager.addPresetAgent()` 优先按 presetId 查找本地实例，存在即复用，停用实例重新启用；新安装按当前语言创建普通 Agent，等待 OpenClaw 配置同步后返回。并发安装再次检查实例，自建 Agent ID 冲突沿用既有分配策略。目录更新只影响新安装的业务配置，已安装实例断网或下架后仍可从 Agent 入口使用，不增加新运行时或 OpenClaw 补丁。

`expertOnboarding.ts` 准备草稿，并向 `agentSlice` 写入一次性侧栏展开请求。`useAgentSidebarState.ts` 等偏好与 Agent 列表就绪后展开并消费请求；会话导航按会话 ID 和所属 Agent ID 触发，不监听完整会话对象。保留其他分组状态，流式消息、标题和后台任务更新不会覆盖手动收起。

卡片使用独立的整面详情按钮与上层召唤按钮，避免嵌套按钮，支持 Enter / Space。卡片标签仅展示，详情内标签负责筛选。

### 4.4 头像归属与持久化

分类图片为 256×256 WebP、每张低于 20 KiB，以颜色和职业配饰保证小尺寸可辨认；原图及生成提示词留在内容仓库。应用仅内置 3,612 字节的机器人兜底图。远程图片校验协议和来源，延迟加载、异步解码且不发送 referrer。

SQLite `agents.icon_customized` 是可空新增字段：0 为预设管理，1 为用户选择，NULL 为未标注的旧记录。新预设写 0，用户实际换头像后写 1，编辑其他字段不改变归属。

旧记录通过 `usesManagedPresetAvatar()` 结合 preset 来源、非主 Agent、稳定 presetId 和历史默认值精确识别；已知旧默认 SVG 或缺省龙虾值视为受管理，其余图片或 SVG 保守视为用户选择。历史记录无法还原“用户曾重新选中同一默认值”的意图，新字段保证后续可识别。

目录校验成功后，`AgentManager.getExpertCatalog()` 仅向受管理实例写入有效图片 URL，数据层写入前再次检查归属；不改其他配置、不触发 OpenClaw 重启，单个头像失败不阻断目录。设置页仅在头像实际变化时提交 icon。广场展示目录头像，已安装实例展示本地归属结果；受管理图片失败回退内置机器人，用户头像沿用原回退策略。

### 4.5 首问内容与 Windows 表格重算

本轮完善前 24 位专家的双语首问，并为新安装实例拼接通用交付原则。应用开发、数据分析、流程自动化不再默认选择只读的 `create-plan`；旧实例的指令和技能保持不变。重点约束如下：

| 任务 | 首次体验设计 |
|------|--------------|
| PPT | 自带模拟咖啡店数据，制作六页可编辑 PPTX；图表使用矩形、线条和文字，附数据表，适配当前端内 Chart/SmartArt 展示限制 |
| 视频 | 九秒、三张字幕卡、淡入淡出，交付实际 MP4 与源文件，减少对大型工程和外部素材的依赖 |
| 数据分析 | 区分事实与假设；月度总量不能证明同一人群或因果关系，禁止用净增订单/净增访客冒充新增人群转化率 |

Excel 验收发现 Windows 旧重算脚本依赖错误宏目录且缺少有效超时，导致首问长时间等待。XLSX 技能升级至 1.0.1：Windows `.xlsx` 使用 `soffice.com` headless 转换，在源文件同卷临时目录创建独立 LibreOffice profile 和输出目录，按[官方启动参数](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)调用，无需宏或接入用户 Office 实例。

等待设置 timeout，超时只结束本次 PID 及子进程，不按进程名清理 Office。仅在转换成功、输出可读取且源文件大小/修改时间未变时原子替换；缺少依赖、超时、损坏输出、并发修改或 Windows 宏工作簿均保留原文件并报错。Linux/macOS 原流程不变。

### 4.6 开发体验实例的登录回跳

独立资料目录验证时，Windows 协议启动不会继承原终端环境变量，可能用默认 userData 启动另一实例。开发协议注册因此携带绝对目录 `--lobsterai-dev-user-data-dir`，使用开发服务器时另携带 `--lobsterai-dev-start-url`；`developmentProtocolContext.ts` 在设置 userData 和获取单实例锁前恢复上下文，使回调交给原实例，冷启动也使用对应渲染页面。

目录参数优先于开发环境变量，相对路径无效；渲染地址仅接受无凭据、查询、片段且为根路径的本地 HTTP(S) 地址，主机限 localhost、127.0.0.1 和 IPv6 loopback。参数使用独立 argv，不拼接 shell。生产 bundle 的未打包应用只记录目录；已打包应用忽略开发参数。授权码交换、账户存储和本地 HTTP 回调流程保持不变。

### 4.7 内容发布与回滚

内容修改后递增版本、构建并校验，上传压缩资源及不可变目录，下载核对摘要后生成清单。先发布 test 的 `expert-store` 并验证加载、展示和召唤，再将同一清单发布 prod；只更新目标 key，不同步整个配置项目。发布后核对两环境版本、摘要和目录数量。回滚使用旧清单，不覆盖 CDN 文件或删除本地 Agent。Git 推送与 Overmind 下发是独立步骤。

## 5. 边界情况

| 场景 | 处理方式 |
|------|----------|
| 超限、超时、坏摘要、版本不符或悬空引用 | 整份目录拒绝更新，使用本环境有效缓存；无缓存提供重试 |
| 环境切换、主动空目录或回滚 | 缓存隔离，接受有效空目录和旧版本，不迁移已有 Agent |
| 重复召唤、专家停用或下架 | 防重复创建；召唤时启用已有实例；下架不删除实例与会话 |
| 用户自定义指令或头像 | 保留用户配置，旧指令可能影响新版示例的执行行为，不为验收强制重装 |
| 待展开 Agent 尚未加载或被删除 | 等依赖就绪再消费请求；目标删除则清除请求 |
| 用户手动收起会话分组 | 后续消息流、标题和后台任务不强制展开 |
| 技能、媒体服务或在线来源不可用 | 不自动安装或越权；明确能力限制、来源缺失或替代制作方式，不虚报成功 |
| 重算超时、输出损坏或用户并发保存 | 有界退出、保留原文件，不影响用户 Office 进程 |
| 安装版收到开发回跳参数 | 忽略开发参数，沿用安装版登录和目录规则 |

## 7. 验收标准与记录

### 7.1 验收标准

- 导航、整卡详情、独立召唤、三条示例、标签筛选、键盘操作和浅深主题可用，头像在小尺寸及加载失败时显示正确。
- 安装等待 OpenClaw 配置同步；复用保留旧实例配置；示例未发送前无模型调用；草稿保留、分组展开与手动收起行为正确。
- 目录覆盖缓存隔离、损坏、失败回退、并发加载、空目录和回滚；头像覆盖主/自建 Agent 排除、旧值识别、用户优先和可重复迁移。
- 原样发送默认首问，检查实际文件、结构、数值及核心交互；分别记录首次失败、修正和复测，不以配置静态检查替代真实模型执行。
- Windows XLSX 验证超时、格式、损坏输出、源文件保留与并发修改；开发登录用无授权码协议探针确认原实例激活、新进程退出。
- 相关单元测试、改动文件 ESLint、TypeScript 与 Electron 编译通过；通过 Electron 调试接口完成端侧验证，不占用系统键鼠。

### 7.2 本轮验收记录

2026-10-13 使用真实 Windows Electron、OpenClaw v2026.8.1 和已登录套餐模型验证当前前 12 位专家，另补充教学、电商，共 14 个专家场景；最终均为一次发送、零中途澄清并交付实际成品。结果包含调整后的复测，不表示首次尝试全部成功，也不代表全部 70 位专家或所有模型的稳定性。六个旧 Agent 的 14 项业务字段对照一致。

相关 8 个 Vitest 文件共 123 项、内容仓库 7 项、XLSX Python 5 项及编译/lint 已通过。仍有 Excel 端内图表配色偏浅的展示问题；PPT 使用可编辑形状适配预览，不等于原生图表已完整支持。跨盘 worktree 的 Word WASM 路径异常在正常合并目录验证恢复，未为此修改产品代码。

验收目录为 `2026-10-13.7`，含 70 位专家、15 类和 14 组场景；截至本轮记录，客户端和内容源功能分支已推送，test/prod 最近核验的发布版本仍为 `.5`。`expert-store` 正式下发按 4.7 执行。

逐项结果、截图与成品见[热门专家首问体验验收](https://confluence.inner.youdao.com/pages/viewpage.action?pageId=442406715)；需求排序与验收过程维护在内容仓库的 `research/`。本文保留设计与验收结论，不重复存放每轮操作记录。
