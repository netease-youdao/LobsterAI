# Markdown 实时编辑与 Codex 安装包核对

## 核对范围

用户提供的 `ChatGPT (1).dmg` 以只读方式挂载。包内 `ChatGPT.app` 的应用元数据标识为 Codex，`app.asar/package.json` 为 `openai-codex-electron`，版本 **26.825.51511**，构建号 **7377**。

结论来自这份安装包中前端文件预览入口、编辑组件及保存调用的静态核对。未安装或执行参考应用，不能据此保证其他版本、账号或远程功能开关具有相同能力。实现采用本项目已有的开源 CodeMirror 组件，没有复制参考包中的应用代码。

## 实际接入的能力

| 文件类型 | 该版本的文件预览入口 | 保存机制及判断 |
| --- | --- | --- |
| Markdown | 默认 Markdown 实时预览，支持源码模式，直接编辑同一份文本 | CodeMirror 的文档变更进入保存控制器；有延迟保存、草稿、串行写入、文件版本检查、外部修改处理及关闭时保存 |
| Word / DOCX | 文档查看与选区批注；正文编辑未启用 | `PopcornElectronDocumentPanel` 的 `isEditing` 默认 `false`，文件入口未传入开启值；另有 `docx-preview` 预览分支。未发现该入口接通正文修改的原文件自动写回 |
| PowerPoint / PPTX | 幻灯片查看、批注与评论；正文编辑未启用 | 底层组件包含文本框、幻灯片和讲者备注编辑能力，但文件入口未启用 `isEditing` 或传入正文 CRDT 更新；原生 PowerPoint 评论有单独保存链路，不能把评论保存视为正文实时编辑 |
| Excel / XLSX | 持久化编辑会话进入 `live` 后开启编辑；初始化失败等情况回退预览 | 工作簿组件接收 CRDT 更新、检查点与外部更新；更新先持久化，再导出并写回 XLSX，有重试与源文件冲突处理 |

可复核的包内入口（均位于 `webview/assets/`）：

- `text-file-editor-tab-content.electron-DxCiFr1w.js`：Markdown / source 模式、CodeMirror 配置、草稿与文本保存控制器。参考包的自动保存定时器为 3 秒。
- `artifact-tab-content.electron-NO4CTIoa.js`：各类文件的组件参数，以及 XLSX 的 `artifactDocuments.bindToExactFile`、CRDT 持久化、`isEditing` 与文件导出写回。
- `PopcornElectronDocumentPanel-ChQKWPXH.js`、`docx-preview-panel-BrTTkJpG.js`：DOCX 查看及批注入口。
- `PopcornElectronPresentationPanel-CvPOnRt2.js`：幻灯片组件的 `isEditing = false` 默认值；须结合调用方判断实际启用情况。
- `PopcornElectronWorkbookPanel-U7sH4v1k.js`：工作簿编辑交互及 CRDT 发布回调。

官方[文件预览说明](https://learn.chatgpt.com/zh-Hans/docs/artifacts-viewer)说明了侧栏预览和批注后请求修改的流程；它不等价于所有 Office 文件都能手动编辑并自动保存。

## 本次 Markdown 实现

- 文件型 Markdown 默认可直接输入。标题、强调、列表、引用、链接等在 CodeMirror 原始文本上添加显示装饰；当前编辑行显露 Markdown 标记。
- 表格、代码块、独立图片和块公式复用现有预览。点击复杂区块进入对应 Markdown 源码编辑。行内公式支持渲染。
- 使用现有面板的“源码 / 预览”切换，同一编辑器保留文本、选区和撤销历史。仍支持选中文字加入对话。
- 文本变更直接应用到原始文件内容，不进行 Markdown → 富文本 → Markdown 的整体序列化；保留未编辑的 YAML、注释、表格空格、BOM 和换行符。
- 每次输入同步备份本地草稿，停止输入 600 毫秒后自动保存；失焦、快捷键保存、切换文件和关闭时补充保存。磁盘保存失败时保留草稿，下次打开恢复。
- 主进程按真实文件路径串行处理写入，以 SHA-256 校验文件版本；写入同目录临时文件、同步后原子替换。保留普通文件权限，检查符号链接指向；外部修改冲突时暂停保存，用户选择版本后继续。
- 编辑范围为现有 UTF-8 `.md` / `.markdown` 文件，最大 2 MiB。超限、其他编码或无法读取时显示错误并保留预览，避免把截断内容写回文件。

本次没有新增 Word、PPT 或 Excel 的正文编辑入口。

## 2026-09-13 Review 修复

- 关闭保护改由文档注册表持有，切换文件或关闭预览后仍检查未保存且无法备份的修改；主进程退出确认接收这一状态，显示丢失修改的提示，并默认选择取消。确认框打开期间状态发生变化时也会重新确认，确认退出后停止接收主窗口输入。
- 面板工具栏复制优先读取编辑器的实时内容，覆盖等待保存、保存失败、冲突和清空文档等状态，不依赖上一次保存后同步到 Redux 的正文。
- 表格、独立图片和正文引用链接使用文档级引用定义；定义在文末或视口外时同样生效。采用完整的 Lezer 增量语法树及 Remark 片段缓存，避免每次输入都执行完整 Remark 解析；渲染上下文不写回源文件。
- 7 个测试文件、69 项针对性测试通过；所有改动的 TypeScript 文件通过 CI 同款 ESLint，`npm run build`、`npm run compile:electron` 和 `git diff --check` 通过。构建保留现有 Vite / lottie 提示。
- 在 Electron **43.5.0** 的隔离窗口中挂载真实 `ArtifactPanel`、Redux 和文件编辑 IPC，验证了自动保存、保存失败时工具栏复制最新内容、清空后复制空字符串、切换文件及关闭预览后保留关闭保护、主进程接收危险编辑状态及默认取消选项、恢复写入后解除保护，以及文末定义更新后正文／表格链接同步更新和引用图片实际加载。测试入口、记录和截图位于忽略目录 `.work/markdown-fix-qa/`。
- 实际工具栏切换源码／预览并执行撤销后，编辑器实例保持不变，正文及磁盘内容与编辑前逐字一致。引用解析专项测量中，接近 2 MiB、含 13,436 个引用的样本，每次编辑约 56–60 毫秒；该数据不包含完整编辑器渲染耗时。

## Excel 的独立接入方案

当前 `SheetRenderer` / `SheetFallbackRenderer` 是表格预览。展示数据只保留了值、部分样式、合并区域和列宽，不能用这个展示模型重新生成 XLSX 覆盖原文件。

建议按以下边界推进，先验证文件保真再开放自动保存：

1. **工作簿编辑层**：建立独立的 `EditableWorkbook`，支持单元格、公式、多工作表与撤销。工作簿原始模型和源文件字节独立于 React 展示数据保存；编辑引擎的选型须先验证现有格式的导入导出能力。
2. **持久化会话层**：`workbookDocument` 管理检查点、增量修改、失败重试与外部修改冲突。只有会话准备好后才启用输入；关闭视图不能销毁尚未保存的修改。多人协作不是单机编辑的前置条件，是否使用 CRDT 由引擎决定。
3. **主进程写回层**：新增共享 IPC 合约和受校验的二进制文件写入模块。导出成功且源文件版本一致后原子替换；导出失败继续保留原文件与编辑会话。
4. **独立验收**：用包含样式、合并区域、公式、日期、隐藏工作表、图表及外部链接的固定样本做往返测试，同时验证中文输入、撤销、关闭重开、写入失败和 Agent 同时改文件。对于不支持保真的特性，保持预览或提供另存副本，不能静默覆盖原件。

Word / PPT 可以独立借鉴“选区或对象批注 → Agent 修改 → 刷新预览”的流程；完整正文编辑属于另一条文档引擎接入工作，不应通过给预览 DOM 加 `contenteditable` 来实现。
