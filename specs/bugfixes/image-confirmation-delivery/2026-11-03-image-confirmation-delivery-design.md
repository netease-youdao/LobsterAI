# 图片额外确认与交付恢复设计文档

## 1. 概述

### 1.1 问题

- 同一轮额外生成图片时，用户尚未操作，确认请求就会在约 120 秒后结束，并被当作主动取消。用户切换会话或稍后返回时无法继续原确认。
- 用户主动取消后，模型可能重试工具，再次要求确认。
- 图片已经生成，但会话工作目录无法写入时，客户端反复重试保存，用户一直看不到可打开的图片。

### 1.2 根因

图片额外确认使用普通问答的等待期限，且把非肯定回答统一归为取消；图片工具也缺少独立确认等待预算和停止信号传递。主动取消没有约束本轮后续的额外生成尝试。

图片持久化只尝试会话工作目录，缺少针对本地目录写入失败的恢复路径。生成成功与本地交付成功是两个不同状态，反复生成不能解决目录不可写的问题。

## 2. 用户场景

1. 用户稍后确认额外生图，或切换会话、刷新界面后返回，可以继续处理仍有效的原确认。
2. 用户取消额外生成，本轮停止继续询问；用户主动发起下一轮请求时仍可正常生图。
3. 工作目录不可写，但应用数据目录可用时，图片保存到持久恢复目录，并在会话中显示提示和可打开的结果。

## 3. 功能需求

- 额外付费生成必须获得明确确认；超时、中断、账号变更与主动取消分别返回真实原因。
- 确认等待不消耗生成请求本身的提交预算；停止会话后不再提交尚未确认的图片请求。
- 报价过期时重新检查价格，价格变化需要再次确认。
- 恢复交付沿用原图片结果，不重新创建生成任务或重复计费。
- 恢复成功才显示图片已保存；失败不能伪装成成功。

## 4. 实现方案

### 4.1 可恢复的图片确认

复用现有媒体确认机制，增加图片类型。确认最多保留 30 分钟，120 秒仅作为报价刷新阈值。用户确认时重新读取过期报价，价格不变则继续，变化则重新询问。

展示简单按张计费的单价；复杂计费只展示模型提供的说明，不推测总额。通过报价信息指纹识别价格变化，避免说明文字相同而漏掉变化。

OpenClaw 图片工具传递停止信号，并增加独立确认等待预算。主进程在提交前检查停止状态。按本轮默认图片配置快照记录主动取消，后续额外尝试直接返回取消；新一轮使用新的快照，不继承取消状态。

### 4.2 本地保存失败恢复

优先写入会话工作目录。仅遇到明确的本地路径或写入错误时，复用已下载的图片字节，尝试保存到 `userData/generated-images/{sessionId}`。

保留唯一文件名和临时文件写入机制，只清理本次创建的临时文件。结果记录恢复标记及实际路径，界面显示恢复目录提示，图片仍可预览和打开。下载去重和原任务交付状态继续沿用现有机制。

## 5. 边界情况

| 场景 | 处理方式 |
| --- | --- |
| 长时间未确认 | 保留期结束后返回确认超时，不记为主动取消 |
| 确认期间价格变化 | 展示最新报价，要求再次确认 |
| 停止会话或账号切换 | 结束原确认，不继续提交 |
| 原目录与恢复目录均不可用 | 保留交付失败状态 |
| 网络下载或图片格式错误 | 不通过切换目录掩盖错误 |
| 已有图片或临时文件占用名称 | 避免覆盖已有图片，不删除其他写入者的临时文件 |
| 图片编辑流程 | 暂不启用目录回退，保持编辑版本与本地合成约定 |

本次目录恢复针对本地写入失败，不代表其他下载或交付失败原因也已解决。

## 6. 验收标准

- 额外确认等待超过 120 秒仍可操作，界面刷新和切换会话不会丢失有效请求。
- 确认后生成真实图片；取消后不增加生成任务，也不在本轮重复询问。
- 同一会话的新一轮请求不受上一轮取消影响。
- 目录写入失败时可交付到恢复目录，图片可打开且与原结果一致，不增加生成任务或计费。
- 覆盖报价变化、停止信号、确认原因、两处目录失败、临时文件保护和恢复提示的回归测试。
