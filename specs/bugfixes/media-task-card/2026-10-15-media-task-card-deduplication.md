# 生成任务状态卡片重复展示修复

## 1. 概述

### 1.1 问题

同一个图片或视频任务，在创建后查询状态，会出现多张内容相同的完整状态卡片。取消后，多张卡片都显示「已取消」和退款说明，容易被误解为重复生成或重复计费。

### 1.2 根因

完整卡片绑定在每次工具调用上。创建调用和状态查询调用都带有任务信息，因此各自生成卡片；后台状态更新又同步到这些调用，形成相同终态的重复展示。

## 2. 用户场景

- 创建任务后查询一次或多次，只显示一张完整状态卡片。
- 后续轮次再次查询同一任务，保留可展开的调用记录，继续更新原卡片。
- 同一会话创建两个不同任务，各保留自己的卡片和状态。
- 重新打开历史会话，取消、失败、超时、成功和退款说明仍正确展示。

## 3. 功能需求

1. 在当前会话已加载的消息中，按完整任务 ID 确定唯一卡片位置。
2. 保留全部调用及原始返回内容；重复调用默认折叠为「生成任务 … 的调用记录」。
3. 卡片聚合该任务的状态。较旧的处理中状态不能覆盖已结束状态，较旧的下载重试状态不能覆盖已保存状态。
4. 保持历史任务展示兼容；旧式轮询继续使用原有合并逻辑。

## 4. 实现方案

- `mediaTaskPresentation.ts` 构建会话级展示映射。首次出现的有效任务调用承载完整卡片，其余调用保留详情入口。
- 主会话、通用会话视图及定时任务记录共享同一映射规则。
- `AssistantTurnBlock` 将映射传给调用组件；独立使用时在当前轮次内构建映射。
- `ToolCallGroup` 仅在指定位置渲染完整卡片。其它调用使用折叠详情，不再另外显示媒体等待提示。
- 新任务的查询记录不再进入旧式轮询汇总，避免汇总行与完整卡片重复表达任务状态。
- 同步补充中英文文案。本次修改限于展示和对应测试，不改动任务数据。

## 5. 边界情况

| 场景 | 处理 |
|---|---|
| 任务 ID 以数字或字符串保存 | 统一为字符串进行精确匹配 |
| 两个 ID 仅前缀相同 | 不合并 |
| 已加载历史中缺少创建调用 | 首个有任务信息的查询承载卡片 |
| 加载更早历史后找回创建调用 | 重新计算唯一位置，仍保留一张卡片 |
| 查询尚未返回 | 已知任务的查询仅显示调用记录 |
| 多会话或多个任务 | 映射隔离，不复用全局缓存 |
| 无有效任务信息或旧式记录 | 保持原展示方式 |
| 简短完成或取消通知 | 继续保留，便于过程折叠时获知结果 |
