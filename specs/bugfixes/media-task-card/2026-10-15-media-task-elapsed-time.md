# 媒体任务等待计时修复

## 1. 问题与根因

视频确认窗口停留一段时间后，刚点击确认，任务卡片就显示已经等待几十秒。卡片使用工具调用开始时间作为计时起点，将用户阅读和确认的时间计入生成等待。

## 2. 用户场景

用户发起视频生成，在确认窗口停留一分钟后点击确认。任务受理后，卡片应从接近零秒开始计时；后续查询、切换会话或重新加载页面，继续显示同一任务已经等待的时间。

## 3. 实现方案

- 在现有任务结果中保留创建时间及其时区信息，供卡片统一确定计时起点。
- 优先按任务创建时间计时。日期缺少时区时，使用同一任务已有的明确时区信息，不按用户电脑时区解释。
- 历史记录缺少有效时间时，使用首次收到该任务结果的时间，不再回退到工具调用开始时间。
- 后续查询共享原有计时起点；获得有效任务时间后，替换历史回退值。
- 没有可信时间时暂不显示秒数。任务结束后继续隐藏等待计时，保留结果及退款等状态。

改动集中在 `mediaTaskPresentation.ts`、`MediaTaskCard.tsx` 及主进程任务结果整理处。沿用现有文案和卡片去重规则，不改变任务期限、轮询策略、取消或扣费行为。

## 4. 边界情况

| 场景 | 行为 |
|---|---|
| 确认前长时间停留 | 不计入生成等待 |
| 用户电脑时区不同 | 使用任务明确的时区，保持相同起点 |
| 历史记录时间缺失、无效或时区未知 | 从首次任务结果时间计时 |
| 尚无有效任务时间或结果时间 | 隐藏秒数，保留任务状态 |
| 后续查询及页面重新加载 | 保持原起点，不从零重新累计 |
| 先加载查询记录，再加载创建记录 | 使用同一任务时间，仍只显示一张卡片 |

## 5. 验收

自动化覆盖长时间确认、时区换算、历史回退、跨查询与历史恢复、无可信时间不显示秒数，以及原有终态和单卡片展示。相关 Vitest 30 项通过；修改文件 ESLint、Electron 编译及 TypeScript 检查通过。

2026-10-15 使用独立 Electron 实例完成真实视频生成验收，通过调试连接操作会话和确认按钮，不占用系统键鼠。

| 场景 | 结果 |
|---|---|
| 确认窗口停留约 89 秒 | 点击确认后卡片显示「已等待 0 秒」 |
| 持续生成与状态查询 | 卡片增长到 36 秒，仍只有一张任务卡片 |
| 生成中重新加载页面 | 继续显示 40 秒，计时起点没有重置 |
| 生成完成 | 约 71 秒后完成，保存视频，卡片停止显示等待秒数 |
