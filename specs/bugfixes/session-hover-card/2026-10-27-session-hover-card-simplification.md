# 会话悬浮卡内容与样式简化

日期：2026-10-27。状态：**客户端已实施；相关测试、类型检查、严格 lint 和真实组件浏览器 QA 通过。未打包发布。**

适用范围：LobsterAI 桌面侧栏的会话悬浮卡。本次仅调整摘要展示和悬浮定位，不改变会话归属、任务执行、同步状态本身或完整详情的数据。

## 1. 目标与现状

简化前的会话悬浮卡复用 `OwnershipDetailContent` 的 compact 分支，混合展示当前账号、空间、同步状态、Agent、计算机 hostname、任务状态和更新时间。大量稳定或后台信息占用悬浮摘要，任务失败与同步失败也容易在视觉上混淆。

本次将默认内容收敛为三个信息行：**标题、所在电脑与空间、更新时间与可选任务状态**。状态紧跟更新时间自然排列，标题独占整行宽度，避免标题右侧形成孤立状态列。更多归属、设备和同步信息继续在现有完整详情入口查看，不新增点击层级或请求协议。

“默认三行”指三个内容分组；长标题、长企业空间名称及大字号可以使实际高度增加，不能靠固定高度裁掉信息。

## 2. 内容规则

| 位置 | 展示内容 | 规则 |
| --- | --- | --- |
| 第 1 行 | 会话标题 | 独占整行宽度，最多两行，保留完整标题提示；状态不再占用标题宽度 |
| 第 2 行 | 电脑图标 + “本地电脑” + scope 标签 | 使用通用本地电脑文案，不显示机器 hostname；它表示此会话在当前桌面可见，不宣称是原始执行设备。现有 `deviceName` 为当前主机，不能据此推导远端来源。scope 来自已授权详情数据，企业空间保留真实名称 |
| 第 3 行 | 更新时间图标 + “更新于 …” + 可选任务状态 | 状态紧跟时间自然排列，不使用独立底色或右对齐；时间精确到分钟，当年省略年份。未提供 `updatedAt` 时省略时间图标及文案，有状态则保留状态；时间和状态均无时省略整行，不伪造当前时间 |

### 2.1 更新时间后的任务状态

| 任务状态 | 是否显示 | 含义 |
| --- | --- | --- |
| `running` | 显示运行状态 | 当前任务运行中 |
| `waiting_approval` | 显示审批状态 | 当前任务等待审批 |
| `error` | 显示任务失败状态 | 任务执行失败，文案明确为任务失败 |
| 其他状态或未提供 | 不显示状态 | 不为完成、空闲等常态增加摘要噪声 |

状态依据任务 `status`，不能依据 `syncState` 推导。同步失败不能显示成任务失败，也不能使正常任务出现失败状态。文字统一使用 `text-foreground` 保证小字号可读性，状态色使用 `bg-primary` / `bg-warning` / `bg-destructive` 的装饰圆点；不能只用颜色表示状态。文案分别为“执行中 / 待审批 / 任务失败”。状态与时间统一使用 `text-xs` 普通字重，移除原 badge 的底色、圆角、内边距及独立加粗。末行用 `flex-wrap`，时间与状态间距 8px、换行间距 4px；空间不足时状态整体自然换行，不缩小字体、不增加固定空白，也不独立右对齐。

### 2.2 空间与匿名会话

- 已关联个人会话：显示其个人 scope 标签，不再重复“当前账号”或账号姓名。
- 已关联企业会话：scope 标签保留实际企业/空间名称，不能统一替换为“企业”而丢失区分。
- 匿名会话：身份标签仅为“未关联账号”，不追加“当前账号”“个人空间”“本机可见”等说明。电脑位置仍按第 2 行使用“本地电脑”。
- 不通过标签变化推断或修改归属；缺少 scope 时省略标签，不回填个人空间或当前企业。完整详情仍承担归属说明。

### 2.3 从会话 hover 移除的内容

以下内容全部从本次会话悬浮摘要移除：同步中、同步失败、等待服务、仅本地等所有同步状态；当前账号或账号名称；Agent 名称；计算机 hostname。也不在该卡的嵌套 `title`、辅助提示或图标说明中把它们重新拼回。

现有完整详情继续保留所属账号/空间、Agent、实际设备名称、任务状态、同步情况、关联时间等字段。摘要变短不意味着清除数据、隐藏完整详情入口或修改权限检查。

## 3. 主题与排版规范

| 元素 | 使用规范 | 默认字号下的解释 |
| --- | --- | --- |
| 标题 | `text-sm font-medium text-foreground` | 15px / 21px，随全局 UI 字号变化 |
| 辅助行和标签 | `text-xs text-secondary`，必要标签使用主题前景色 | 13px / 17px，随全局 UI 字号变化；不额外用固定 `leading-5` 覆盖主题行高 |
| 卡片内边距 | `p-3` | 12px |
| 标题区与辅助信息区间距 | `space-y-2` | 8px |
| 两个辅助信息行间距 | `gap-1` | 4px |
| 同行图标与文字间距 | `gap-1.5` | 6px |
| 时间与状态 / 末行换行 | `gap-x-2 gap-y-1` | 横向 8px，换行 4px |
| 状态圆点与文案 | `gap-1`，圆点 `0.4em` | 间距 4px；圆点随字号缩放，不使用底色块 |
| 表面、边框、正文 | `bg-surface`、`border-border`、`text-foreground` | 遵循当前浅色/深色主题 |
| 圆角与阴影 | `rounded-xl shadow-popover` | 使用现有弹出层视觉规范 |
| 图标 | Heroicons | 电脑、时间及必要状态使用现有图标体系，不用 emoji 代替 |

使用现有字号 token，而不是在组件中硬编码 15px/13px 或独立字号缩放。状态色使用现有语义角色，避免为本卡新增脱离主题的任意颜色。图标作为文字的补充，装饰性图标对辅助技术隐藏，避免重复朗读。

## 4. 定位与交互

简化内容后，不再依赖旧详情卡的大高度估算来决定悬浮位置。定位需考虑实际渲染高度、当前字号、标题换行、企业 scope 长度和视口边界；实现用 `useLayoutEffect` 首次测量，测量前保持隐藏以避免跳位；`ResizeObserver` 观察卡片及触发元素，尺寸变化时重读锚点坐标。定位算法保持 300px 常规宽度、8px 视口边距，传入真实高度。

要求如下：

1. 卡片在触发会话旁合理放置；靠近窗口右侧、底部或窄窗口时调整位置并保持可见。
2. 实际内容较短时，不因旧的固定高度假设被无故上移；内容变高时也不能溢出视口或挡住无法访问的内容。
3. 首次展示和高度更新避免明显位置跳动；字号变化后的尺寸应与定位一致。
4. 保留现有 hover/focus 触发、离开延迟、Escape 关闭、外部滚动/窗口调整/失焦时关闭；卡片内部滚动不关闭、完整详情打开时关闭 hover 等交互。
5. 仅在已有可访问详情已加载时展示；不因新布局绕过禁用态或归属权限，不为每次鼠标移动新增重复数据请求。
6. 更新卡内内容时，不能让上一会话或上一账号的异步详情残留在新的触发位置。

卡片最大高度为视口高度减 16px，与当前 top 无关，超高内容内部滚动，避免“裁剪高度参与测量”造成的定位反馈。实际高度不固定。

## 5. 实施范围与兼容

本方案整体涉及 `OwnershipDetailContent.tsx` 的任务 compact 分支、`OwnershipHoverCard.tsx` 和 `i18n.ts`。本轮状态下移仅修改 `OwnershipDetailContent.tsx` 及此 spec，沿用已完成的定位与文案，不扩展接口或数据逻辑。定位工具 `position.ts` 未修改；删除本次重构后不再使用的旧摘要文案。完整详情与 Agent 详情不因本次会话摘要要求被删减，共享样式调整应单独核对其影响。

无服务端 HTTP API、认证协议、MySQL DDL、SQLite schema 或手机源码改动。沿用现有 `OwnershipDetail` 字段，不新增后台查询、同步轮询或数据迁移；移除的是摘要展示，不能停止原有同步行为。现有 main/preload/renderer IPC 结构保持不变。

本次没有服务端部署依赖。回退仅涉及客户端展示实现，不通过删除会话、重置账号或更改归属来回退。
