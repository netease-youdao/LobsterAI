# 网关重启后恢复桌面 IM 消息同步

分支：`fix/openclaw-qq-shutdown-lifecycle`。测试目录：`D:\github\LobsterAI`。

## 本次问题与证据

2026-09-09 本机回验中，QQ 能收到回复，但退出登录后 LobsterAI 不再补入消息：

- 14:00:37，退出登录触发 `media-entitlement-changed` 配置同步及网关重启，桌面主动断开网关客户端。
- 14:01:30，切换自定义模型重新建立客户端，并成功订阅 `sessions.changed`。
- 14:01:57、14:02:12、14:03:25，网关完成回复，桌面收到会话开始／完成状态，却始终读取到 6 条本地消息。
- 同一个 QQ 会话在 OpenClaw 的状态库中存在这些新回复；LobsterAI 的最后一条消息仍为 14:00:22。

原因是主动断开客户端时清除了消息同步定时器，而普通 RPC 的连接就绪路径只恢复了连接和事件订阅。`sessions.changed` 触发的补同步也要求定时器存在，因此只能更新运行状态。已有客户端的 `connectGatewayIfNeeded()` 提前返回，不能修复这一状态。

本次三次网关停止均记录为 `clean_stop`；此前 QQ 插件退出处理补丁已生效。

## 修复

- 配置驱动的网关重启成功后，主动连接桌面客户端；退出应用或数据恢复期间不重新连接。
- 当前客户端握手成功后恢复频道发现与历史同步，覆盖切模型、普通 RPC 和专用重连入口。
- 已有客户端也检查并恢复同步；重复调用复用定时器。
- 沿用现有历史对齐、去重及界面刷新机制，不修改账号认证、QQ 凭据或会话映射。

## 用户侧回验

使用当前目录的本地改动启动 `npm run electron:dev`。此前 QQ 插件运行时补丁仍需存在；本次同步修复只需重新编译 Electron，无需重新构建 OpenClaw。

1. 打开 QQ 对应的 LobsterAI 会话，在手机 QQ 发送：`请只回复 IM-SYNC-BASE-01，不要调用工具。` 确认两端都出现本次消息与回复。
2. 退出登录，选择一个已配置且可用的自定义模型。待网关就绪后，仅在手机 QQ 发送：`请只回复 IM-SYNC-LOGOUT-02，不要调用工具。`
3. 保持桌面会话打开，确认新增的用户消息与回复自动出现，且之前已生成但未同步的回复也补入。正常事件可触发快速补同步；若事件遗漏，允许等待一个 10 秒轮询周期及请求耗时。
4. 重新登录并切回套餐模型，再从手机 QQ 发送：`请只回复 IM-SYNC-LOGIN-03，不要调用工具。` 核对两端内容及 Agent 归属，确认没有重复消息。
5. 重复退出／登录一轮，每次使用新编号。全过程避免通过 PC 发送消息、开关 QQ 实例或手动重启网关来恢复同步，这些操作可能掩盖原缺陷。

模型不可用期间仍允许生成失败；应分别记录“QQ 是否收到回复”和“已生成的回复是否同步到桌面”。首次失败时记录时间、编号与两端截图，并保留主进程和网关日志。
