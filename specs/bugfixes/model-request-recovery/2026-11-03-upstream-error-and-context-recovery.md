# 模型请求错误提示与上下文恢复

## 1. 概述

### 1.1 问题

长输入被模型拒绝时，用户只看到笼统的服务端错误；原样重试仍失败。
恢复上游错误原因后，自动压缩可能也超出模型窗口，原生压缩器还会重复提交同一份摘要输入。

### 1.2 根因

服务端路由耗尽时丢失了上游请求拒绝的语义，OpenClaw 无法识别上下文超限。
原生摘要的重试条件又把明确的上下文超限视作可重试错误；本地 token 估算与供应商
计数存在差异时，完全相同的请求不会因重试而缩短。

## 2. 用户场景

输入超过模型窗口时，客户端应尝试已有的上下文恢复。恢复仍失败时，明确说明原因，
保留会话并建议缩短输入或新建会话分批发送。正常对话继续生成回复。

## 3. 功能需求

- 获取服务端保留的上游请求错误，识别上下文超限。
- 避免重复提交已经明确超限的摘要输入。
- 恢复失败保留原会话，用中英文提示说明下一步操作。

## 4. 实现方案

现有服务端能力列表追加 `upstream-error-details-v1`，复用 token proxy 和 SSE 解析。
共享错误分类识别上游窗口错误及原生“压缩失败且保留会话”的提示，主进程和渲染层补齐翻译。

OpenClaw v2026.8.1 的版本补丁在 `generateSummary` 重试判断中排除明确的上下文超限。
此判断位于原生 compaction 内，没有适合的端侧 hook；发布时需要重建运行时。
更小输入的 fallback、瞬态错误重试和取消处理继续原逻辑。

服务端协议细节见 `docs/server-integration/2026-11-03-upstream-error-recovery.md`。

## 5. 边界情况

| 场景 | 行为 |
| --- | --- |
| 摘要输入仍超出窗口 | 停止原样重试，保留会话并提示缩短输入 |
| 可恢复的瞬态摘要错误 | 保留原有重试 |
| 用户取消 | 立即结束等待和重试 |
| 连接尚未支持新能力的 server | 继续原协议行为 |
| 不支持的输出格式、缺失推理历史 | 保留真实拒绝原因，不自动降级格式或伪造推理内容 |

## 6. 验收标准

- 上下文超限能够触发已有恢复；明确超限的相同摘要输入不重复发送。
- 恢复失败后原始会话完整，提示可理解且包含下一步操作。
- 正常生成、瞬态重试、用户取消及旧协议兼容行为保持有效。
