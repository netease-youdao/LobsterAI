# OpenClaw 压缩摘要格式冲突与章节截断修复设计文档

## 1. 概述

### 1.1 问题

长会话达到上下文压缩阈值后，OpenClaw 会生成摘要，并检查其是否保留必要章节、
待处理请求和精确标识。最终摘要未通过检查时，压缩返回 `guard_blocked`，
用户可能看到上下文过大且自动压缩无法恢复的提示。

排查基于 LobsterAI `2026.9.14` 固定的 OpenClaw `v2026.8.1`。反馈与开启 memory
flush 的时间相关，但故障回合因本周期已执行过记忆保存而跳过 flush，自动压缩仍独立
执行。现有证据不能将失败直接归因于该开关。

### 1.2 根因

已确认两个独立缺陷：

1. **生成模板冲突。** 核心摘要提示词要求 `Goal`、`Progress` 等章节；safeguard
   又通过 `Additional focus` 追加另一套精确标题。当前回合前缀摘要也将专用格式追加
   到默认模板之后。模型可能同时输出两组标题。
2. **章节解析与审核约定不一致。** 质量审核允许五个必需章节以任意顺序出现，
   `parseRequiredSummarySectionContents()` 却只接受固定顺序。完整但换序的摘要
   因此无法建立保护计划，退回普通尾部截断，可能丢失章节和标识。

上游 [PR #138850](https://github.com/openclaw/openclaw/pull/138850) 于 2026-09-05
合并模板修复，`v2026.9.4` 已包含，当前固定版本未包含。2026-09-15 检查的
`v2026.9.4` 质量解析器仍存在固定顺序限制，因此需要分别处理两个缺陷。

原会话的完整消息与模型最终摘要无法恢复。已确认的故障结果是最终审核报告
`missing_section,missing_identifiers`；不能据此断言上述缺陷就是该次失败的全部原因。

## 2. 用户场景

| 场景 | 预期行为 |
| --- | --- |
| 长会话生成、更新或合并历史摘要 | 每次请求采用 safeguard 指定的唯一主模板。 |
| 压缩当前回合前缀，保留后续消息 | 使用前缀专用模板，保留后续工作所需背景。 |
| 完整摘要的必需章节顺序变化 | 继续保护必要章节和标识，按预算生成最终摘要。 |
| 其他调用方没有指定主模板 | 继续使用核心默认摘要格式。 |

## 3. 功能需求

- FR-1：区分主模板与补充要求，在首次生成、已有摘要更新、分块合并及降级路径中
  传递调用方选择的格式。
- FR-2：允许完整必需章节换序；缺失或重复章节不能建立保护计划。
- FR-3：保留现有质量审核和最终 16000 个 UTF-16 code units 的预算，正文与后缀
  继续共享该预算。
- FR-4：采用当前固定版本的补丁机制，提供应用结果强校验、补丁清单登记和回归覆盖。

## 4. 实现方案

### 4.1 回迁唯一主模板接口

新增 `openclaw-compaction-summary-format.patch`，回迁上游 PR 的通用模板改动。
补丁不包含该 PR 中本地模型能力及其他上下文预算相关改动。

核心 `generateSummary()` 增加可选 `summaryPrompt` 参数，沿核心导出、会话包装层、
分块压缩及 safeguard 调用链传递：

| 调用类型 | 主模板 |
| --- | --- |
| 历史摘要、被裁剪历史摘要 | `Decisions`、`Open TODOs`、`Constraints/Rules`、`Pending user asks`、`Exact identifiers` |
| 当前回合前缀摘要 | `Original Request`、`Early Progress`、`Context for Suffix` |
| 未指定 `summaryPrompt` | 既有默认生成或更新模板 |

自定义主模板替换默认模板。精确标识保留规则、操作方补充要求、合并要求和质量检查
反馈继续作为附加信息传递。更新已有摘要时保留此前摘要和中性的更新说明，不再注入
默认模板的章节要求。

前缀摘要采用上游专用输出预算：预留 token 的 50%；历史摘要仍为 80%，两者均受
模型最大输出 token 限制。这与最终摘要的字符预算属于不同阶段。

### 4.2 按标题识别必需章节

新增 `openclaw-compaction-summary-section-order.patch`：

1. 将匹配到的标题映射到必需章节索引，不依赖前一个章节的位置。
2. 记录已出现的章节，发现重复即返回无保护计划。
3. 遍历结束后确认五个章节齐全，将各章节正文交给既有保护预算逻辑。

保护计划的预算分配与事实保留规则保持原有实现。新增回归遍历全部 120 种章节排列，
同时施加超长正文和后缀压力，检查最终长度、标识保留与质量审核结果。

### 4.3 集成与涉及文件

该行为由 OpenClaw 核心生成、解析和截断逻辑负责，LobsterAI 配置边界无法直接替换
核心默认模板，因此使用版本补丁。

| 文件 | 职责 |
| --- | --- |
| `scripts/patches/v2026.8.1/openclaw-compaction-summary-format.patch` | 主模板接口、调用链及格式传播回归。 |
| `scripts/patches/v2026.8.1/openclaw-compaction-summary-section-order.patch` | 章节顺序容错及预算回归。 |
| `scripts/apply-openclaw-patches.cjs` | 验证接口、调用点和回归确实存在，拒绝未应用的源码。 |
| `src/main/libs/openclawPatches/v20260801UpgradeDecisions.test.ts` | 将两项补丁登记到审核后的版本补丁集合。 |

两项补丁可以依次应用。后续升级固定版本时，分别核对上游是否包含等价实现，再移除
对应补丁。发布前需要重建并打包 OpenClaw runtime；增加补丁文件不会更新已构建的运行时。

## 5. 边界情况

| 场景 | 处理与限制 |
| --- | --- |
| 模型漏写、改名或重复必需章节 | 不将其视为完整可保护摘要，继续由现有审核与纠正生成处理。 |
| 必须保留的事实超过总预算 | 保持现有失败处理，不通过扩大预算或放宽审核掩盖问题。 |
| 完整章节换序 | 建立保护计划，避免仅因顺序变化退回普通尾部截断。 |
| 模型混用格式 | 唯一主模板减少生成歧义，但不能保证模型永远遵守格式。 |
| memory flush 开关变化 | 不改变开关语义；关闭开关不能替代对自动压缩的修复。 |
| 原会话完整正文缺失 | 使用片段与合成历史验证机制，不宣称完成原会话重放。 |

### 6.2 真实模型对照

使用 `deepseek-flash`、`thinking=enabled`、`reasoning_effort=high`，针对两个历史
分块、合并、前缀摘要及已有摘要更新，分别运行原版与模板修复版，共 10 次真实调用。
输入由恢复的请求片段与明确标记的合成历史组成，分块输入约 6.4 万 token，前缀约
7.5 万 token；已有摘要更新的两组调用使用同一份此前生成的摘要。

| 本轮观察 | 原版 | 模板修复版 |
| --- | ---: | ---: |
| 调用次数 | 5 | 5 |
| 同时输出默认模板与调用方模板 | 3 | 0 |

所有调用均正常结束。两组历史合并摘要加前缀经预算处理后均小于 16000 字符，最终
审核通过。该小样本验证了模板歧义及修复效果，没有复现原会话完整的 `guard_blocked`
失败，也不能作为稳定失败概率或原会话已恢复的证据。
