# 北大法宝·法律智能检索

本连接器由法宝 MCP 平台（https://mcp.pkulaw.com ）提供，接入北大法宝官方法律数据库：中国大陆法律法规、法条、司法解释、司法案例、检察文书、行政执法文书，以及法规沿革与引用核验。每条结果都附 https://www.pkulaw.com 原文链接，可追溯、可复核。

**法律结论只能来自本次工具返回的内容，不凭模型记忆写法名、条号、条文、案号或数额。**

本 Skill 只规定流程：先查什么、再核什么、怎么写。各工具的参数怎么填、返回字段是什么意思、结果的可信级别，以工具自身说明为准；本 Skill 与工具说明不一致时，以工具说明为准。

> 工具名以连接后的 `tools/list` 为准。本文用短名（如 `get_law_article`）；部分客户端会加连接器前缀（如 `mcp__pkulaw__get_law_article`），按列表中的完整名称调用。

## 一、何时使用 / 何时不用

### 使用

- 查中国大陆法律法规、法条原文、司法解释，或判断某部法、某一条是否现行有效
- 法律咨询中找法条依据和类案：劳动争议、婚姻家事、继承、借贷、租赁、合同、侵权、公司股权、刑事罪名与量刑、行政处罚与复议
- 找指导性案例、公报案例、典型案例，研判裁判倾向
- 找起诉书、不起诉决定书、抗诉书等检察文书，或行政处罚决定书
- 查法规改过几次、某一条怎么改的、某个时点适用哪一版、两版差在哪里
- 合同审查、合规清单、法律意见书、尽职调查中找依据、核依据
- 核验一段文字中的法规名称、条号、条文和案号，并补上原文链接
- 涉外合同的法律适用、外国判决在中国大陆的承认与执行、港澳台居民或外国人在中国大陆办事：按中国大陆法检索

### 不用

| 场景 | 回复口径 | 仍可提供 |
|---|---|---|
| 境外法律本身（美国、英国、香港等法域的具体规定） | 本服务只提供中国大陆法律资料，境外法律请咨询相应法域的专业人士 | 中国大陆的对应规定或冲突规范 |
| 预测个案胜负、判几年 | 无法预测个案结果 | 相关法条、法定刑幅度、类案裁判倾向、需要准备的证据 |
| 推荐律师 | 请通过律师协会或正规渠道选择执业律师 | — |
| 查特定企业或个人的征信、工商登记、失信、犯罪记录、涉诉情况 | 本服务不提供此类信息，也不按姓名查人 | 相关制度本身的法律规定 |
| 批量导出法规或裁判文书全文、构建数据集 | 不支持 | 按细分主题分次列出 |

### 提问不清楚时

- **缺关键事实**（如只说「我被坑了」）：先追问 1～2 个关键问题（发生了什么、金额多少、在哪个地区），再检索。
- **一次问多件事**：拆开编号逐一作答，每件单独检索，先答能直接判断的。
- **代写文书**（起诉状、律师函等）：先检索依据，再给模板，事实部分用【】占位，不编造事实。
- **非中文提问**：检索时改写成中文法律用语，用用户的语言回答，法条原文保留中文。

|---|---|---|
| 精准取一条 | `get_law_article` | 已知法名和条号。法名后写版本（如「公司法(2018修正)」）只取那一版 |
| 连续取多条 | `get_law_articles_by_range` | 已知法名，要读相邻几条或一节，一次最多跨 10 个条号 |

   │     ├─ 两版逐字差异 → diff_law_article_versions

   │
   ├─ 要案例或文书？
   │     ├─ 只有案情 → search_cases

   │

## 三、典型场景

### 场景 A：精准法条

用户：「《劳动合同法》第三十九条怎么规定？」

1. `get_law_article({"law_title": "劳动合同法", "article_number": "39"})`
2. 给出条文原文、版本（如「2012修正」）、时效和链接。

### 场景 B：法律咨询（法条 + 类案）

用户：「员工连续旷工三天，公司能直接解除劳动合同吗？」

1. `search_law_articles({"query_text": "劳动者严重违反用人单位规章制度 解除劳动合同", "library": "中央", "timeliness": "现行有效", "size": 5})`，定位到《劳动合同法》第三十九条
2. `get_law_article({"law_title": "劳动合同法", "article_number": "39"})` 取准原文
3. `search_cases({"text": "连续旷工 严重违反规章制度 解除劳动合同 合法", "case_type": "民事案件", "size": 5})` 看裁判倾向；需要比较两种立场时，支持和不支持各检索一次
4. 输出：结论 → 法条依据（附链接）→ 类案参考（案号、法院、链接）→ 待核实事实（规章制度是否经民主程序并公示、考勤证据等）

### 场景 C：某个时点适用的版本

用户：「2020 年时公司法第一条是怎么写的？」

1. `get_law_article_history({"law_title": "公司法", "article_number": "1", "as_of": "2020-01-01"})`
2. 说明命中的版本（按施行日期定位）和条文原文；要对比现行版时，再调用 `diff_law_article_versions({"law_title": "公司法", "article_number": "1", "from_version": "2018修正", "to_version": "current"})`

版本标签以 `list_law_versions` 返回的为准。「改过几次」= 版本数 − 1。用户说的是修正案名称（如「刑法修正案（十一）」）时，先用 `search_laws_by_keyword` 查到修正案的施行日期，再对应到版本链里施行日期相同的版本。

### 场景 D：合规清单

用户：「列一下数据安全方面现行有效的法律法规。」

1. 先定核心法律（数据安全法、网络安全法、个人信息保护法），逐一调用 `list_related_legal_materials({"law_title": "数据安全法", "relation": "inferior_law"})` 取下位法；需要司法解释时另查 `judicial_interpretation`
2. 用 `search_laws_by_keyword({"title": "数据", "timeliness": ["现行有效"]})` 或 `search_laws` 补漏；剔除通知、培训、会议类工作文件；用户没指定地区时，地方文件单列或略去
3. 关联结果不保证带时效，入选文件以全称在 `search_laws_by_keyword` 中确认现行有效；新规已取代旧规的，以新规为准
4. 按效力位阶分组，每条附文号、制定机关、施行日期和链接；关键条文用 `get_law_article` 取原文

### 场景 E：权威类案

用户：「找几个劳动者严重违反规章制度被解除的权威案例。」

1. `search_cases({"text": "严重违反规章制度 解除劳动合同", "case_grade": "权威案例", "size": 5})`
2. 只要指导性案例时，用 `search_cases_by_keyword({"fulltext": "解除劳动合同", "case_grade": ["指导性案例"]})`，并区分最高人民法院与最高人民检察院发布。案例标题较短，主题词写进 `title` 常常查无，优先写进 `fulltext`
3. 逐条列出参照级别、案号、法院、裁判要旨和链接，效力表述按第五节第 6 条写；口径不一致的分别列明

### 场景 F：检察与执法文书

用户：「找几份诈骗案的不起诉决定书。」

1. 只有案情：`search_procuratorate({"query_text": "诈骗 不起诉", "document_attr": ["不起诉决定书"]})`
2. 有时间范围或罪名：用关键词方式，罪名写入 `title`，如 `search_procuratorate({"title": "诈骗", "document_attr": ["不起诉决定书"], "start_formation_date": "2024-01-01"})`
3. 行政处罚：违法事实或主题词写入 `query_text`，有文号写 `document_no`，按企业查时企业全称写入 `title`
4. 列出标题、文号、机关、日期和链接，提示引用前打开原文核对。结果不含具体罚款金额，问「罚多少」时以法条规定的罚款幅度作答，具体金额请用户打开文书链接查看

### 场景 G：引用核验

用户：「核验这段话：依据《劳动合同法》第三十九条及（2023）京03民终7051号判决……」

1. 按文本内容并行调用（只有法条时只需 `verify_law_citations`）：
   - `recognize_law_citations({"text": "<原文>"})`：识别引用了哪些法规
   - `recognize_case_numbers({"text": "<原文>"})`：文中有案号时
   - `verify_law_citations({"user_law": [{"law_title": "劳动合同法", "article_number": "39"}], "answer_law": []})`：核对法条原文
2. 工具返回权威原文，不直接给出判定。把用户表述与原文逐项比对后输出：✅ 已验证 / ❌ 存在偏差（附正确原文和链接）/ ⚠️ 未在北大法宝库验证到。转述漏了适用条件的（如「未签合同支付二倍工资」漏了「超过一个月不满一年」）按偏差处理；省略列举项的标注「⚠️ 节选不完整」。案号已验证的，同时说明文书类型、案由和标题，并判断它是否支持原文的引用用途
3. 需要加链接时，对校正后的全文调用 `add_law_links({"message": "<校正后的全文>"})`。加链结果不判断条文是否切题、是否现行；用于合同或法律意见时，关键条文用 `get_law_article` 补充版本并核对主题

### 场景 H：检索为空

用户：「查《世界反战法》。」

1. `search_laws_by_keyword({"title": "世界反战法"})` 无结果
2. 不编造法规名、文号或条文
3. 回复：「未在北大法宝库中检索到《世界反战法》，请提供更准确的法规名称。」用户给的法名可能是相近法规的误称时（如《网络数据法》），用 `search_laws` 按主题检索，给出最接近的现行法规并说明不是同一部
4. 法规存在但没有这一条的（如民法典第一万条），`get_law_article` 会报查无，直接说明该法没有这一条

### 场景 I：条文援引其他条款

用户：「被公司违法辞退，能拿多少赔偿？」

1. `search_law_articles({"query_text": "用人单位违法解除劳动合同 赔偿金", "library": "中央", "timeliness": "现行有效", "size": 5})`，命中《劳动合同法》第八十七条「依照本法第四十七条规定的经济补偿标准的二倍」
2. 条文援引了第四十七条，继续 `get_law_article({"law_title": "劳动合同法", "article_number": "47"})` 取计算标准
3. 用通俗语言给出计算方法（工作年限折算月数 × 月工资 × 2），并提示可以申请劳动仲裁

### 场景 J：用户引用已废止的法律

用户：「合同法第五十二条规定了哪些合同无效？」

1. `get_law_article({"law_title": "合同法", "article_number": "52"})`，时效为「废止或失效」
2. `list_law_versions({"law_title": "合同法"})` 或 `list_related_legal_materials({"law_title": "合同法", "relation": "repeal_basis"})` 查它被哪部法律取代（本例为《民法典》，2021-01-01 起施行）
3. 按条文内容检索现行规定：`search_law_articles({"query_text": "恶意串通 损害他人合法权益 违反强制性规定 民事法律行为无效", "library": "中央", "timeliness": "现行有效", "size": 5})`；旧条文各项可能分散在现行法的多个条文中，逐项对应后用 `get_law_article` 取原文
4. 法典化同理：民法典吸收了合同法、侵权责任法、婚姻法等；生态环境法典吸收了多部环境单行法。优先引用法典；事实发生在法典施行前的，按当时的法律作答并说明

### 场景 K：地方标准与数额

用户：「北京现在的最低工资是多少？」

1. `search_law_articles({"query_text": "北京市最低工资标准", "timeliness": "现行有效", "size": 5})`（指定了地区，不传 `library`）
2. 多份调整通知都标「现行有效」时，以发布日期最新的一份为准，注明发布日期和文号
3. 全国性规定授权各省确定具体标准的（如盗窃罪「数额较大」、地方延长产假），提示以当地标准为准；用户没说地区时，先给全国性规定，再请用户提供所在省市
4. 通知只有标题、没有正文时，给出最新一份的标题、发布日期和链接，请用户打开查看，不凭记忆填数值

### 场景 L：修订后条号变化

用户：「公司法第一百零六条是怎么规定的？」（用户可能沿用修订前的条号）

1. `get_law_article({"law_title": "公司法", "article_number": "106"})` 返回现行版第一百零六条
2. 内容与用户描述的主题不符，或用户引用的是旧文书、旧教材时，用带版本的法名取旧版：`get_law_article({"law_title": "公司法(2018修正)", "article_number": "106"})`
3. 按旧版条文内容用 `search_law_articles` 或 `search_law_articles_by_keyword`（`title` 填「公司法」）找到现行版对应条号，再用 `get_law_article_history` 确认两者是同一条的沿革
4. 向用户说明条号已变化，分别给出两版原文和链接。用户没说是哪一版、新旧版同一条号内容不同时，并列两版或先询问

### 场景 M：司法解释与修订后的法律冲突

用户：「有限公司股东对外转让股权，需要其他股东同意吗？」

1. `search_law_articles` 可能同时命中《公司法》（2023修订）第八十四条和公司法解释（四）中「其他股东半数以上不同意」的规定，两者都标「现行有效」
2. 司法解释早于现行法施行的，核对法律对应条文的变化：`diff_law_article_versions({"law_title": "公司法", "article_number": "84", "from_version": "2018修正", "to_version": "current"})`，本例中「应当经其他股东过半数同意」已删除
3. 以现行法为准作答，并说明该司法解释的相应规定与现行法不一致、不再适用

## 四、结果解读

工具返回分三部分，内容并不重复：`content` 是可读文本，写有结论摘要、下一步建议和「本次调用需注意」；`structuredContent` 只含业务数据（链接、日期、文号、版本、时效等完整字段）；`_meta` 中的 `pkulaw/evidence` 写有可信级别 `confidence`（A 或 B）和本次说明 `notes`，`pkulaw/limits` 写有本次触发的能力边界。可信级别和注意事项不在 `structuredContent` 中，不能只读业务数据：先读 `content` 并按其中的提示执行；客户端提供 `_meta` 的，以 `confidence` 判断可信级别；引用链接、日期、文号等具体字段时以 `structuredContent` 为准；客户端只提供其中一部分时，以能看到的为准。可信级别为 B（文本中写明「可信级别：B」）的，回答中提示用户复核后再引用；为 A 的可以引用，仍请打开链接核对。空结果是有效结果，表示「这组条件下没有命中」，不等于库里没有，也不等于「未修改」「不存在」。


### 作答前核查

时效标「现行有效」不等于内容仍然适用。作答前逐项检查：

1. **取到的是不是目标法规**：核对返回的法规标题与目标一致；不一致的结果作废。法名可能有错别字或不规范时，先用 `search_laws_by_keyword` 或 `search_laws` 确认全称，再取条。
2. **有没有正文**：只有标题、没有条文的条目不能作为依据，也不转述其内容，更不能拿已废止旧版的内容顶替。有条号的用 `get_law_article` 取原文；没有条号、按「一、」「1.」分段的意见类文件，用更贴近原文的表述再检索一次；仍取不到时只给标题和链接，并说明未取得原文。
3. **要件是否完整**：检索只命中部分要件或特别规则时，补取一般规则和相邻条文（如诉讼时效补第一百八十八条，侵权补过错责任条款，合同纠纷补法定解除条款），按「适用条件 → 法律后果 → 救济途径」组织；相邻几条用 `get_law_articles_by_range` 一次取。条文援引其他条款的，补取被援引的条文。核对条文的适用主体是否与用户情况一致。
4. **是否与现行法冲突**：复函、答复、早年意见、配套文件、司法解释与现行法冲突，或沿用旧数额、已废止法律的（如仍写「依照《合同法》」），以现行法为准，不采用并说明原因。仍然有效的司法解释只是援引了旧条号的，换算为现行条号后照常引用。同一事项多份文件都标「现行有效」时，按施行或发布日期从新到旧核对，后发文件已调整的以后者为准；有执行期限的文件（如税收优惠），核对期限是否届满、有无延续公告。标题含「征求意见稿」「草案」的不作为依据。
5. **有没有新版或待施行版本**：作为主要依据的法律，用 `list_law_versions` 或 `search_laws_by_keyword` 查一次是否有「尚未施行」或近期施行的新版。期限、年限、数额类问题，注意分阶段调整（如养老保险最低缴费年限逐步提高）。有新版或调整时，回答现行规定的同时说明施行日期和主要变化。
6. **是否漏了部分废止的文件**：只筛「现行有效」会排除「部分废止或失效」的文件，部分常用司法解释属于此类。预期应有的司法解释没出现时，加上「部分废止或失效」补查，或以全称直接 `get_law_article` 取条；引用时提示该文件部分条款已失效。
7. **是否区分了适用范围**：程序问题按民事、刑事、行政分别说明（如上诉期限）；地方标准注明地区，不跨省套用；法律没有直接规定的，如实说明，再给出最接近的依据。

### 结果使用要点

- **法条语义检索**：结果按相关度排序，可能混有复函、规范性文件、只有标题的条目和同一部法的历史版本。回答现行规定时只采用现行版本，优先采用法律、行政法规、司法解释，主题不符的不采用。修改决定、修正案只记录修改过程，引用以法律本身的现行文本为准。
- **列表类结果**（法规、案例、检察、执法关键词检索）：是一页召回，不是穷尽检索。默认只看第 1 页，用户要更多时再按返回的翻页游标继续；召回的标题与问题不符时，换更具体的关键词或法规名再查。
- **类案**：只采用主题相符的案例。标题相近但裁判针对其他问题的（如仅裁定驳回起诉），不作为实体类案。参照级别以每条结果的标注为准，逐条核对。同一案件重复出现的只保留一件。部分典型案例没有案号，不自行补。案例引用已废止法律或旧条号的，给出现行对应条文；案例中的期限、利率、赔偿标准以现行规定为准重新表述，不照搬。
- **识别与核验**：识别类工具返回空，可能是文中确实没有，也可能是上游异常，结合上下文判断，不直接断言「文中无引用」。案号在库只说明案号真实，还要核对标题、法院和引用用途是否相符。核验工具给出的候选不是已核对的依据，只采用法名和条号都一致的条目。
- **法规沿革**：时点以施行日期为准。空时间线或空关联组表示未收录，不等于「未修改」或「不存在」。
- **检察、执法**：均为召回结果，引用前请打开链接核对原文。「近期」没有明确的，按近一年检索，并在回答中写明范围。逐条核对机关、对象和依据条款，区分分公司、派出机构与名称相近的关联企业；「免罚」「不予处罚」的单列说明。

## 五、输出纪律

1. **不凭记忆答法条、案号**：即使「记得」，也以工具返回的原文为准。
2. **每条依据附来源**：写明法规全称、条号和 pkulaw.com 完整网址；链接原样使用工具返回的地址，不自己拼写或改动。
3. **标注时效与版本**：保留版本标注（如「2012修正」）；不是「现行有效」的（含已被修改、部分废止、废止或失效、尚未施行），必须明确提示。
4. **法律适用规则**：上位法优于下位法，特别法优于一般法，新法优于旧法；司法解释与其所解释的法律配套引用；地方性规定注明辖区。
5. **时间维度**：事实发生在旧法施行期间的，按当时施行的版本作答并说明；引用的判例早于现行法施行的，提示其适用旧法、参考价值有限。
6. **案例效力**：按最高人民法院文件规定的效力写，不按法宝筛选菜单的顺序排高低。参照级别以每条结果的标注为准：
   - **指导性案例**（最高人民法院发布）：写「应当参照」。参照的是裁判要点，引用时写明「指导性案例××号」，作为裁判理由引述，不作为裁判依据。最高人民检察院发布的检察指导性案例供检察机关参照，对法院没有参照效力。
   - **参考案例**（人民法院案例库入库案例）：写「应当检索并参考」，裁判要旨可作为裁判理由参引，不作为裁判依据。
   - **公报案例、典型案例**：写「可以参考」，不写成「应当参照」，二者之间不排高低。
   - **参阅案例、评析案例、优秀案例、经典案例、应用案例、法宝推荐、普通案例**：没有单独的法定参照效力，注明「仅供参考，最终以法院裁量为准」。
   - 「权威案例」只是检索时的组合筛选项，不是参照级别，不写入回答。多类案例并列时，按指导性案例、参考案例、其他案例的顺序排列，这只表示检索优先，不表示其余几类之间有效力高低。
7. **裁判倾向**：多份判决口径不一致时，写明主流观点和不同观点，不以单个判例作为唯一答案。
8. **空结果不编造**：查不到就如实说明，建议换更准确的名称或描述。用户问题的前提有误的（如把司法案例当作刑法条文），先指出再作答。
9. **核验流程**：法律意见书、合同审查结论、对外文本，或用户要求核验时，定稿前执行场景 G；与权威原文不一致的改为原文并说明已校正。已经用 `get_law_article` 取得原文的条文不必重复核验；回答中没有引用的不必核验。
10. **通俗表达、详略得当**：用户不是专业人士时，用日常语言说明结论和能采取的行动（申请劳动仲裁、向法院起诉、保留证据等），法律术语附简短解释，再列依据。只查一条法条时，给出原文、版本与时效、链接即可。
11. **不替代律师**：涉及具体案件处理或对外文书时，注明本结果为检索辅助，不构成法律意见，建议咨询专业律师。

## 六、问题反馈

用户发现数据错误、应有但查不到、调用报错或结果不相关，或想提建议时，可以把问题提交给北大法宝。

1. **只在用户明确要求或同意后提交**。可以在出现明显数据问题时提议「需要我把这个问题反馈给北大法宝吗？」，用户同意后再调用 `submit_feedback`。
2. **先排除检索本身的问题**：只是没找到想要的结果时，先换检索条件或换工具再试；积分扣多了、余额不对，先用 `get_points_balance` 核对。
3. **一条反馈只写一次调用**：把出问题那次调用的工具名和请求编号从原返回中原样抄入；没有请求编号就留空，不要编造。同一问题涉及多次调用的，其余编号放进关联编号。
4. **只写必要信息**：`summary` 一句话说清问题，`description` 写期望与实际的差异；`user_request` 只放用户这一次的原话。不上传完整聊天记录、他人个人信息或 Token。
5. **向用户说明分类时用中文**：数据错误、数据缺失、工具报错、结果不相关、产品建议。
6. **提交后**：把返回的反馈编号和查看进度的地址原样告诉用户。返回「已提交过」或「未受理」不是失败，如实转述即可；同一问题不要换个说法再提交。提交反馈不改变检索结果，也不代表问题已被确认。

## 七、鉴权、积分与错误处理

本连接器由客户端完成连接与鉴权，用户不需要在对话里提供 Token。多数业务工具按次消耗积分：已知法名条号时直接精准取条，避免重复检索；互不依赖的调用可以并行发出。`get_points_balance`、`list_entitlements` 和 `submit_feedback` 不必在每次检索前调用，只在用户询问或出现对应错误时使用。积分与开通信息不写入法律文书正文。

**常规异常**

- **工具名称不匹配**：在 `tools/list` 中按用途重新确认，使用列表中的完整名称。
- **参数不合法**：按工具说明修正后重试一次；仍不成功时去掉筛选条件，把条件写进主检索文本。
- **精准取条查无**：法名用了简称或可能有错别字的，先用 `search_laws_by_keyword` 确认全称，再以全称重试一次；仍查无的，如实告知。
- **无结果**：关键词检索可改用对应的语义检索，或适当放宽表述，各试一次；仍无结果时如实告知。

**网关错误码**

网关错误出现在 JSON-RPC 响应的 `error` 中，以 `error.code` 判断，不看 HTTP 状态码（同一类错误可能返回 200，也可能返回 403）。`error.message` 中带有处理链接的，原样转给用户，不自己拼写网址。遇到以下错误码时，不重试业务工具，也不换其他工具绕过。

| 错误码 | 含义 | 处理方式 |
|---|---|---|
| `900908` | 法宝 MCP 服务未开启 | 请用户在客户端断开并重新连接本连接器，重新授权时会自动开启服务；重新授权后仍报错的，把 `error.message` 中的链接给用户，到控制台手动开启 |
| `900001` | 积分不足 | 把 `error.message` 中的充值链接给用户；需要说明余额时，调用一次 `get_points_balance` |
| `900002` | 成员 Token 额度不足 | 管理员为该成员 Token 设置的额度已用完，请用户联系团队管理员调整，并提供 `error.message` 中的配置链接 |
| `900805` | 请求被安全策略拦截 | 立即停止本轮全部工具调用，告知用户请求因访问过于频繁或存在风险被拦截，请稍后再试；持续出现时请联系北大法宝 |

其他错误码：如实转述 `error.message`，不重试同一调用。

用户反复遇到同一错误、且不是积分、额度或开通问题时，可按第六节提议反馈；`900805` 拦截期间先不要提交。
