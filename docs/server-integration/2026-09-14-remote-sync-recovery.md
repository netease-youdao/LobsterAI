# 桌面任务同步状态恢复与诊断

2026-09-22 同步设计更新（代码已实现，未部署）：见[当前生效服务与同步绑定恢复](../../specs/bugfixes/remote-sync-target/2026-09-22-effective-server-sync-design.md)。新方案取消域名/模式硬阻断，按当前服务确认的 binding 核对增量、快照及原操作回执；只有相应绑定恢复成功后才清失败标记，不把普通 404 或所有状态冲突统一转成全量导入。本文的证据边界和不伪造 ACK 原则继续有效。

日期：2026-09-14。改动范围为桌面 RemoteBridge 和回归测试，不修改服务端接口、数据库或用户任务数据。

## 问题与证据边界

用户提供的 2026-09-14 日志未包含远控同步接口响应或错误码；ChannelSync 的网关休眠/重启错误不能证明手机远控 HTTP 同步失败。不能据此断言本次原始失败来自某个服务端错误码。

代码审查确认：快照导入失败会保存 syncFailure；重试成功或收到服务端已 committed 的幂等结果后，原实现确认同步水位并删除 import，却未删除 syncFailure。任务详情优先读取该失败标记，因此可能在数据已同步后仍显示失败。页面的同步失败摘要也可能残留。

## 修复

- 在快照 ACK 的同一事务中清除失败标记；ACK 校验或本地提交失败时保持原状态，不能提前显示成功。
- 对旧版本留下的失败标记，只有设备匹配、无需快照、source_seq=ack_seq、无 import、无 dirty、无待发 outbox 时才清理。
- 全部当前账号的会话没有失败标记后，清理对应的同步失败摘要；其他连接错误或仍失败的任务不受影响。
- 同步错误日志只记录本地/远端会话 ID、snapshot/batch 阶段、错误码、HTTP 状态和格式受限的 reason/requestId。不输出会话内容、凭证、原始响应和异常消息；失败记录保留同样的诊断字段供后续排查。

## 兼容与接入

HTTP/WS 路径、认证、快照/增量同步及恢复协议不变，无 App、Portal、Admin 改动，无 SQL 迁移。不会删除或改写冲突 import、未确认 outbox，也不把未知服务端水位当作已同步。

本改动修复了可复现的失败状态残留，并补齐诊断信息；实际原始网络/服务端失败仍需结合失败当时的 requestId 和服务端日志确认。

## 验证

修复前针对新恢复用例运行可复现旧失败标记残留；修复后三个桌面远控测试文件共 81 项通过，其中本次新增 12 项恢复用例。改动文件 ESLint 和 Electron TypeScript 检查通过。未运行服务端测试、真实账号同步请求或修改用户数据库；日志包缺失的原始接口错误仍待进一步证据。

## 补充排查：首次问答成功、后续问答失败

用户确认故障发生在另一台电脑，不能用本机 SQLite 的状态判断该故障是否恢复。按导出日志中的 localSessionId 只读查询用户指定的测试库，定位到日志对应桌面设备的记录：

| c2f8dbbf-2ef2-4402-8f84-4bf96d6fdc09 | 2026-09-14 10:46:52.844 | 2026-09-14 10:46:33.665 | sourceSeq=22、controlVersion=3 |
| 4a996a41-df5a-4e9c-ac3f-3dcf76a9c877 | 2026-09-14 12:38:36.235，随后 12:39:31.834 再次续聊 | 2026-09-14 12:38:24.566 | sourceSeq=18、controlVersion=3 |

第一条会话的服务端事件不仅有首次 session.reset，也已成功接收第一轮的 message.upsert、tool.upsert、session.upsert 和 run.updated；最后一个 run 为第一轮 succeeded。因此不是“所有增量接口请求都失败”，范围应收敛到第一轮结束后、第二轮更新被提交之前。现有数据证明后续问答没有同步上来，不能用失败标记残留解释。

服务端协议静态检查排除了 batchId 长度、正常 sourceSeq 衔接及正常第二轮 controlVersion 顺序不匹配。另用真实 RemoteStore 和内存 SQLite 进行了合成两轮检查：首轮快照确认后，第二轮 sourceSeq 连续、相同版本内容一致、消息关联字段不变、最终 controlVersion=6 且 ACK 追平。该检查没有调用真实服务端，不能替代故障环境复现。

本轮未确认具体根因，未据猜测修改同步协议或任务数据。已有导出日志不含失败同步请求的响应码及 requestId；后续需在故障电脑使用包含 [RemoteSync] 诊断的构建复现，并用 localSessionId、phase、code、httpStatus、reason、requestId 对照服务端日志。此前失败标记修复仍有效，但不应作为这次第二轮同步中断已经解决的依据。
