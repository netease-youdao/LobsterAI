# 远控 WS 容量配置更新

日期：2026-09-11。服务端按现有 4 个 Pod 合计 100,000 条远控 WS 配置准入额度；尚未实际部署或完成目标负载压测。

## 1. 变更摘要

- 每 Pod 远控准入上限由 1,024 改为 25,000，桌面和手机共同占用。
- Tomcat 总连接上限设为 32,768，连接等待队列设为 1,000；保留原 Tomcat 512 个工作线程。
- 远控共享工作线程由 4 改为默认 32，执行队列容量随单 Pod 连接额度扩大；保留有界字节预算和单连接串行处理。
- 不修改登录、设备限制、会话归属、审批或任务状态恢复协议，无数据库迁移。

## 2. 接口信息

现有 `POST /api/remote/v1/connection-tickets` 和 `GET /api/remote/v1/ws?ticket=<ticket>` 的路径、请求及成功响应保持兼容。服务端节点达到准入上限时仍在 WS 升级前返回 HTTP 503，业务码 47011、reason=RATE_LIMITED，响应 data 中包含 retryable=true、retryAfterMs=3000。该响应不代表现有桌面任务执行失败。

## 3. 客户端接入事项

无新增必改项。继续采用既有重连退避、重新获取一次性 ticket、按事件水位和持久任务状态恢复；不要在重连时重新创建原任务。不要把每 Pod 25,000 解释为每个账号可连接的设备数。

## 4. 认证要求

沿用 JWT Bearer 与设备凭证获取连接票据、一次性 ticket 握手；账号及个人/团队身份隔离不变。

## 5. 部署和限制

- 默认值可由 REMOTE_MAX_CONNECTIONS_PER_POD、REMOTE_WS_WORKER_THREADS、SERVER_TOMCAT_MAX_CONNECTIONS、SERVER_TOMCAT_ACCEPT_COUNT 覆盖，旧覆盖值需在发布时核对。
- 无强制客户端/服务端升级顺序；节点滚动更新期间各自按当前配置执行限额。
- 4 个 Pod 满配合计 10 万是额度预算，不是集群全局硬限。负载分配不均可能提前触发单 Pod 拒绝；副本增加会增加总额度。
- 满负载时暂时少一个 Pod 只剩 75,000 条额度，部分客户端需等待节点恢复；依靠原有持久状态恢复任务。
- 本次不变更 Pod 资源、JVM 8GB 堆、数据库、Redis 或 Nginx/LB；实际在线容量仍需核验入口/FD、CPU、内存和后端负载。
