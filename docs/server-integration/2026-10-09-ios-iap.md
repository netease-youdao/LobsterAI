## 1. Change Summary

首版仅支持 iOS 通过 Apple 购买个人自动续期月订阅（P1M），同一 LobsterAI 账号在手机、Electron 和 Portal 共享服务端确认的会员与周期积分。Apple 加油包购买不在首版范围，旧 Web 加油包的购买、有效期、消费和退款保持现状。

服务端采用独立 Apple 交易账本、订阅来源与周期积分桶，不把 Apple 交易写入旧人民币 `payment_orders`，不将 Apple 周期积分写进自然月额度。所有来源的会员和余额由服务端聚合；客户端不得自行合并不同来源套餐等级或推算积分。

## 2. Endpoint Details

Electron 当前主要消费 `GET /api/user/quota` 与 `GET /api/user/profile-summary`，继续沿用这些接口。它们返回服务端聚合的有效会员和余额，现有字段类型、错误语义及认证不变。

| 既有字段/接口 | 兼容要求 |
|---|---|
| `subscriptionStatus` | 有效 Apple 会员，包括按政策有效的宽限期，仍映射 `active`；Apple 精细状态仅放新增字段/接口 |
| `planName` 等套餐字段 | 保留既有名称、类型和中英文语义；由服务端当前有效订阅决定 |
| `hasPaidCredits` | 继续包含服务端既有兼容判定，纳入实际可用 Apple 订阅权益；不得让媒体插件错误禁用 |
| `creditItems[].type` | Apple 订阅沿用 `subscription`；既有加油包继续 `boost`，不以新字符串替换旧枚举 |
| `creditItems[].creditsRemaining` | 旧协议继续 number，不改为新协议的 decimal string |
| `totalCreditsRemaining` | 由服务端统一计算，不要求桌面自行遍历 Apple 交易累加 |

后续如需展示来源，读取新协议 `GET /api/iap/apple/entitlements`，其 `membership.sources` 区分 `provider=apple|legacy`；`boost` 仅含既有加油包的只读 `creditsRemaining`，邀请余额另见 `invitation`，不提供 Apple 加油包批次或购买能力。新接口 ID 和积分为字符串，新日期为 UTC RFC3339；不能直接拿新 DTO 替换旧 number/日期 DTO。Apple 相关客户端 API 以 API 文档权限为准。

本期不增加永久加油包、日期哨兵值、`neverExpires` 展示或旧加油包统计改造。既有加油包明细、到期日和余额口径保持不变。

新 Apple 来源另提供 `lastVerifiedAt`（当前链最近成功核实时间）、`renewalProductId`（未来续费商品）、`priceIncreaseStatus`（`pending|accepted|null`）和 `expirationIntent`（Apple 到期原因整数或 null）。这些只用于增强解释：未来商品不代表已生效；accepted 不一定表示用户亲自同意涨价；未知原因或空值不得覆盖服务端 active/有效截止。`asOf` 仅是本地聚合时间，不代表刚向 Apple 查询。

## 3. Frontend Action Items

### 无需强制升级的行为

- 保持现有 `/api/user/quota`、profile-summary 调用和刷新逻辑。服务端确认到账后，桌面下一次刷新可见权益。
- 保持 `active` / `enterprise` 等既有付费判定，Apple 不需要独立客户端模型权限逻辑。
- 非 Apple 用户的订阅升级、既有充值和账单继续使用原有 Portal 跳转。账号菜单识别到 Apple 订阅时，升级入口按下文提供 Apple 引导。桌面不负责 StoreKit，不接收 `.p8`，不调用 Apple 通知端点。
- Apple 交易独立于旧订单；原 Portal 人民币订单列表和发票列表不应出现伪造的 Apple 人民币订单。

### 后续可接入的体验增强

- 若增加来源管理页，按来源展示套餐、实际结束时间、续费意愿和管理方式。一个来源关闭续费不等于其他来源也关闭。
- Apple 会员的管理动作引导至服务端声明的 Apple 管理方式；不要将“升级”直接映射成旧微信签约。
- 从 Apple 管理入口返回后可刷新服务端权益，但页面关闭或旧快照都不证明变更已完成。桌面不伪造 JWS；主动恢复及签名交易同步由 iOS 完成，桌面通过正常刷新观察服务端通知/对账结果，必要时引导用户在 iOS 恢复购买。
- 刷新过程中保持原账号上下文，账号切换后丢弃旧账号返回值；沿用现有账户 generation/scope 保护。
- 对服务端返回的重复订阅或 Apple 管理提示直接展示可读信息，不把被拒绝的旧取消接口当成功。

## 4. Auth Requirements

保留现有 Electron JWT accessToken、refreshToken、账号/企业身份选择协议。共享权益属于购买时绑定的个人用户，不因登录同一台设备或相同 Apple 账号自动转给其他 LobsterAI 账号。

新增 IAP 用户 API 只接受个人 JWT accessToken，refreshToken、Cookie/Session、企业 token 均不能作为回退；缺失/无效 Bearer 必须处理认证失败。已有 Electron 及旧接口认证行为保持不变。Sandbox 交易只在测试身份域生效，不形成生产账号付费资格、生产媒体权限或首购活动排除依据。

新 IAP 响应使用 `Cache-Control: private, no-store`；不要缓存到共享位置或写入完整响应日志，临时界面数据按账号隔离。限流遵守 Retry-After，不因为读取失败重新发起购买。

## 5. Notes & Caveats

- `subscriptionStatus=active` 与 `autoRenew=false` 可同时成立，表示已付款周期仍可用。
- Web/Apple 正常订阅互斥；历史异常来源由服务端处理。套餐、余额和日期统一读取服务端，不自行合并。
- 旧 `boostCreditsRemaining` 包括邀请积分，不能再次叠加邀请字段。
- 服务端须合并正式 Apple 已交付支付的历史付费资格，用于首购优惠及风控；客户端不能因为旧支付订单列表为空就断言“从未付费”。
- 现有 `authQuota.ts`、`accountMenuState.ts` 与发布/ASR 逻辑只识别既有枚举，这是服务端保留 `active` 投影的原因，不是强制桌面升级的前提。
- 开启服务端功能开关不代表接口已部署可用。前端验证见下文；测试库结构迁移已由服务端任务执行，真实支付联调仍待验收。

建议验收：仅旧 Web 用户响应不变；纯 Apple 会员桌面功能可用；Apple 订阅与旧 Web 加油包余额并存；退款不清除其他来源；关闭 Apple 续费但周期未到仍可用；Sandbox 不污染生产；账号切换不串余额。

## 6. 本轮实现与交付范围

已实现桌面消费端适配：现有 quota/profile-summary 的新增字段为可选，保留旧服务端回退。2026-10-13 按最小改动原则调整账号菜单：套餐及“升级”按钮保留原有显示条件；仅在点击升级且识别到个人账号 Apple/mixed 订阅时，复用现有全局带操作按钮的提示，显示“当前订阅由 Apple 管理，请前往 Apple 升级套餐。”点击“前往 Apple”才打开固定官方管理地址；关闭或忽略提示不跳转、不创建订单。打开失败时提示在 iPhone 设置的订阅页面管理。移除此前新增的常驻 Apple 菜单项及续费说明，非 Apple 的 Portal 跳转、埋点、账号 generation 保护和刷新机制不变。不新增组件、IPC、接口调用或 StoreKit 接入，不更改旧账单范围。

本次交互调整仅覆盖账号菜单的“升级”；其他既有充值/购买入口保持原逻辑，服务端继续执行跨渠道订阅保护。关闭 Apple 自动续费但权益尚未到期不代表可立刻转其他渠道购买。

### 已确定的旧接口增量字段

`GET /api/subscription`、`GET /api/user/quota`、`GET /api/user/profile-summary` 与 UserStats 的投影新增下列字段，旧字段类型、认证和请求路径不变；客户端全部按 optional 处理：

| 字段 | 类型与语义 |
|---|---|
| `subscriptionProvider` | `legacy | apple | mixed | null`，无付费来源可为 null |
| `hasAppleSubscription` | boolean，服务端确认是否存在需要 Apple 管理的订阅来源 |
| `canCancelLegacySubscription` | boolean，仅表示旧 cancel 接口可取消 legacy，不代表可取消 Apple |
| `appleSubscriptionManagementUrl` | string/null，Apple 订阅管理入口；客户端限制到已知 Apple 管理地址 |
| `appleRenewalDate` | string/null，已确认的 Apple 下一续费日期，UTC RFC3339，不按周期结束减一天推算 |

`mixed` 保留为历史异常兼容值，不表示允许跨渠道同时订阅；`autoRenew=false` 不表示可以立即切换渠道。旧服务端缺字段时保留原有行为。

## 7. 2026-10-14 兼容与安全修订（服务端已实现待联调）

服务端按[修复 spec](../../../lobsterai-server/docs/specs/payment/feature-2026-10-14-ios-iap-remediation.md)冻结旧路径、认证、字段类型、日期、null/省略、状态及 HTTP/业务错误，不要求桌面增加版本/幂等参数。零额项仍只使用 type/label/labelEn/creditsRemaining/expiresAt，creditsRemaining 为数字 0，仅对应当前选中的有效订阅；不新增 planId/name 字段，不增加汇总余额。其他钱包仍有实际余额时允许使用，全部耗尽才按真实有效会员区分原额度错误；不会为 Apple 补建旧 monthly_credits。

服务端会独立处理证据版本、防重、隔离和权限，桌面刷新或 Apple 管理页返回都不能代表交易已完成。仍按旧响应判断会员/额度；不调用新 Admin 恢复接口，不把维护失败转换为新购买。
