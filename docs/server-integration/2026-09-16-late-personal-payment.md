# 2026-09-16 个人支付延迟到账修复

## 变更说明

当前工作区的个人订单切换实现已经增加订单有效期和渠道关单。本次补齐直接二维码下单的有效期、持续运行的超时处理，以及 `closed` / `failed` / `payment_review` 的受控成功付款结算。旧订单没有 `payment_flow_state` 也可恢复。

## 支付规则

- 微信 Native 下单传订单原始 `expires_at`，不从再次扫码时间重新计时。剩余不足一分钟拒绝生成新二维码，避免微信自动延长短期限。相关官方约束：https://pay.wechatpay.cn/doc/v3/merchant/4012791877 。
- 已发起支付的订单先查渠道状态，再实际关单；未知结果保留处理中和优惠占用。Native 的“本地过期 + 查无订单”不作为已关单证明。
- 换购及后台恢复始终可用，无需开关配置。个人初购/加油包超时清理持续执行，续费和升级订单不进入该清理队列。
- 验签成功后校验金额、支付时间、流水、渠道及微信商户/应用身份。自动恢复前还检查退款事实、其他订单的流水占用、已有积分、优惠占用和订阅状态。
- 无冲突的标准/自定义加油包和首次订阅按原订单结算；自定义加油包积分基数仍取 `originalAmount`。支付事实、权益、优惠核销在同一事务完成。重复通知不会重复发放。
- 不能覆盖其他订单的优惠，不能重置已变化的订阅；延迟升级/续费需人工核对。可信付款有权益冲突时记录 `payment_review`、实际支付时间和渠道流水，并记录 `PAYMENT_RECONCILIATION_REQUIRED`。退款/凭证冲突拒绝结算。
- 已取消/过期协议的真实付款可以补权益，但不会恢复自动续费。

## 客户端接口

接口路径、鉴权与请求不变：

- `GET /api/payment/orders/{orderNo}/status`
- `GET /api/subscription/order-status/{orderNo}`

Portal 使用现有 Cookie/Session；Electron 使用 JWT Bearer。订单归属校验不变。示例（省略原有其他字段）：

```json
{"code":0,"message":"success","data":{"orderNo":"LB...","status":"paid","paymentChannel":"wechat","paidAt":"2026-09-16T12:00:00"}}
```

`closed` 是本地关闭结果；收到并校验真实付款后仍可转为 `paid`。`payment_review` 表示已记录付款但不能安全自动发权益，不能展示“到账成功”。

## 客户端接入事项

1. 沿用服务端下发的订单截止时间；本地倒计时不能证明渠道未扣款。
2. 返回订单页/支付结果页时刷新原订单状态。`paid` 后刷新积分和订阅。
3. `payment_review` 提示“付款已记录，正在核对到账”，保留订单号供核对。不要要求已扣款用户再次支付。
4. 本次没有修改前端源代码；原有切换商品接入说明继续适用。
