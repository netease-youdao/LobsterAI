# 远控首连启动顺序修复接入（2026-10-28）

## 变更摘要

桌面执行核心和账号监听仍早初始化；远控 bridge 延后至旧运行状态清理、provider/auth getter 注入、模型缓存预热、Agent 模型迁移及首轮运行器配置同步返回之后。启动期间 IPC 不能提前初始化或消耗身份恢复重试。GC 也必须等待 bridge 建立及原安全恢复门禁通过。

此修复解决代码可确认的启动竞态。提供的日志缺少首次失败与手动重连的对照窗口，尚不能认定现场故障已经闭环；需要 Mac 安装包与手机复验。

## 接口与客户端行动项

HTTP/WS、请求响应、认证和错误码均不变。继续使用原设备注册、设置、连接票据、WS hello，以及输入准备和命令链路；完整接口与示例见服务端 `docs/api/mobile-remote-api.md`、`docs/api/mobile-remote-input-v2.md`。手机无需同步升级，不修改手机源码。

“在线”仍只代表传输连接。输入 v2 按原 `purposes.*.available`、Agent/模型目录和命令回执判断可执行性；不要将在线、目录同步或 HTTP 200 当作任务执行成功。

## 认证与兼容

JWT Bearer、设备凭据、owner/scope/目标/连接代次与执行许可校验保持。启动门禁不授予权限、不创建替代身份、不清理历史请求。保存的关闭偏好、原身份恢复及账号切换仍生效。首轮配置同步返回失败结果后保留既有错误处理；Gateway 继续按原 ensureReady 流程启动。

服务端仅补充接口与接入说明，无业务代码/开关/DDL变更，兼容 MySQL 5.7，无服务端发布顺序要求；Portal、Admin 无接入动作。

## 验证

定向测试、编译、lint、安全审查结果及待验收项统一记录在服务端 `docs/integration/2026-10-28-remote-startup-readiness.md`。服务端测试按要求不运行；自动化验证不替代首装/保留登录冷启动的手机真机测试。
