# 2026-09-16 加油包扫码支付路由兼容修复

## 变更摘要

标准加油包、自定义金额加油包、复用优惠订单统一返回路径参数形式的二维码地址。统一路由地址由服务端共用方法生成，企业积分包继续使用原有路径格式。

旧版加油包二维码使用 `?orderNo=`，服务端原先只映射 `/route/{orderNo}`，导致手机扫码后出现 Whitelabel 404。本次增加旧链接兼容入口，直接进入同一支付处理，不重建订单、不重置截止时间、不变更优惠占用。

## 接口与响应

推荐入口：`GET /api/payment/unified/route/{orderNo}`。

兼容入口：`GET /api/payment/unified/route?orderNo={orderNo}`。

购买接口的 JSON 结构保持不变，仅 `qrCodeUrl` 的地址格式改正。测试服示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "orderNo": "LB20260916101650944988",
    "qrCodeUrl": "https://lobsterai-server.inner.youdao.com/api/payment/unified/route/LB20260916101650944988"
  }
}
```

以上是格式示例，不代表该历史订单当前仍可付款。

路由返回手机 HTML 或跳转响应，不使用 API JSON 包装：

| 条件 | HTTP 与行为 |
| --- | --- |
| 有效订单、微信内扫码 | 200，返回原有微信支付唤起页 |
| 有效订单、支付宝内扫码 | 302，跳转原有支付宝支付地址 |
| 普通浏览器 | 200，提示使用微信或支付宝扫码，不发起渠道下单 |
| 订单不存在 | 404，返回“订单不存在”的业务页面 |
| 旧入口缺少或传入空白 orderNo | 400，返回重新生成二维码的提示，无数据库查询/渠道下单 |
| 订单已关闭或已处理 | 沿用 200 业务提示，不重新打开订单 |
| 个人订单仍 pending 但超过截止时间 | 410，提示重新下单，不发起渠道下单 |

旧数据没有 `expires_at` 时，沿用 `created_at + 30 分钟` 的有效期。服务端支付流程仍会再次检查当前订单状态和有效期，防止路由检查与支付初始化之间发生并发变化。

## 鉴权与前端接入

扫码路由保持现有公开访问方式，手机扫码不要求携带 PC 的 Cookie 或 JWT；微信和支付宝继续通过原始 User-Agent 识别。下单接口仍需原有登录态：Portal Cookie/Session 或 Electron JWT Bearer。

Portal、Electron 无需修改页面代码：直接使用购买接口返回的 `qrCodeUrl`，不要自行拼接或重写订单地址。重新打开购买窗口时重新读取服务端返回值。

## 兼容、发布和用户恢复

- 服务端修复部署到测试服后，新生成的二维码使用新地址；仍有效的旧二维码继续可用。
- 已关闭、已过期的旧二维码仅展示业务提示，不能恢复付款或重启优惠倒计时。
- 排查时用户 17644 的订单 LB20260916101650944988 已关闭、没有支付时间或渠道流水，优惠记录为首充八折。部署后通过购买页面重新下单，由现有业务逻辑检查并释放旧关闭订单的预约，再生成新订单。
- 无新增配置、无数据库迁移、无数据 UPDATE SQL。现有支付功能的发布依赖保持不变。
- 本次没有修改前端源代码，也未部署服务或操作线上订单。
