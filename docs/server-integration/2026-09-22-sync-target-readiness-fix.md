# 同步身份读取及“待同步”修复接入说明

## 变更摘要

服务端显式映射 remote_sync_target 的两个字段，修复测试库已有有效身份却返回 503/47003/DEVICE_NOT_READY 的问题。桌面同步修复注册失败退避和任务详情状态；App 和 Portal 不需要改代码。本次无数据库迁移或新功能开关，不更换既有身份/世代。

## 接口及认证

保留以下接口的请求、响应和认证语义：

- `GET /api/remote/v1/capabilities`
- `POST /api/remote/v1/devices/register`
- `POST /api/remote/v2/devices/register`

继续使用现有 JWT Bearer、账号/空间及预算校验。注册的 installationId/deviceKey 等字段不变；发现请求不携带旧目标头，其他远控请求按原协议使用已确认的设备凭据与目标头。数据身份只是同步目标，不代替认证。

成功响应已有的 `data.syncTarget` 示例（不是完整响应）：

```json
{"version":1,"dataSpaceId":"449157c2-49d8-4ea7-b8f4-c4c6e4ecbe56","dataGeneration":"1"}
```

dataGeneration 保持十进制字符串。真实身份缺失/非法仍返回原 503/47003；不得把任意错误或普通 404 当成新空数据库证明。

## 桌面行为

- 发现/注册未完成时，失败使用现有指数退避，普通本地事务 wake 无法越过截止时间。没有已确认 registration/target 时不启动删除空轮询，避免持续触发立即重试。手动重试、换账号和服务地址后重新尝试；已注册的删除事实回执仍独立处理。
- “同步服务暂不可用”区别于普通排队中的“待同步”。当前已验证目标的完整 ACK 仍显示“已同步”；API 路由改变、目标不匹配或注册未知时，不把旧 ACK 显示为当前服务已同步。当前任务投影失败显示“同步失败”。
- 悬浮卡打开时订阅远程状态事件，3 秒内合并刷新、不并行查询；关闭后解绑。刷新期间仅保留同 target 和 ownership revision 下的授权详情，账号/权限变化立即隐藏并丢弃迟到结果。

## 发布与回滚注意

先部署服务端修复，再更新桌面。测试库 V102 已执行，不要重跑迁移以轮换身份，不清空桌面队列或重建任务。其他环境继续满足原 V102 与一致部署条件；默认开启开关不变。旧客户端可继续使用原接口，桌面新版本也会在旧服务返回503时有界等待。

验收 capabilities、两版注册返回同一既有身份，桌面可自动恢复并更新详情。故障时本地新建/续聊/文件操作保持可用；服务端恢复不应导致重新执行已完成任务。真实环境和手机联合验收仍需部署后完成。
