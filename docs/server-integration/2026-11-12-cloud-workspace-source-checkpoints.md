# 云任务源码检查点兼容说明

日期：2026-11-12。本次为云运行时及服务端内部检查点兼容改进，无新增客户端 API。

## 变更摘要

成功完成一轮任务后，受筛选的普通工作区源码（例如 `src/main.py`、`src/app.js`）与文档、下载文件一同保存到检查点。下一轮可以在新实例恢复这些文件及已完成会话，再继续任务。`.env`、凭据、运行时配置、插件、技能、`node_modules`、`.git` 和 `tmp` 等保护路径仍不进入检查点；恢复文件不保留可执行权限位，也不会自动加载为插件或启动配置。

## 接口详情

路径、请求响应字段类型、错误码、认证和幂等语义均沿用已有协议：

- `GET /api/cloud/v1/tasks/{taskId}`：继续使用 `canContinue` 和 `recoveryState` 判断是否可续接。
- `POST /api/cloud/v1/tasks/{taskId}/runs`：仍使用 `requestId`、`expectedVersion`、`input`，无需传入检查点路径或选择运行时。
- 任务事件、文件上传及产物下载接口保持不变。工作区源码快照不等同于新增“浏览任意工作区文件”接口。

既有续接请求示例（替换为真实任务版本及新 UUID）：

```json
{
  "requestId": "e75098ba-2287-4cb9-9df7-3d743f64a279",
  "expectedVersion": "3",
  "input": {"text": "继续修改上一轮生成的源码", "assets": []}
}
```

成功响应继续为 `{ "code": 0, "message": "success", "data": { ... } }`；`data` 原有 `requestId`、`task`、`run` 和 `inputMessageId` 不变。只有服务端返回 `canContinue=true` 且 `recoveryState="ready"` 时才应开放继续操作。

## 客户端行动项

无需强制升级或修改请求结构。若已有“继续任务”功能，保持当前调用和错误处理即可；不要仅凭上一轮显示成功就推断检查点已可恢复。产品说明可将“完成轮次后继续处理源码和文件”与“保留原机器、后台进程或完整桌面”区分开。

## 认证要求

云协议仍要求 `Authorization: Bearer <accessToken>`；除 `/api/cloud/v1/capabilities` 外，继续携带当前 `X-Cloud-Environment-Id`。任务归属及个人/企业授权校验不变，不接收工作负载凭据，也不新增 Cookie 回退。

## 注意事项与发布顺序

- 这是完成轮次的快照恢复，不提供中途取消/失败恢复、后台服务常驻或旧实例保留。
- 仍按任务固定 `runtimeRelease` 和检查点 schema 1 恢复，不跨运行时强制转换历史会话；旧镜像需保留到相关任务恢复兼容期结束。
- 相对路径暂按现有服务端协议限制为不超过 512 个字符；本次不扩大协议上限，也不静默丢弃超长路径。
- 新能力只影响此后成功生成的完整快照，无法补回旧快照当时未保存的源码。
- 先发布兼容服务端逻辑与完成验收的固定镜像，再按现有发布流程准入新 release；无需联动客户端发布。候选构建或模拟模型检查不等于正式业务已上线。
- 本轮不调用收费模型；Java 控制面、真实 TOS 和积分扣费验证范围以最终验收文档为准。

Electron 继续使用现有 JWT access token 与刷新流程；无需更新本地桌面 Agent 或让客户端直连 Runner。
