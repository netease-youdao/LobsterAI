**插件加载优化：用户侧冒烟回测计划**

目标：确认启动和重启明显变快，同时日常聊天、工具、IM 接入与收发保持正常。

使用包含本次新 OpenClaw runtime 的 Windows 安装包。优先在原 QA 问题机器上，以原有账号、模型和 IM 配置覆盖升级；另用干净的测试用户覆盖一次新安装、未配置 IM 的场景。性能对照使用同机、同配置的优化前版本。

**核心冒烟清单**

| 功能点 | 用户操作 | 通过标准 |
| --- | --- | --- |
| 安装与首次使用 | 老用户覆盖升级后打开；新用户完成安装、登录，不配置 IM，直接聊天 | 正常进入并收到回复；历史会话、模型和渠道配置保留；没有未配置 Discord 等平台的登录或错误弹窗 |
| 基础聊天与会话 | 新建会话、连续追问；打开老会话继续聊；生成中停止，再发送一条消息；切换一个自定义助手 | 流式回复和停止正常，没有长期停在“生成中”；历史内容保留，助手切换生效 |
| 本地文件与用户确认 | 在含中文、空格的测试工作目录里，让助手读文件、创建一个测试文件；再触发一次弹出选项的确认流程，各测一次确认和取消 | 文件内容正确；确认结果能传回助手并继续任务，取消后不会卡住或继续执行已取消的操作 |
| 飞书／Lark | 用已有账号进行文字问答和图片／中文名附件收发；执行一次需要授权的测试文档查询；重启后再查询、再发消息 | 收发、附件内容和文档查询正常；授权流程可完成，重启后能正常复用仍有效的授权 |
| Discord | 用测试账号从设置中完成一次新接入；首次私聊或群内 @ 机器人，再重启复测；已有账号也做一次问答 | 设置可保存，首次使用即可回复；重启后连接正常，无重复回复或串会话 |
| 钉钉及其他已配置 IM | 钉钉重点做文字、图片、文件收发；其余实际使用的平台各做一轮问答，重启后再问一次；有多账号时分别发消息 | 收发完整，无漏答、重复回复；消息进入正确的会话和绑定助手，账号间不串消息 |
| 模型与思考设置 | 普通模型完成一轮工具任务；切到 Kimi K3 或已配置的自定义 K3 别名，做多轮聊天和文件工具任务；修改思考设置后再问一次 | 切换生效，无模型／参数错误；工具执行后能继续回复，历史上下文和设置保留 |
| 设置变更与重新连接 | 禁用再启用一个已接入渠道／插件，保存后继续聊天和 IM 问答；再完全退出应用并打开 | 设置生效并保留；功能能恢复使用，没有重复连接、重复消息或持续重启 |

未使用飞书、Discord 等平台的测试账号，由团队提供专用测试账号补测；收发操作使用测试群、测试文档和测试文件。

**按实际使用情况补测**

| 功能点 | 最小操作 | 通过标准 |
| --- | --- | --- |
| 自装插件 | 调用一个已有自装插件；更新或禁用再启用，重启后再调用 | 插件仍可用，更新内容生效，没有一直使用旧版本 |
| MCP 与技能 | 调用一个已有 MCP 工具和一个常用技能 | 能发现并执行，结果正确，任务能正常结束 |
| 图片生成 | 在有测试额度的账号下生成一张图片并打开结果 | 生成成功，进度结束，结果可预览 |
| 记忆与定时任务 | 保存一条测试记忆，重启后在新会话查询；手动执行一个已有测试定时任务 | 记忆可查询，任务按原配置执行并产生结果，无重复执行 |
| Windows 路径 | 在带中文／空格的安装路径或 Windows 用户目录下，复测启动、工具和一个 IM 渠道 | 与普通路径下行为一致 |
| 其他发布平台 | 本次若同步发布 macOS／Linux，至少复测启动、聊天工具和一个主要 IM 渠道 | 基础流程与升级前一致 |

**重复重启观察**

原 QA 配置至少做 10 轮：完全退出再打开 3 轮、退出登录再登录 5 轮、渠道启停或保存设置后恢复使用 2 轮；优先复现此前出现约 3 分钟等待的操作。关闭窗口仅缩到托盘时，需要从托盘完全退出应用。

每轮记录两个时点：界面恢复可操作，以及发送固定短提示后收到首字。重新登录的人工输入／扫码等待单独记录；不要把这段时间计入应用恢复耗时。设置操作没有触发服务重启时，如实记为配置恢复场景。

建议验收标准：核心功能全部通过；同机同配置下，启动／重启恢复耗时的中位数较优化前至少缩短 50%，并且本轮不再出现约 3 分钟的长时间等待。首次启动和后续重启分别比较，不能用插件内部加载时间代替用户实际恢复时间。

每种场景记录中位数和最长一次。发生异常时，保留版本号、场景、开始时间、耗时、已启用渠道列表，以及应用导出的日志和录屏。
