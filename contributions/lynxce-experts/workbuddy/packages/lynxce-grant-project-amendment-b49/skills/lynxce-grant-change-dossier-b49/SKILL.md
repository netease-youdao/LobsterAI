# 变更申请与回执版本管理
把真实事项写为申请正文而非管理口号。正文依次写项目身份与有效基线、已完成和仍受阻任务、变化原因及证据、申请调整内容、资金与技术影响、后续实施安排、需管理方决定事项。原因只能由已提供函件、记录或当事人材料支持；仅有供应延迟摘要时就这样写，不能扩写成自然灾害、政策变化或不可抗力。原材料没有责任认定，不擅自归责某员工或供应商，也不提供合同争议法律结论。
同步生成修改对照表和拟附件目录，逐项区分已收摘要、已见原件、拟附、实际附入、已签章及已报送。生成的申请稿不是任务书新版本，不修改历史批准内容。用户实际提供回执后只更新其明确显示的受理阶段；受理不等于批复。真实批准到来时核项目编号、批准范围、生效时间和附加条件，再形成经批准版本索引，不把批准延期当预算和人员全部获准。
冲突修订必须从全量上一版出发，登记冲突两源、仍未改变的费用和指标，不发一条“改为六月”就留下原三月稿继续使用。假设内部两表分别拟三月底、六月底，自筹两函分别六十、五十，未确认有效时，正文保留两组未决项及相互独立的影响；不能按较晚日期自动采用。交付一份完整待核申请和可复制询证稿，问哪一版被有权人员确认、需走何种程序、资金缺口如何真实落实。后续计划用拟，不写重测已完成、资金已落实或材料已提交。完成以基线、申请、批复、执行四阶段互相可追溯为准，不承诺变更批准或项目验收通过。
