# 可复制接口文档模板

```text
接口名称／用途／读者／适用版本／证据状态：
准备：环境配置｜权限｜测试数据｜所需材料。
调用：方法｜路径｜请求头占位｜路径与查询参数｜请求体。
字段：名称｜位置｜类型｜必填｜默认｜范围单位｜空值｜来源。
成功：状态｜响应JSON｜字段解释｜分页与排序｜完成标志。
失败一：状态｜错误JSON｜原因｜下一动作。
失败二：状态｜错误JSON｜原因｜下一动作。
调用语义：副作用｜幂等｜重试｜超时｜限额｜未知参数。
首次接入：准备→最小调用→核对成功字段→按错误表排查。
变更：旧行为｜新行为｜兼容假设｜迁移步骤｜验证证据。
覆盖：已确认／冲突／待确认；关键问题最多三个。
```

## 已填假设示例：订单分页查询

以下是一份虚构但自洽的演示契约，未调用任何服务。方法 `GET`，路径 `/orders`，请求头写 `Authorization: Bearer <TOKEN>`。查询参数 `page` 为从1开始的整数，`size` 为1至100的整数，示例默认值分别为1和20。测试读者需有查询自己租户订单的权限；权限校验如何实现仍由真实系统材料决定。

请求示例为 `GET /orders?page=1&size=100`，成功状态假设为200，响应：

```json
{"items":[{"id":"demo_order_01","amount_minor":2500,"currency":"CNY"}],"page":1,"size":100,"total":1}
```

其中订单金额2500表示25.00单位货币，币种单独说明。为演示完整响应，上面只使用总数为1的结果；不要把这一条样例误称为返回了100条。另一组分页计算假设总数235，每页100，则页数向上取整为3页，分别100、100、35条；总数若在翻页过程中改变，此计算只适用于同一快照。

失败一假设为400，响应 `{"code":"INVALID_SIZE","message":"size must be 1..100"}`，输入 `size=0` 应修正参数，不重复原请求。失败二假设为401，响应 `{"code":"AUTH_REQUIRED","message":"valid token required"}`，应核对凭据是否配置及是否有效，不把真实令牌贴入排障资料。示例空结果为200且 `items=[]`、`total=0`；真实接口对超出页码范围的行为需按真实契约填写，不能照抄演示。

首次调用指南依次写确认环境和只读权限、准备测试订单、发送最小请求、检查状态与字段单位、按两类错误分别处理。版本变化示例是响应新增可选 `source` 字段：允许忽略未知字段的客户端通常无需修改，但严格反序列化客户端需要兼容验证。文档完成状态为“演示结构可审查，真实契约与运行验证待提供”，不会冒称已经发布。
