# 复业任务前置环路核查

面向临时闭店后的复业协调员与店长的独立小任务：复业任务前置环路核查。适用阶段为临时闭店原因已由负责人处理、计划复业前的任务依赖核对。最少事实输入为用户给定任务编号、前置边、完成证据与外部等待条件；交付依赖边表、环路清单与后继阻塞范围。核心方法：把前置到后继构成有向边，先核悬空编号再查环；只对无环且前置证据满足的任务列可启动，环内任务等待负责人拆解。输入仅接收用户主动提供的脱敏文本或表格摘录，记录来源代号与原文位置；不要求业务系统接入，示例不能补真实资料。

## 工作流程

1. 登记任务与前置边，不从任务名猜依赖。 接收时先登记来源、版本、对象范围和记录截点；若用户只给部分记录，交付已知范围并列最少缺项，不把没提供的数据补成零。

2. 核每条前置编号存在，外部条件单列。 对象编号与资料行号应分开，整理值不覆盖原值。重复引用是证据复用而不是新增业务对象，同名对象必须查身份关系再合并。

3. 沿前置关系回溯，重复到起点则记录完整环。 处理时按本任务方法逐项核查，事实、陈述、派生计算和建议分别标识。支持某一条件的证据不可自动扩展到其它条件。

4. 核环外前置完成证据，缺证据与未完成分开。 条件不全给局部成果，矛盾给双值及来源；请用户指定确认角色，不取平均、不选更有利数值，也不把询问草稿记为完成动作。

5. 列环路直接及间接受阻后继，去重任务计数。 复核应从来源重新取原值，检查单位、分母、版本和状态互斥性；已明确未知的字段保持未知，不以合计能对齐反推缺失事实。

6. 输出拆解问题，不自行删除负责人给定的依赖。 交付时保留仍未解决的行和下一核实动作，说明接收角色与完成凭据。新资料到来按原对象续版，人工确认与实际执行仍分开。

## 对象与资料门槛

- 没有前置不等于任务已完成。

- 自依赖A到A也算环。

- 外部批准不虚设完成时间。

- 悬空号不补成相近任务。

## 专属判断与异常分支

- 重复边不重复计阻塞任务。

- 环内外任务需分组说明。

- 并行任务只能在给定条件下讨论。

- 后继已做记录与前置冲突留例外。

## 输出验收与状态边界

- 时间仅用用户给定单位。

- 拆边需明确负责人确认。

- 解除阻塞不等于实际开工。

- 本任务不批准营业。

## 五类内容设计假设案例（非模型实测）

- 正常：假设A到B，B到C，A已完成而B待做。 预期：B可待启动，C受阻，共1个受阻后继。

- 缺资料：假设B前置写X，任务清单无X。 预期：悬空前置【待补】，不按字母猜任务。

- 矛盾：假设同一边一表保留一表删除，未说明生效版。 预期：保留边版本冲突，不自选无环版。

- 边界：假设A到B、B到A、B到C。 预期：环内2项、环外受阻1项，合计影响3项。

- 超出能力：假设要求擅自删环内任务立即营业。 预期：仅提出待负责人拆解，不批准开业。
