# 小组个人贡献与合稿协议

## 何时调用与最低输入
输入团队人数、任务依赖和预期作品栏目，输出角色卡、个人交付和合并规则。
只围绕本项任务制作一个可以被上层专家直接引用的中间成品。用户没有给出的条件以待补标记；可先按写明的假设生成样稿，再提出不超过三个会改变结果的问题。给每次输入分配材料编号，同一编号在本轮中保持含义不变，不能把推测写成材料事实。

## 具体制作方法
按任务对象分工，再安排交叉复核。每人必须拥有一个可独立保存的草稿，角色说明写到输入、动作和交付颗粒度。合稿时先统一事实口径，再处理取舍与表达；出现争议，先各写依据再比较，避免口头强势决定内容。设计角色轮换，让记录与表达工作不长期固定到某一成员。缺席时临时拆分未完成任务，已有贡献仍保留记录。

## 可复制的已填示例
已填四人角色为数据解释、计算、行动方案、表达组织。计算员交“三十乘十五除六十乘四等于三十升”，解释员核对次数与单位，方案员交两条行动和限制，表达员合成一页稿。合稿协议：“有冲突先回材料编号；无法确定列成待核；每次改数必须通知全部成员复算。”贡献表为姓名代号／个人稿编号／合稿使用位置／交叉复核对象。

## 修订与完成判据
不要按学生固定能力高低分配永久角色。三人组可合并表达与材料管理，但仍需三份个人判断。完成时公共作品每一核心栏有责任人，每人有可查的独立产物，并有缺席替补办法。
交付时同时给可直接使用的正文和一段使用说明，指出哪个条件变更会触发重做。引用本项成品时保留版本号和适用范围，不能只复制结论丢掉假设。遇到用户要求跳过必要输入，仍给可编辑草案，并把受影响位置显式标注，不扩展成未经授权的执行。完成意味着输入可以逐项映射到输出，示例能够手算或逐句核验，所有占位都已有用途说明；不把纸面设计写成已经获得现实反馈。

逐人产物守恒：四组×四人=16份个人产物。两批各有两个巡读组时，每批8人须各交一张反馈和反思，两批各类16张；组级站展记录每批2份、共4份。不得将组数和人数混计。


第四轮同次成品：复用包内schedule_ledger.py的具体人/动作/活动唯一ID与结果，正文、角色产物、议程和复制稿来自同一JSON。学习动作压缩、资源条件与未知执行回执分别保留，不把人分钟当课堂经过时间，不把本地测试当模型真实通过。
