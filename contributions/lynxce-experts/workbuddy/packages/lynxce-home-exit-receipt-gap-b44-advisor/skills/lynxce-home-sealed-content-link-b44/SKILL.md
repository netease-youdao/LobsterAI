# 封包件号回执关联

内部独立专项：只核封包内应返还件号到回执行是否一一可定位。用户为家政服务终止时的委托方记录员。输入只需既定包号、件号、封包日期及接收回执编号。此项按自己的证据键、方法和输出表工作，不以专家摘要替代专项交付，不依赖任何外部接入。

## 工作流程

1. 锁定本项任务：只核封包内应返还件号到回执行是否一一可定位。最少输入为既定包号、件号、封包日期及接收回执编号；先给材料范围和截止时点，超出本项范围的请求单独记录。

2. 按最少字段建立证据索引：以件号作为核对键、包号作为容器键，钥匙一串与钥匙单把采用清单原计量粒度；粒度不同先列不可比。

3. 建立对象与事件关系：列每件的清单位置、回执位置和双方日期，件号只出现在包级标题而非逐件行时标未开验。

4. 执行专项推演：查一件多包、一包多次接收与清单重复；复签同一包保留事件链，不把复签当成新增件数。

5. 检查专属异常与边界：输出可定位、缺回执、重复关联三类，冲突行不自动归给任何一包，待核结果返回公开返还任务。 对照缺资料与冲突案例，确认缺项没有被填成示例值。

6. 交付封包件号回执关联文本表与补证队列，逐格保留资料编号及状态。重新核正常与边界算式，给负责人确认入口；实际完成状态以用户后续反馈为准。

## 专项方法与证据顺序

- 以件号作为核对键、包号作为容器键，钥匙一串与钥匙单把采用清单原计量粒度；粒度不同先列不可比。

- 列每件的清单位置、回执位置和双方日期，件号只出现在包级标题而非逐件行时标未开验。

- 查一件多包、一包多次接收与清单重复；复签同一包保留事件链，不把复签当成新增件数。

## 专属异常和采用条件

- 工具自带套件不能按零件数量擅自放大清单数；有零件表才展开。

- 封口完整记录不能证明内部数量，内容确认与封口确认分字段。

- 换包必须有旧包至新包转移单，保留旧号停用时点。

- 件号敏感信息用代号，记录所需证据而不是索取开锁照片。

## 资料状态与交付复核

- 引用材料使用资料代号、版本和行号，事实摘录与推演结果分栏。未知值统一写【待补】；补证问题指出缺什么、为什么影响本项判断，以及用户应返回哪一格资料，不能仅泛称完善材料。

- 所有统计注明对象、单位及截止时点，记录数、唯一对象数与关联边数分开。计算从原始值逐步列算式，残差保留符号；不通过四舍五入隐藏冲突，零分母写不适用而非百分之百。

- 文本表是材料审阅草案。建议动作、用户确认拟执行、用户反馈实际完成采用不同状态；无反馈时不得变为完成。这里只用已给文字与表格手工推演，不声称已查询系统、通知人员或操作实物。

- 收到新增材料后只重算受影响对象，保留旧值、采用版本和修改理由。冲突未解决的对象不能挤入已确认集合；结束时检查每条输入有去向、每条判断有来源、每个未决项有最少补证动作。
