# 风险阻塞与变更评估

## 输入与分类
接收基线版本、任务快照、风险清单、会议纪要与变更申请。先记录资料时间、状态确认人和覆盖范围，再把条目分类：尚未发生但可能影响目标是风险，已经发生的是问题，需要外部条件的是依赖，主动改范围的是变更。四类不可互相替代，已经延期不能还称“可能延期”；用户材料只是担忧则不写已发生。负责人来自用户名单，未知写待指定。
风险要有触发条件、影响任务、观察信号、响应动作和复查节点，不能只有“注意沟通”。概率与影响可用用户约定等级；没有历史样本不编精确概率。排序优先考虑硬截止、验收阻塞和依赖传播范围，不给漂亮分值掩盖资料不足。当前状态必须有来源，不能声称已经监控系统。
## 方法一：变更影响沿依赖传播
拆变更为新增或删减交付物、工期、资源、预算与验收口径。先定位受影响任务，再沿后继传播；并行任务有时差不意味着关键路径无变化。工期估计需说明谁提供与何时确认；提议不等于批准。输出至少一个保持基线与一个接纳变更的方案，但不替用户选择批准。
完整假设样例：基线A2、B3、C4、D2、E1，B/C依赖A，D依赖B/C，E依赖D，总9工作日。C增加2天后为6天，A结束2、C结束8、D结束10、E结束11，变更后11天，影响2天。B仍结束5，不决定D开始。硬期限10天时缺口1天，候选是把新增字段移到后续版本、调整经用户证明可并行的部分或调整期限，不能凭一句“加人”把11写成10。
## 方法二：阻塞到恢复方案
用户说接口材料尚未收到，记录问题I01、材料请求、影响D联调与验收、责任人和最迟需要时间。只给可复制的催办草稿，不发消息；未收到用户回传不把状态更新为已解除。已有任务快照显示完成而会议说未交报告，要比较来源时间与“完成”定义；快照更新晚也未必证明报告已交，需证据确认。
恢复方案至少列当前事实、待核假设、下一动作、负责人、期限和回退条件。没有期限日历用相对工作日，不能凭系统日期自行计算节假日。任务待批准时写待决，不冒充“项目经理已同意”。外部供应条件未确认时对工期给条件式结论而非确定日期。
## 冲突与超范围处理
两位用户对范围口径不同，输出冲突交付物和各自要求，让有权确认的人裁决，不取折中范围当批准。资源与期限冲突分别列，不一律归因于员工效率。材料不足时可继续整理不受影响任务，阻塞部分单列。要求伪造进度、隐瞒已发生问题或自动提交审批时拒绝对应行为，交真实状态和待批准草稿。
## 可核对输出
风险问题表：ID｜类型｜材料出处｜触发/事实｜影响任务｜行动｜责任｜复查条件｜状态。变更表：申请ID｜原范围｜新范围｜基线｜算式｜资源影响｜验收变化｜候选方案｜批准状态。差异表列工期从9到11、增加2和期限缺口1，不只写“略有影响”。接纳变更后交计划技能重排，交交接技能更新验收材料与纪要。
## 验收
检查每个问题有事实出处，每个变更有传播任务与算式，每个批准状态有用户确认记录。没有真实项目系统接入不宣称实时跟踪、自动催办或写回，所有动作是材料与草稿。零工期批准节点仍可阻塞流程，未批准不算已完成。本技能不保证按期交付或代替工程签章，样例为假设静态评估。
### 复核顺序
先核需求与基线，再核任务前置、工期、资源与验收证据，最后核纪要和行动项。用户对方案表示兴趣不等于批准变更，批准记录与执行状态分列。新基线生效后同时更新计划、风险和交接期限，旧版留版本标记。任务已做但没有验收记录时不能写项目已交付，未知负责人和未确定日历都在结论中提示。

## 本领域材料模板
参照 `references/delivery-template.md` 的字段交付，不把空字段填成已核实。用户需确认的值标为待确认；未提供资料保留原始缺项。模板只用于本技能，不代替方法中的决策分支。


## 增补实例：风险触发与问题解除
风险“外部材料可能晚到”写清需要材料的任务、最迟相对节点和用户提供的预计到达时间。到节点仍未收到，转为问题，不继续用模糊风险表。解除需要材料已收到且满足使用条件的证据，只收到空目录不算解除。风险等级若用高、中、低，给用户约定的判定依据，不随意填百分之八十概率。
变更请求说“只多一个字段”，但验收需追加一个导出场景和说明文档，就把字段、联调与验收三处范围都列入影响。新增工期由用户负责人员估计确认，若缺估计可列影响任务而暂不给总天数。成本缺报价时标未知，不凭简单程度填零。某项新增工作能与旧任务并行，需要明确产出独立、人员有容量和接口可用，不把并行作为默认。
两份快照显示不同状态，先查更新时间与完成定义。最新快照若导出自滞后系统，可能仍不代表现场，故确认记录比单纯文件时间更重要。用户说“先写完成，后面补报告”时拒绝把未验收改成完成，可写开发完成、验收待报告两种状态，保留真实覆盖范围。对恢复行动的负责人和期限没有信息时待指定，不发送催办或假称已协调。
恢复方案要有观察点和回退条件。若临时绕过某非核心功能，列影响用户场景与验收条件变更，必须待用户批准；不能把绕过项从问题清单删除。批准方案后同步新基线、风险与交接内容，未批准时保留原基线和候选，避免用户拿到两套混用的期限。所有决策来源回到用户材料，不冒充项目授权人。
