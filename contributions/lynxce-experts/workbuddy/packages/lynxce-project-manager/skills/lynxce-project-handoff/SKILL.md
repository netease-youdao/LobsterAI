# 会议决议与验收交接

## 方法：把发言、决议和行动分开
接收用户会议记录、参会名单、项目基线、交付物与验收标准。登记会议日期、记录覆盖范围和材料来源，只有明确决定及决策人可记决议，提议、猜测和有条件同意都要保留状态。不要把“应该可以”“先看看”改成已批准。人名与角色只取用户材料，没有责任人就待指定，不能凭岗位常识派任务。
会议纪要先给结论、阻塞和需要决策的一项，再按议题组织事实与动作。逐条将行动项连到决议或未决问题，写动作、负责人、期限、产出和验收人。期限没有日历时用相对节点；消息草稿只供用户复制，不写“已经通知”。缺少录音后半段时说明仅覆盖提供范围，不声称完整会议纪要。
## 流程一：会议记录到行动项
提取明确事实，例如“联调报告未交”，和提议，例如“导出字段可以放二期”。标事实F01、待决D01，再给行动A01。按用户原话记录范围和条件，有多种解释时并排候选，不选更好看的一种。纪要定稿前用户需确认关键决议、责任与期限；其余不影响推进的描述可先形成草稿。
完整假设样例：材料写“产品负责人明天补字段定义，是否二期安排等负责人确认，接口联调报告还未提供”。输出F01联调报告缺失；D01新增字段二期安排待决；A01产品负责人提供字段定义与验收样例，期限“明天”需按用户会议日期及日历确认；A02联调负责人提供报告，负责人未给则待指定。不能把D01写为已经移至二期，也不能凭“明天”自动生成当前系统日期。
## 流程二：交付物到验收交接
根据计划技能给的交付物树列验收资料、确认人和通过条件。每一项产出要能对应明确材料，例如字段定义表、测试摘要、培训文档、问题清单，而不是“客户满意”。用户业务包含专业领域时只做流程和资料交接，不出具法定验收或签章结论。未有实际回传资料时实际结果填待验收，静态计划不能替代实际完成状态。
完整假设样例：D联调产出为联调报告R01，E用户验收1工作日，前置D已交报告且用户确认测试范围。交接表给“R01是否包含接口、场景、结果与未解决项”，通过条件由用户提供；如果只是报告目录没有结果，就列缺项。基线9天，若C增加2天到变更后11天，交接期限同步到E[10,11)，旧E[8,9)标为旧版，不能在不同页维持两种日期。
## 冲突、边界与回退
任务表写完成但验收人未确认时区分内部完成与外部验收，不一律标关闭。验收口径版本不一致先请用户定版，不把后来新增标准强加到旧完成记录。0天批准节点未批仍列阻塞。用户要求删除未解决问题以便通过交付时拒绝隐瞒，改为已知问题与接受条件表；接受条件必须由用户指定确认人批准，本技能不代表批准。
延期交接给未交材料、影响、责任、下一时间和回退方案，说明未知项，不伪造签收。交接需要系统写回或发邮件时只给字段映射及文本草稿，没有接入也不声称已提交。实际材料含敏感信息只引用最小必要范围，匿名参与者仍可用用户定义ID回查。
## 输出与验收
纪要表：议题｜材料ID｜事实｜决议｜待决｜行动ID；行动表：动作｜负责人｜期限来源｜产出｜验收人｜状态；交接表：交付物ID｜基线版本｜证据｜通过条件｜实际结果｜未解决项｜确认记录。验收检查每个完成有证据、每个行动有负责人状态、每个变更同步基线、每个未决没有被改成已批准。样例是静态预期，不代表会议实际发生或模型运行验证，真实签收与专业签章由有权人员处理。
### 复核顺序
先核需求与基线，再核任务前置、工期、资源与验收证据，最后核纪要和行动项。用户对方案表示兴趣不等于批准变更，批准记录与执行状态分列。新基线生效后同时更新计划、风险和交接期限，旧版留版本标记。任务已做但没有验收记录时不能写项目已交付，未知负责人和未确定日历都在结论中提示。

## 本领域材料模板
参照 `references/delivery-template.md` 的字段交付，不把空字段填成已核实。用户需确认的值标为待确认；未提供资料保留原始缺项。模板只用于本技能，不代替方法中的决策分支。


## 增补实例：会议原话的不同状态
原话“测试可能明天结束”只支持预计，不支持完成；“我确认该版本可以进入验收”可记明确决定，但仍需是谁确认以及确认哪个版本。一个议题中有人赞成、有人提出条件，先列赞成与条件并存，不能按多数发言自动生成批准。没有完整参会记录时只用提供的角色，不虚构名单、签名或到场证明。
行动项“研发处理一下”需要补具体对象、产出和期限。可改为待确认草案“联调负责人补充接口异常场景结果，提交报告给验收人”，但负责人和期限必须用户确认。行动项做到不代表验收通过，报告提交、内容完整、验收确认三个状态分别记录。纪要中未决问题保持可见，不把它们移到附录后在摘要声称没有阻塞。
交接范围内若有培训、运行说明和已知问题清单，应给对应文件ID，用户只交核心文件时其他项待补。项目内容涉及专业工程时，交接表中的“确认人”只是用户的流程角色，不能由本技能冒充有法定签章权的人。用户需要正式工程验收时只准备已提供资料与缺口，不出具替代签章的报告。
回传材料出现旧基线日期和新变更日期混用时，在版本差异表指明哪些位置待同步，不取较早日期美化进度。需要外部发信或系统提交时提供草稿及字段映射，由用户在真实环境操作，不把生成文件标为已送达。最终交接保留未解决项、用户接受条件和确认记录，不把未回复当接受。内容复核完成只说明草稿可审阅，不说明现实签收已经完成。
