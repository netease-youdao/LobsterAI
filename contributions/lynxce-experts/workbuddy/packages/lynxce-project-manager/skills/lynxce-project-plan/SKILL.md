# 交付物拆解与依赖排程

## 方法：从目标拆成交付物
接收需求版本、交付目标、验收人、范围、硬期限、人员可用性和日历。先写范围内与范围外，再把目标分成可验收的交付物；每个交付物至少对应一项输入、动作、产出和证据。任务名称写动作与对象，例如“形成字段定义并取得用户确认”，不写“推进项目”。用户名单里没有负责人就待指定，不假定某部门有空。工期是估计工作时长，历时还会受资源、依赖与等待影响，两者不要混用。
为任务建立唯一ID，记录前置任务ID和关系。默认完成到开始关系，只有用户提供证据才允许并行或重叠。审批可以0天里程碑但状态仍需确认，不能绕过批准。日历缺失用相对工作日，不制造实际日期；日期范围含端点还是半开区间需说明。资源同人多任务时另做冲突检查，不能仅凭依赖图宣称资源可行。
## 流程一：依赖排程
先检查任务ID唯一、前置ID存在和依赖无环。按前置最晚结束确定开始，再加任务工期得结束；从最终节点倒算允许的最迟结束与开始，计算时差。未知工期保留未知，不能当0。关键路径代表在当前假设下决定总工期的链，不是最重要业务任务的列表。输出并行前提，避免用户误读排程为已确认交付承诺。
完整假设样例：A需求冻结2天，B界面3天、C接口4天均依赖A，D联调2天依赖B/C，E验收1天依赖D。工作日0起，A[0,2)、B[2,5)、C[2,6)、D[6,8)、E[8,9)。总工期9天，路径A-C-D-E=9，另一路A-B-D-E=8，B时差1天。B和C需不同人员或用户明确并行容量；同一人不能同时满负荷做两项，资源重排后工期不能沿用9天。
## 流程二：期限差距到选择方案
用户期限8天时，差距9−8=1天。先列关键路径上哪些任务有可核的压缩空间、哪些范围可延期，再给用户选择。不能直接删验收或把工期都乘0.8。增人是否有用取决于任务能否拆分和交接成本，用户未给证据时只作为候选条件。客户验收未安排人时即便图上有1天验收，也属于责任阻塞。
为每个方案写改变范围、工期、资源、验收和新风险；将需批准项交给变更技能评估。用户确认后形成新基线版本，不覆盖旧计划而失去差异记录。完成计划之后交给交接技能生成里程碑证据，不以任务全排完作为交付完成。
## 缺项、冲突与边界
需求版本冲突先列材料来源与影响交付物，再由用户确定基线。循环A依赖B、B依赖A要输出A-B-A环并停止工期计算。0天节点不能消除其前置与批准状态。任务“已完成”没有产出证据时保留待确认，不把剩余工期归零。无团队可用性时给逻辑排程并标资源未核，不用“按期可交付”表述。
## 输出模板与核验
交付物树表：目标｜交付物ID｜证据｜验收人｜范围；任务表：ID｜输入｜动作｜产出｜前置｜负责人｜工期｜最早/最迟时间｜时差；期限差距表：基线｜硬期限｜差额｜选择｜条件。核对所有前置有来源、并行有容量假设、每项有验收、日期口径一致。任务与会议状态全部来自用户材料，不自动查询或写回项目系统。不保证真实工期，不替代工程专业签章，样例只是静态依赖计算。
### 复核顺序
先核需求与基线，再核任务前置、工期、资源与验收证据，最后核纪要和行动项。用户对方案表示兴趣不等于批准变更，批准记录与执行状态分列。新基线生效后同时更新计划、风险和交接期限，旧版留版本标记。任务已做但没有验收记录时不能写项目已交付，未知负责人和未确定日历都在结论中提示。

## 本领域材料模板
参照 `references/delivery-template.md` 的字段交付，不把空字段填成已核实。用户需确认的值标为待确认；未提供资料保留原始缺项。模板只用于本技能，不代替方法中的决策分支。


## 增补实例：资源可行性与逻辑可行性
在九天的示例计划中，界面与接口并行依赖不同人员。若用户说明两项由同一名工程师满负荷承担，顺序执行界面三天后接口四天，则需求两天之后共七天，再加联调两天与验收一天，合计十二工作日。顺序倒置也同为十二，在无其他约束时只改变中间节点；不能为了维持原承诺继续标九天。额外人员是否能独立做界面需用户确认能力与交接，不以人数加倍直接将工期减半。
如果其中一项有等待用户确认的节点，等待时长不能默认为零，单独列依赖与最晚需要时间。用户未提供工作日历时九天或十二天都只是相对工作日，不自动换算月底。验收人只有周五可用可能延长实际日期，需实际日历后再计算。任务工期为零的里程碑可以表达批准完成，但未批准时仍阻塞后继。
交付物拆解要与验收粒度一致：“完成接口”应说明有哪些接口、请求与响应样例、异常条件和用户认可证据；“写文档”应说明文档对象与读者。用户只有抽象目标时先给交付物建议和待确认，不虚构技术实现或安排具体员工。一个交付物多个任务时仍只有一个最终验收入口，不能把局部完成当整体交付。
版本冻结前用户添加新范围，先记录变更申请并交影响技能评估，而不是静默追加到任务表造成旧期限看似不变。输出显示基线估计、待确认资源、日历状态与范围批准状态。计划完成意味着可追查每条输入和依赖，不意味着项目已实际按此执行；真实状态更新依赖用户材料，不用想象补进度。
