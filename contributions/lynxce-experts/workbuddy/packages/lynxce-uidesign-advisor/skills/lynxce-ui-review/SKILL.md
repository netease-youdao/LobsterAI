# 规范token整理

## 触发条件与交付边界

当前任务进入“规范基线与组件映射”时使用。只负责这一环节，其他环节通过证据编号交接。按组件与用途登记规范而非盲目统一尺寸，例外要列作用范围与批准证据，后续走查只能引用选定版本。

## 必要输入

设计规范版本、页面截图或尺寸记录、页面目标、目标设备宽度、交互状态清单、已有颜色和字阶约束、用户提供的键盘或读屏检查记录。只引用与本环节有关的字段；其余材料记录存在而不据此扩展结论。输入不足时先交付结构与缺口，不把占位解释成事实。

## 操作方法

先从用户已有规范提取间距、字阶、语义颜色、圆角阴影四组约束，并列来源和使用范围。四或八的倍数可以是候选梯度，不能在没有用户认可时强迫旧系统重写。字号与行高字重成组登记，颜色按用途命名，同一个危险提示不混用多个语义。对已有组件登记例外原因与允许范围，不把历史例外默认为新规则。页面目标决定信息优先级，风格好恶不算缺陷。缺规范时交付候选规范与待确认项，走查报告标为建议比较，不能伪称偏离已批准规范。

规范表先固定语义再列数值。间距以容器、元素组、组内三个层级登记，不能把所有间距统一成八像素。字阶按信息角色而非页面名字命名，标题、正文和注释分别记录字号行高字重。颜色给背景、文本、边框和状态用途，每个用途绑定版本，防止同一色值在危险和主操作中混用。圆角和阴影是候选档位，既有规范允许例外时写明例外组件及原因。输出新增、保留、待确认三组变更，建议基线未经用户确认不得标为已批准设计系统。

## 证据与判断

截图支持可见的布局判断，不能证明键盘、焦点或加载状态。标记每张截图的尺寸与版本，将设计值、用户量测值和建议值分列；没有源文件不声称已测出字体或真实点击区域。

主操作无法辨认或被遮挡时列阻塞项；只有截图的状态只能给静态结论。设计稿与规范冲突时先确定用户选用版本，不能任意挑一个当正确值。

判断表以问题为行，不以文件为行。同一个材料支持多个问题时引用相同编号，不能复制后冒充独立证据。本环节每项建议写清原状态、建议状态和等待用户确认的依据；用户只提供计划时输出仍为计划。

## 异常处理

截图无尺寸时不给精确像素误差；低清图片只列不可判断项；设计要求与可读性冲突给替代层级，不以风格判断替代可用性证据。

仅一张首页截图没有规范：提出候选基线和可见问题，交互状态标未验证。

设计稿边距16但已批准规范24：记录版本冲突并要求选定基线，不偷偷改规范。

按钮44×44刚达项目目标：记录尺寸满足，焦点和相邻重叠仍需独立验证。

要求声称已操作所有设备并认证无障碍：只出静态报告和真实需执行的检查清单。

## 可复算交接样例

假设视口宽360像素，左右边距各16像素，内容宽=360-16×2=328像素。两列卡片间距8像素，每卡宽=(328-8)÷2=160像素。按钮实际点击区40×40，项目目标44×44，两维各少4像素；扩大点击区需要检查与邻近区域是否重叠，不能单纯放大图标。若三个标签各110像素且间距8像素，总宽=110×3+8×2=346像素，大于328像素18像素，应换行或调整信息布局。

此样例为假设静态核对，未实际模型运行。当前技能提取与“规范基线与组件映射”相关的口径，并将其他环节的结果作为注明来源的交接字段，不宣称自己完成整个项目。计算保留原始输入与单位，比例比较注明百分点或相对变化，舍入在末步；如果任一输入被用户改动，应重新复算而非沿用结果。

## 实质模板与交付

使用 [本环节模板](references/templates.md)，字段为：组件｜状态｜规范版本｜token｜实际值证据｜差异｜影响｜优先级｜复核方法；设备宽｜内容宽｜断点｜长内容｜溢出｜待验证交互

交付顺序为本环节结论、逐项证据、条件性建议、未确认事项和下一环节所需输入。对每一个关闭项写能核验的完成依据，对每一个开放项写具体补件或复核问题，不填写虚构责任人或日期。按组件与用途登记规范而非盲目统一尺寸，例外要列作用范围与批准证据，后续走查只能引用选定版本。

## 独立复核步骤

先对照原始材料核引用位置和版本，再逐项检查“规范基线与组件映射”的处理是否改变用户事实；最后以异常、边界和能力限制三组输入审查结论。复核问题必须可以由用户用现有材料回答；无法回答的记录为待确认。复核结果分为依据充分、证据不足和口径冲突。依据充分的判断需要列出具体问题编号，证据不足的判断不得标为已验证，口径冲突的判断需要保留两种条件结论。本环节以可追溯的判断表交接，不向用户保证后续环节或外部流程必然成功。
