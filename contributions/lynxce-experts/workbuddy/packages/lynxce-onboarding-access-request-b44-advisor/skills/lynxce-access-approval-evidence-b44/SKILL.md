# 入职权限审批链缺件卡

本任务服务人事经办、用人主管与账号审批协调员，独立交付“入职权限审批链缺件卡”。只以用户提供材料完成下列核查，最小输入见第一步。这是专门中间成果，可单独使用；不重复公开技能整套输出。资料不足时先交可确认部分和精确补件问题。

## 工作流程

1. 接受申请编号、要求的审批节点、各节点资料及范围，最少一份申请与明确节点要求。

2. 以申请版本和资源范围关联证据，旧申请的审批不自动沿用到新增权限。

3. 逐节点区分已收件、明确批准、明确拒绝和未回应；截图已读或聊天收到不算批准。

4. 核批准人角色是否与用户要求相符，缺身份依据标待核而非自行判其有权限。

5. 统计同版本有效批准节点数及缺件节点，拒绝节点单独阻断，不用多数节点通过覆盖拒绝。

6. 输出节点缺件卡和补证原句，最终授权状态仍需用户反馈，不代催消息或模拟审批。

## 任务专属规则

- 批准证据应明确范围，口头可以记录为用户主张但不等于指定书面证据。

- 改了资源范围即触发对应节点重核，无关节点可保留旧证据及适用说明。

- 审批时刻早于申请版本产生时刻应核关联，不自动认定证据有效。

- 拒绝与未回应是不同状态，不能都归资料缺失等待开通。

## 资料定位与事实等级

- 每条原始材料分配来源编号，保留原文与采用版本。示例是假设资料，不写入实际输入空白；用户只需提供会影响本项成果的字段，未知值统一填【待补】，空白与零区别处理。

- 每条结论明确是用户记录、计算结果、候选判断还是待人工确认。原材料状态与建议动作分开列，不用已处理、已通过等用语替代缺失证据；没有反馈的环节保留待核状态。

- 同一对象出现两份互斥记录时并列原值和来源，不按较新日期自动取舍。指出哪一个字段会改变结果，并给出需补充的最小证据；不平均文本冲突，也不删除不利记录。

- 复算前确认计数对象、单位及分母，所有比率同时提供分子和分母。零分母写不可计算，展示百分比保留两位小数；不同范围的数量不能为了凑合计而直接相加。

## 交付复核与变更

- 表格中每个异常给出具体受影响行、待补字段、经办角色与解除条件，建议只到文本资料层。用户没有实际系统记录时不假称已执行、读取后台或联系其他人。

- 收到补证后先确认对应对象和版本，再重算受影响行及汇总，旧版与新值都保留。对未受影响行维持原证据范围，避免局部补充被误读为全量验证或全流程成功。

- 输出前核对原记录数、可分析范围、排除原因和结论状态之间是否一致，每个输入都有去向。资料质量检查只支持本份草稿，不证明实际业务效果或第三方认可。

- 超出任务范围时交付可完成的资料部分，并写需要用户指定人员处理的具体事项。不提供医疗诊断、财税或法律专业结论，不虚构账号接入、现场观察或外部工具能力。

## 五类假设验收案例

- 【假设案例，未模型实测】正常：输入三节点仅主管批准，一节点收到，一节点未回应。 预期：有效批准1/3=33.33%，其余2节点待证。

- 【假设案例，未模型实测】缺资料：输入不知道本项需哪些审批节点。 预期：节点分母待补，不以现有回复数代替。

- 【假设案例，未模型实测】矛盾：输入申请v2权限扩大，审批证据只写v1。 预期：保留旧批准范围，新范围待核。

- 【假设案例，未模型实测】边界：输入3节点中2批准1拒绝。 预期：仍有拒绝阻断，不以多数批准判可开通。

- 【假设案例，未模型实测】超出能力：输入要求代主管批准并催发聊天消息。 预期：给人工补证草稿，不代签或发消息。
