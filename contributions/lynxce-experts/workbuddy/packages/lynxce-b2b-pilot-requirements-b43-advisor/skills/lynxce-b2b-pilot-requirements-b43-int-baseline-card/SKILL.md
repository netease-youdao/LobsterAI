# 客户验证指标基线核对

本内部能力只处理客户验证指标基线核对，输入为客户指标定义、原始样本、异常剔除规则；输出为基线口径卡与不可比较项。独立保留依据，不代替公开任务的完整交付。 依据仅限用户提供的业务资料。每项事实注明资料编号、版本与日期，缺项写【待补】，推测与确认事实分栏。对冲突输入保留原值和来源，不用示例填补真实空白。只交付可复制的文本和表格；不声称已联网取得数据、连接系统、发送消息、修改记录或执行现场操作。不作资质、认证或签章结论。

## 工作流程

1. 接收客户指标定义、原始样本、异常剔除规则，明确本轮对象、截至时刻、资料版本与用户希望解决的问题；缺少核心资料先给待补表，保留能够核对的部分。

2. 按任务对象建立唯一记录键，拆分事实、声明与未知条件；逐条关联原文及原值，重复、缺漏与来源冲突单列，不静默覆盖。

3. 把客户指标的起点终点写成事件，等待、返工与人工复核是否计入分别确认，不能只摘取软件运行时间。使用表格保存比较口径、数量单位和适用范围，方法无法实施时说明具体缺少哪一项输入。

4. 保留原始样本总数及剔除清单，异常剔除须依据事先确认规则，不能看到坏结果后临时删样本。对存在分歧的条目提出可回答的确认问题，条件足够才推进，不把未确认的假设转成决定。

5. 结合领域方法复核异常和变更影响，给出待核、补证后可继续或需重新对齐的分支；把责任、期限与验证证据逐项列入。

6. 交付基线口径卡与不可比较项，逐行复算数字与单位，检查来源、版本、状态和未闭环项；由用户负责角色复核后使用，后续资料按新版本续接。

## 对象与口径方法

- 把客户指标的起点终点写成事件，等待、返工与人工复核是否计入分别确认，不能只摘取软件运行时间。

- 保留原始样本总数及剔除清单，异常剔除须依据事先确认规则，不能看到坏结果后临时删样本。

- 平均值、总量、比例分别计算，缺失记录不填零；不同订单类型分层展示，避免订单结构变化冒充性能提升。

- 用同口径反算总量，记录测量者和日期，用户没有提供原始数据时仅交付待补卡，不伪造测量。

## 证据与决策方法

- 接收客户需求原句与初访结论，按业务场景拆分对象、触发条件、期望结果和不适用边界；“更快更好”属于不可检验需求，必须拆成具体测量对象。

- 区分采购方、使用方和验收方的观点，记录每句话来自哪个角色；意见多并不代表优先级高，用户指定最终确认人之前不擅自合并为客户一致要求。

- 对异议只追问影响验收的具体条件，分类为范围、口径、样本或责任问题；预算、竞品报价与商机健康度不在本次诊断中评分，避免泛化成销售跟进。

- 形成联合验证准备结论：资料足够、补齐后可准备或范围尚不一致；结论不是产品验收通过，不承诺客户收益，不把双方讨论当成已签署协议。

## 异常与交付复核

- 核对表中每项判断必须能回指输入记录，不同来源相互矛盾时列出冲突双方与待确认问题；输入没有证明完成的事项保持待核，不能写为事实。

- 检查每行单位、分母、时间窗口与版本是否一致，先复算再解释；零值、空白、未发生是三种不同状态，不把缺失字段默认为零。

- 输出时先列影响与未满足条件，再给逐行证据与下一步动作；责任人与复核人没有提供就留待补，不自行捏造人员或补上批准结论。

- 新资料到来时更新差异与有效范围，保留原表版本和修改原因；旧记录仅作历史依据，不把之前的假设结果当本次真实业务数据。

## 假设案例

假设10笔耗时总计600分钟，其中2笔等待合计180分钟；全部样本平均60分钟，若事先约定剔除这2笔，则余8笔总计420分钟，平均52.5分钟。两个口径不能直接比较，应保留剔除原因与原始60分钟。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
