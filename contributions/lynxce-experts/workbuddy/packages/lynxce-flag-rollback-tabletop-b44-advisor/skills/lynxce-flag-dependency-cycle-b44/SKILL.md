# 功能开关依赖环路核查

本任务服务发布协调员、值班开发与演练主持人，独立交付“功能开关依赖环路核查”。只以用户提供材料完成下列核查，最小输入见第一步。这是专门中间成果，可单独使用；不重复公开技能整套输出。资料不足时先交可确认部分和精确补件问题。

## 工作流程

1. 取开关编号、边方向定义、环境及手册顺序，至少提供一条依赖及其方向含义。

2. 将必须先关闭X再关闭Y写成X到Y的有向边，不用字段名称猜箭头；不同环境分图。

3. 逐节点列前置集合，去除重复边但保留来源，记录孤立节点与引用缺失节点。

4. 从无前置节点开始逐轮移除，剩余节点有环或依赖缺件时列出具体路径，不能随意破环。

5. 将能形成的偏序与手册逐项比对，无依赖的节点允许多种顺序，避免误报唯一正确顺序。

6. 交付环路路径、可安排节点与待确认边；这只是资料图核查，不证明运行时调用关系。

## 任务专属规则

- 边方向必须用先后动作描述，依赖一词不足以明确回退顺序。

- 开关相同名字但环境不同不合并节点，避免测试图污染生产图。

- 无边不表示无实际依赖，只表示用户未给，结论保留资料范围。

- 环内节点全部阻断，环外独立节点可单列可演练范围。

## 资料定位与事实等级

- 每条原始材料分配来源编号，保留原文与采用版本。示例是假设资料，不写入实际输入空白；用户只需提供会影响本项成果的字段，未知值统一填【待补】，空白与零区别处理。

- 每条结论明确是用户记录、计算结果、候选判断还是待人工确认。原材料状态与建议动作分开列，不用已处理、已通过等用语替代缺失证据；没有反馈的环节保留待核状态。

- 同一对象出现两份互斥记录时并列原值和来源，不按较新日期自动取舍。指出哪一个字段会改变结果，并给出需补充的最小证据；不平均文本冲突，也不删除不利记录。

- 复算前确认计数对象、单位及分母，所有比率同时提供分子和分母。零分母写不可计算，展示百分比保留两位小数；不同范围的数量不能为了凑合计而直接相加。

## 交付复核与变更

- 表格中每个异常给出具体受影响行、待补字段、经办角色与解除条件，建议只到文本资料层。用户没有实际系统记录时不假称已执行、读取后台或联系其他人。

- 收到补证后先确认对应对象和版本，再重算受影响行及汇总，旧版与新值都保留。对未受影响行维持原证据范围，避免局部补充被误读为全量验证或全流程成功。

- 输出前核对原记录数、可分析范围、排除原因和结论状态之间是否一致，每个输入都有去向。资料质量检查只支持本份草稿，不证明实际业务效果或第三方认可。

- 超出任务范围时交付可完成的资料部分，并写需要用户指定人员处理的具体事项。不提供医疗诊断、财税或法律专业结论，不虚构账号接入、现场观察或外部工具能力。

## 五类假设验收案例

- 【假设案例，未模型实测】正常：输入边A→B、B→C，D独立。 预期：三层{A,D}/{B}/{C}，不是唯一线性顺序。

- 【假设案例，未模型实测】缺资料：输入箭头未定义先关还是先开。 预期：方向待补，不做排序。

- 【假设案例，未模型实测】矛盾：输入图A→B，手册B先于A。 预期：列顺序冲突与两份来源。

- 【假设案例，未模型实测】边界：输入A→A自环。 预期：单节点自环同样阻断，不因节点少而忽略。

- 【假设案例，未模型实测】超出能力：输入要求扫描线上配置自动纠正依赖。 预期：只核给定边表，不扫描或改配置。

## 假设案例

本例全部为假设，未作模型实测。假设边A→B、B→C、C→A构成环，D无前置，节点共4个。首轮可移除D，剩3个；循环路径A→B→C→A，不存在覆盖全部4节点的有效顺序。若负责人删C→A并给新版依据，层次为{A,D}、{B}、{C}，共3层，A和D可以交换。
