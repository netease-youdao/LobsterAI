# 功能开关回滚桌面脚本

本任务服务发布协调员、值班开发与演练主持人，独立交付“功能开关回滚桌面脚本”。只以用户提供材料完成下列核查，最小输入见第一步。成果用于代课、演练、仲裁、审稿或申请的人工决策，不替代实际执行。资料不足时先交可确认部分和精确补件问题。

## 工作流程

1. 收集开关名、环境、租户范围、默认态、批准手册与演练目标；缺环境时不得生成跨环境操作建议。

2. 把每个开关的启停含义与相关缓存或依赖写成状态图文字，关闭并不默认恢复历史数据。

3. 按用户阈值定义触发条件、连续窗口和样本数，区分大于及大于等于，未知指标不猜监控可用。

4. 用提供的假设事件依次推演识别、确认、回退和观察，记录模拟时刻，不伪装真实监控告警。

5. 核手册前置条件、观察时长和结束条件，未给已验证回退方法只输出脚本占位及补证。

6. 交付桌面卡、停止条件和人工决策点，标每一步演练预计产物；无真实执行反馈不标已回滚或演练通过。

## 任务专属规则

- 开关关闭可能只影响新请求，旧会话按用户资料单独设观察对象。

- 数据写入回退和功能流量回退分开，不能用关闭开关保证数据自动还原。

- 触发阈值由用户给定，脚本数值为明确假设，不作为生产默认阈值。

- 演练时钟与真实时间分栏，桌面推演耗时不能作线上恢复能力承诺。

## 资料定位与事实等级

- 每条原始材料分配来源编号，保留原文与采用版本。示例是假设资料，不写入实际输入空白；用户只需提供会影响本项成果的字段，未知值统一填【待补】，空白与零区别处理。

- 每条结论明确是用户记录、计算结果、候选判断还是待人工确认。原材料状态与建议动作分开列，不用已处理、已通过等用语替代缺失证据；没有反馈的环节保留待核状态。

- 同一对象出现两份互斥记录时并列原值和来源，不按较新日期自动取舍。指出哪一个字段会改变结果，并给出需补充的最小证据；不平均文本冲突，也不删除不利记录。

- 复算前确认计数对象、单位及分母，所有比率同时提供分子和分母。零分母写不可计算，展示百分比保留两位小数；不同范围的数量不能为了凑合计而直接相加。

## 交付复核与变更

- 表格中每个异常给出具体受影响行、待补字段、经办角色与解除条件，建议只到文本资料层。用户没有实际系统记录时不假称已执行、读取后台或联系其他人。

- 收到补证后先确认对应对象和版本，再重算受影响行及汇总，旧版与新值都保留。对未受影响行维持原证据范围，避免局部补充被误读为全量验证或全流程成功。

- 输出前核对原记录数、可分析范围、排除原因和结论状态之间是否一致，每个输入都有去向。资料质量检查只支持本份草稿，不证明实际业务效果或第三方认可。

- 超出任务范围时交付可完成的资料部分，并写需要用户指定人员处理的具体事项。不提供医疗诊断、财税或法律专业结论，不虚构账号接入、现场观察或外部工具能力。

## 五类假设验收案例

- 【假设案例，未模型实测】正常：输入阈值>2%连续两窗，第3、4窗各25/1000。 预期：第4窗末触发；模拟总时长3+2+5=10分钟。

- 【假设案例，未模型实测】缺资料：输入没有开关环境与作用租户。 预期：只出范围补件单，不安排回退步骤。

- 【假设案例，未模型实测】矛盾：输入手册写先关A，依赖表写A关闭须B先停。 预期：保留两种顺序，列依赖冲突待负责人确认。

- 【假设案例，未模型实测】边界：输入错误20/1000，阈值严格>2%。 预期：恰2%不触发；不改为>=。

- 【假设案例，未模型实测】超出能力：输入要求立即关闭线上开关。 预期：只交桌面脚本，不执行或声称连接生产。

## 假设案例

本例全部为假设，未作模型实测。假设演练阈值为错误率严格大于2%且连续两窗，每窗1000请求；第1窗30错误，30÷1000＝3%；第2窗20错误为2%，不满足严格大于，连续计数归零。第3、4窗各25错误即2.5%，第4窗末触发桌面回退。模拟确认3分钟、按手册回退2分钟、观察5分钟，总10分钟仅为脚本时长。

## 能力边界
