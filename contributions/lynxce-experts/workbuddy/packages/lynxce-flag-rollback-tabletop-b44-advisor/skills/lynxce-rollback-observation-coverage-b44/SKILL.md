# 回退观察证据覆盖核查

本任务服务发布协调员、值班开发与演练主持人，独立交付“回退观察证据覆盖核查”。只以用户提供材料完成下列核查，最小输入见第一步。这是专门中间成果，可单独使用；不重复公开技能整套输出。资料不足时先交可确认部分和精确补件问题。

## 工作流程

1. 收集批准观察对象、指标单位、前后窗口、证据记录及门槛，最少对象清单和一份观察记录。

2. 按新请求、旧会话及异步任务分别对应指标，不用总请求下降证明全部路径恢复。

3. 核窗口长度和分母，一分钟值不能直接替代五分钟要求；缺样本只列待补。

4. 逐对象检查是否有前值、后值、范围和时刻四项证据，统计资料覆盖而非故障恢复率。

5. 若错误减少但积压上升，分列指标冲突和继续观察条件；不选择单一好指标作为通过。

6. 输出证据矩阵及需补记录，只有用户给出复核反馈才能写对应观察项已核，不能认定线上恢复。

## 任务专属规则

- 没有旧会话证据时新请求指标再好也不支持旧会话结论。

- 缓存刷新间隔使用提供资料，不能按常识假定关闭即时生效。

- 窗口恰好满足时仍核起止边界，重叠样本不算两份独立证据。

- 指标观测通过与业务恢复由不同反馈支持，报告明确证据等级。

## 资料定位与事实等级

- 每条原始材料分配来源编号，保留原文与采用版本。示例是假设资料，不写入实际输入空白；用户只需提供会影响本项成果的字段，未知值统一填【待补】，空白与零区别处理。

- 每条结论明确是用户记录、计算结果、候选判断还是待人工确认。原材料状态与建议动作分开列，不用已处理、已通过等用语替代缺失证据；没有反馈的环节保留待核状态。

- 同一对象出现两份互斥记录时并列原值和来源，不按较新日期自动取舍。指出哪一个字段会改变结果，并给出需补充的最小证据；不平均文本冲突，也不删除不利记录。

- 复算前确认计数对象、单位及分母，所有比率同时提供分子和分母。零分母写不可计算，展示百分比保留两位小数；不同范围的数量不能为了凑合计而直接相加。

## 交付复核与变更

- 表格中每个异常给出具体受影响行、待补字段、经办角色与解除条件，建议只到文本资料层。用户没有实际系统记录时不假称已执行、读取后台或联系其他人。

- 收到补证后先确认对应对象和版本，再重算受影响行及汇总，旧版与新值都保留。对未受影响行维持原证据范围，避免局部补充被误读为全量验证或全流程成功。

- 输出前核对原记录数、可分析范围、排除原因和结论状态之间是否一致，每个输入都有去向。资料质量检查只支持本份草稿，不证明实际业务效果或第三方认可。

- 超出任务范围时交付可完成的资料部分，并写需要用户指定人员处理的具体事项。不提供医疗诊断、财税或法律专业结论，不虚构账号接入、现场观察或外部工具能力。

## 五类假设验收案例

- 【假设案例，未模型实测】正常：输入3类对象仅2类证据齐，新请求3%降0.5%。 预期：覆盖66.67%，下降2.5个百分点，队列待补。

- 【假设案例，未模型实测】缺资料：输入后值有5错误但没有请求分母。 预期：错误率待补，不以5推断0.5%。

- 【假设案例，未模型实测】矛盾：输入错误率下降同时队列积压从20升50。 预期：积压增加30，分列反证，不能整体判恢复。

- 【假设案例，未模型实测】边界：输入对象清单为空。 预期：不计算覆盖率，退回确定观察范围。

- 【假设案例，未模型实测】超出能力：输入要求保证线上故障恢复并出检测证书。 预期：只给观察资料核对结果，不保证或认证。

## 假设案例

本例全部为假设，未作模型实测。假设要求观察新请求、旧会话、异步队列3类；前两类各有完整证据，队列只有前值，完整覆盖2÷3≈66.67%。新请求前30/1000=3%、后5/1000=0.5%，下降2.5个百分点；队列后值缺失不能填0，不能报告全部恢复。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
