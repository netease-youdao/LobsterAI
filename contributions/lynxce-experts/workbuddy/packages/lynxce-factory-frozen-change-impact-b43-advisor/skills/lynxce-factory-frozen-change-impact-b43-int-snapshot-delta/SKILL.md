# 冻结订单快照差异核对

本内部能力只处理冻结订单快照差异核对，输入为变更前后快照、联合键规则、工作时间轴；输出为逐单差异与承诺余量表。独立保留依据，不代替公开任务的完整交付。 依据仅限用户提供的业务资料。每项事实注明资料编号、版本与日期，缺项写【待补】，推测与确认事实分栏。对冲突输入保留原值和来源，不用示例填补真实空白。只交付可复制的文本和表格；不声称已联网取得数据、连接系统、发送消息、修改记录或执行现场操作。不作资质、认证或签章结论。

## 工作流程

1. 接收变更前后快照、联合键规则、工作时间轴，明确本轮对象、截至时刻、资料版本与用户希望解决的问题；缺少核心资料先给待补表，保留能够核对的部分。

2. 按任务对象建立唯一记录键，拆分事实、声明与未知条件；逐条关联原文及原值，重复、缺漏与来源冲突单列，不静默覆盖。

3. 先检查联合键唯一性，同一订单多道工序分行，重复键不任意去重，要求资料提供者说明拆分规则。使用表格保存比较口径、数量单位和适用范围，方法无法实施时说明具体缺少哪一项输入。

4. 前后时间统一到同一工作时间轴，不能把自然日日期差和工作小时直接相减，夜班跨日需保留班次标识。对存在分歧的条目提出可回答的确认问题，条件足够才推进，不把未确认的假设转成决定。

5. 结合领域方法复核异常和变更影响，给出待核、补证后可继续或需重新对齐的分支；把责任、期限与验证证据逐项列入。

6. 交付逐单差异与承诺余量表，逐行复算数字与单位，检查来源、版本、状态和未闭环项；由用户负责角色复核后使用，后续资料按新版本续接。

## 对象与口径方法

- 先检查联合键唯一性，同一订单多道工序分行，重复键不任意去重，要求资料提供者说明拆分规则。

- 前后时间统一到同一工作时间轴，不能把自然日日期差和工作小时直接相减，夜班跨日需保留班次标识。

- 新增与删除单独展示，缺失完成时间不作零；未变订单也保留计数，核对前后总行数守恒关系。

- 从约定时间反算余量，用移位和缺口两个独立字段解释影响，不重新计算用户未提供的标准工时。

## 证据与决策方法

- 先记录冻结版本、冻结窗口、拟插单方案版本与生成者；没有变更前快照就不能说哪个订单被挤压，只能列待补输入，不拿当前快照当原计划。

- 以订单号和工序号为联合键逐行配对，拆出新增、移位、删除与未变四种状态；同订单分批交付时必须保留批次键，不能把首批与末批日期混在一行。

- 设置撤回条件与时点，例如材料未拆封、工序未开始或原运输窗口仍可恢复；撤回不是删除记录，必须保留拟方案与恢复后的快照版本。

- 方案被部分批准时重新列出允许实施范围和未批准依赖；不能把插单数量批准当成旧订单交期变更批准，也不能把文本草案称为系统排程已更新。

## 异常与交付复核

- 核对表中每项判断必须能回指输入记录，不同来源相互矛盾时列出冲突双方与待确认问题；输入没有证明完成的事项保持待核，不能写为事实。

- 检查每行单位、分母、时间窗口与版本是否一致，先复算再解释；零值、空白、未发生是三种不同状态，不把缺失字段默认为零。

- 输出时先列影响与未满足条件，再给逐行证据与下一步动作；责任人与复核人没有提供就留待补，不自行捏造人员或补上批准结论。

- 新资料到来时更新差异与有效范围，保留原表版本和修改原因；旧记录仅作历史依据，不把之前的假设结果当本次真实业务数据。

## 假设案例

假设快照前8条，后新增2条、删除1条，应有8＋2－1＝9条。订单C原第4小时、新第7小时、约定第8小时，移动3小时且余量1小时；若后快照只有8条，则另有缺失键需查清，不能直接发布影响总表。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
