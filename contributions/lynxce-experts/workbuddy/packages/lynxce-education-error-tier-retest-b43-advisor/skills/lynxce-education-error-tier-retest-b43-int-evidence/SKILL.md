# 错因追问证据卡

内部专项任务：错因追问证据卡。只处理逐题错因假设与一分钟追问记录，不替代公开任务的完整交付。核心方法为：证据强度分为直接步骤、口头解释、只有结果，三类不可互相替代；给每个疑似错因写一个能够区分相邻原因的问题，记录学生实际回答后再更新错因。

## 工作流程

1. 确认专项输入为匿名答卷、原题答案、知识点范围与复测时间，锁定所用版本及本次范围，仅抽取与错因追问证据卡有关的字段；缺项标【待补】，不要套用演示例子作为事实。

2. 建立逐题错因假设与一分钟追问记录的原始证据列，记录资料编号、原文片段与目前状态；将事实与经办人的解释分栏，矛盾内容保留两种记录。

3. 证据强度分为直接步骤、口头解释、只有结果，三类不可互相替代；给每个疑似错因写一个能够区分相邻原因的问题，记录学生实际回答后再更新错因。每项都说明判断顺序、触发条件和例外，缺关键条件时不强行给确定结论。

4. 逐项采用专属方法核查：用题号—知识点—原作答—错因假设四列建立证据链，每个错因至少有一个明确作答片段；只出现错误答案而没有过程时标记原因未确认，建议教师做一句口头追问。保留原始值和推演值，让复核人能够独立重现过程。

5. 用专项示例检查数量守恒及分类互斥：假设4份作答中2份有错误通分过程、1份只有答案、1份空白，只有2份可直接归为通分步骤错误；其余2份进入追问清单，已确认占2÷4＝50%。遇到不闭合结果，先找遗漏与重叠，不能为了闭合改写事实。

6. 输出逐题错因假设与一分钟追问记录并列待补项、影响范围、复核人及下次更新条件；没有用户反馈的条目不变更为已完成，专项结果交由主流程采用。

## 专项证据方法

- 用题号—知识点—原作答—错因假设四列建立证据链，每个错因至少有一个明确作答片段；只出现错误答案而没有过程时标记原因未确认，建议教师做一句口头追问。

- 先检查答案或题干自身是否有歧义，原题出现多解时保留各合理路径，不把与标准步骤不同但正确的解法当错题，教师确认前不生成针对性的纠正练习。

- 概念辨析题采用正例与反例配对，要求学生说出区别；计算执行题采用步骤定位，不把所有错误都归成粗心，避免失去可指导的具体动作。

- 学习层是某知识点上的临时任务标记，复测达到条件即可迁移；不依据一次测验固定学生身份，不在班级公开姓名排名或用层级标签评价学生人格。

## 专项模板与决策

- 证据强度分为直接步骤、口头解释、只有结果，三类不可互相替代；给每个疑似错因写一个能够区分相邻原因的问题，记录学生实际回答后再更新错因。

- 每一行以专项对象编号为主键，与公开成果只通过资料编号关联，不复写公开交付全文；表头固定包含原状态、证据位置、专项判断和待核动作。

- 分支状态采用已确认、待证据和存在冲突三类；待证据不是否定，存在冲突不能合并为已确认，后续反馈到来后再记录原状态和新状态。

- 复核意见必须包含可观察依据与采用版本，确认人没有提供时标【待补】；文字建议与实际执行分栏，避免专项草案被误读为已经完成的业务。

## 复核与版本

- 资料入口采用最小必要字段，先核用户提供的版本、时间与适用范围；原始记录和解释意见分别保存，缺项统一写【待补】。存在两份冲突资料时并排列出，不擅自选更有利的一份，也不把演示数字补成真实业务事实。

- 输出每条判断对应的资料编号、所用方法和状态，记录谁需要确认以及确认后会改变哪一项结果。所有数量注明单位，计算保留分子分母和逐步算式；舍入只用于展示，原值与修正值均保留以便复核。

- 表格是根据给定资料编写的文本草案，计划、人员自报、资料核对通过和实际完成分开记录。没有实际反馈就维持待确认，不能声称已经读取业务系统、发送通知或执行现实任务；也不提供任何资格认定或虚构外部验证。

- 完成前先检查每条输入是否有去向、每条输出是否有来源、每个异常是否有承接动作。后续更新只改有新证据的条目，保留旧版本与变更理由；超出本任务的请求列具体缺项或交接建议，不把未核实事实写进结论。

## 假设案例

以下为专项假设，非真实业务结果：假设4份作答中2份有错误通分过程、1份只有答案、1份空白，只有2份可直接归为通分步骤错误；其余2份进入追问清单，已确认占2÷4＝50%。该示例只演示专项判断的分类与数值核对。实际使用时先把资料对象逐行编号，保留原始证据，再执行所列方法；不符合前置条件的对象必须单列待核，不能放入已确认数量。若用户补充记录导致判断改变，记录新增依据、原状态和新状态，重新计算受影响的分母与合计。最终只输出文本对照表和复核建议，不宣称已执行外部任务。复核时逐项检查对象总数、已确认数和待核数是否闭合，注明所用资料版本与计量单位；发现输入修订时只重算受影响条目，并在输出中保留旧值、修订值和差异原因，交由业务负责人确认后再更新主流程记录。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
