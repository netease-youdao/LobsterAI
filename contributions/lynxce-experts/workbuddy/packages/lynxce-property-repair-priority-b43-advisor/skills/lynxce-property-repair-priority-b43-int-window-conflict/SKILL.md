# 维修人员时窗冲突核查

在时间轴上核工单占用、移动缓冲与预约硬约束。。输入范围仅限用户给定的建筑物业业务材料；与公开技能分工，独立完成此项中间成果再交专家复核。

## 工作流程

1. 收集每人班次与已占时段，工单时长、人数和移动耗时必须来自用户资料。

2. 将双人单对两个人同时占用，核交集可用窗口而非各自总时长。

3. 逐任务叠加移动缓冲并与入户窗相交，边界相接是否允许沿用给定规则。

4. 计算重叠分钟与不可排原因，材料未齐或预约未确认单独标识。

5. 对冲突提供换人、改约或等待条件三类建议，只有给定资源才能列具体候选。

6. 交付冲突表与备用窗口，缺关键工时信息保持待排，不假定准时执行。

## 专属核查方法

- 跨班次作业核结束时间，不把开始在班内当成全程可用。

- 任务工时与往返移动分别列，避免把缓冲隐藏在维修时长里。

- 有技能记录不等于确认资质，只形成资源匹配草案。

- 对未确认预约的时间只能占建议窗口，不应标住户已同意。

## 证据与状态控制

- 先按本任务的复合业务键标记每条材料，保留原值与来源日期，关键字段缺失时只输出可确认部分及补证问题。

- 将输入事实、计算中间值与建议动作分列，复算结果需要能够回到对应单据或记录，不能靠结论倒填来源。

- 用户给定规则只在明确范围内使用，规则变更需记录版本；冲突时列适用条件，不将其他批次或其他任务的规则直接迁移。

- 输出给经办与复核角色审阅，确认资料齐全并不等于业务执行完成，任何现场结果须由用户补充反馈及验证记录。

## 交付与异常

- 输出本任务的领域表格与逐行问题，单位、时间、状态必须写全；没有依据的字段填【待补】，不以零代替缺失。

- 对异常记录给出最小补证动作及其预期证明的条件，不能仅写需要核查，必须说明核哪一项以及结果如何影响表格。

- 先列矛盾与未确认条件，再给条件式建议；存在反证时修订相关行并保留旧版，避免相互矛盾的承诺或计算同时有效。

- 收尾检查表头、合计、状态及来源索引一致，交付文本草案和人工处理清单；不声称联网检测、自动派发或修改系统记录。

## 假设案例

假设甲与乙均可用14:00至16:00，双人任务X需60分钟，甲已有14:00至14:30单人任务，乙已有15:30至16:00任务，两人共同空闲14:30至15:30恰好60分钟。若用户给定前置移动各15分钟，甲最早14:45可到场，两人共同可施工窗口14:45至15:30只有45分钟，缺15分钟，应列不可排并请求改约，不用总空闲时长替代交集。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
