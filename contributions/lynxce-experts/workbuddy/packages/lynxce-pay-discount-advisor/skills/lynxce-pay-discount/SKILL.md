# 大促支付立减与优惠叠加顺序核算

大促叠优惠最容易吃亏的不是少领了一张券，而是**以为支付立减按商品原价算门槛、券和满减叠完实付掉到门槛以下立减失效、拆单或部分退款后优惠被按比例扣回却没算进去**。

## 工作流程（按顺序执行）

1. 问清候选商品的标价与件数、已领到的店铺券与平台券（面额与门槛）、参与的满减规则（如每满 300 减 50）、结算页可见的支付渠道立减（面额、门槛与名额说明），以及是否打算拆单、是否可能部分退货。
2. 排计算顺序：常见顺序为 商品标价 → 单品直降或店铺券 → 跨店满减 → 平台券 → 得到应付金额 → 支付渠道立减 → 实付金额；不同平台与活动的叠加规则不同，最终以结算页展示的优惠明细为准，规则说明未写明的标【待补】。
3. 逐级核门槛：每一步都用上一步的结果去比下一项的门槛，支付渠道立减多数按应付金额（券后）判断门槛而不是标价，券后低于门槛的立减不生效；差额不大时可列出凑单方案，但凑单商品须是本来就需要的，用不上的按 0 价值计。
4. 核拆单与退款：同一优惠拆成两单时，满减与平台券可能各自达不到门槛；部分退货时，已享优惠通常按各商品金额占比分摊扣回，退款金额＝该商品实付分摊额，支付渠道立减是否退回或扣回以支付渠道与平台规则为准，未说明的标【待补】。
5. 划清边界：只算优惠顺序与到手价，不推荐办理任何银行卡或支付账户，不涉及信用卡、分期、借贷与利率建议，不做任何金融结论；支付立减名额与每日次数有限，以结算页实时展示为准。
6. 输出优惠叠加核算表，逐级写明门槛是否满足与每一步金额，给出一单与拆单的到手价对比，最后按商品列出下单入口清单。

## 计算顺序与门槛怎么判

- 常见顺序：标价 → 单品直降或店铺券 → 跨店满减 → 平台券 → 应付金额 → 支付渠道立减 → 实付金额，以结算页优惠明细的实际先后为准。
- 门槛逐级判断：满减按参与活动商品的合计金额判断（是否已扣店铺券以活动规则为准），支付立减多按券后应付金额判断，标价满足但券后不满足的算不满足。
- 每满型满减（如每满 300 减 50）按 满减额＝向下取整（参与金额÷300）×50 计算，差几元跨档时才考虑凑单。
- 同一订单通常只能选一个支付渠道立减，多个渠道活动并存时取其一比较，不能相加。

## 拆单、退款与凑单

- 拆单前后分别核门槛：拆成两单时每单都要单独满足满减与平台券门槛，常见结果是拆单后优惠变少。
- 部分退货扣回：该商品应退金额≈该商品标价÷订单参与优惠商品标价合计×订单实付总额，具体分摊口径以平台售后规则为准。
- 凑单商品只计本来就要买的，用不上的凑单品按 0 价值计，凑单后的到手价要把凑单品价格一起算进去再比较。
- 支付立减名额、每日次数与单用户限次以活动说明为准，结算时没有显示的视为不可用，不按宣传页预估。

## 边界与红线

- 本技能只做优惠顺序与到手价核算，不推荐办卡、不比较银行或支付机构、不涉及信用卡、分期、借贷与利率，也不做任何金融结论。
- 不要为了一次立减去办理新卡或开通新账户，相关决定请用户按自身情况独立判断。
- 不使用「最低价」「全网最便宜」「史低」「绝对划算」等极限或绝对化用语。
- 价格、优惠与活动规则一律以平台活动页、商品详情页与下单结算页的实时展示为准，本技能只做核算与提示，不做价格承诺，不保证必省多少钱。涉及退款纠纷、消费者权益认定的，以平台规则与主管部门规定为准，本技能不做法律结论。不编造价格、历史数据与活动规则，用户未提供或查不到的信息用【待补】占位。

## 示例

用户：「两件衣服标价 199 和 139，店铺券满 300 减 20，跨店每满 300 减 50，结算页有个支付立减满 300 减 15，能叠多少？」→ 先排顺序：标价合计 338 元；店铺券满 300 减 20 后 318 元；跨店每满 300 减 50，按活动规则假设以店铺券后金额判断，318 元够一档，减 50 后 268 元；支付立减满 300 减 15 按券后应付判断，268 元低于 300 元，立减不生效，实付 268 元；若按标价判断门槛，则可再减 15 元到 253 元，所以要看结算页明细确认口径；异常场景：如果之后退掉 139 元那件，按占比分摊应退约 139÷338×268≈110 元，而不是 139 元；我不推荐办卡、不涉及分期建议；最后给出叠加核算表与下单入口。
