# 施工阻塞释放条件任务表

把阻塞描述拆成释放条件、核验人及受影响任务。。输入范围仅限用户给定的建筑装修业务材料；与公开技能分工，独立完成此项中间成果再交专家复核。

## 工作流程

1. 从周报抽取未完区段与具体阻塞事实，删除没有来源支持的确定原因描述。

2. 拆分材料、交接、场地和确认四类条件，多个条件采用同时满足或择一关系明确表达。

3. 写清释放证据，如用户提供到场记录或交接确认，不把口头预计当已释放。

4. 核可用资源和下一任务的依赖，只有用户给定资源容量才能估工期。

5. 制作条件满足前后的两个版本，资源冲突或条件延期时列受影响任务。

6. 交付阻塞表、跟进问题和下周条件计划，等待现场人员确认后更新状态。

## 专属核查方法

- 同时满足条件用逐项核对，缺任何一项都不写可开工。

- 只记录资料表明的工序依赖，不编专业作业参数或技术方案。

- 日期是用户目标还是已确认安排必须分列，预计不等于承诺。

- 状态从待核、受阻、待释放到已反馈释放，转换需关联依据。

## 证据与状态控制

- 先按本任务的复合业务键标记每条材料，保留原值与来源日期，关键字段缺失时只输出可确认部分及补证问题。

- 将输入事实、计算中间值与建议动作分列，复算结果需要能够回到对应单据或记录，不能靠结论倒填来源。

- 用户给定规则只在明确范围内使用，规则变更需记录版本；冲突时列适用条件，不将其他批次或其他任务的规则直接迁移。

- 输出给经办与复核角色审阅，确认资料齐全并不等于业务执行完成，任何现场结果须由用户补充反馈及验证记录。

## 交付与异常

- 输出本任务的领域表格与逐行问题，单位、时间、状态必须写全；没有依据的字段填【待补】，不以零代替缺失。

- 对异常记录给出最小补证动作及其预期证明的条件，不能仅写需要核查，必须说明核哪一项以及结果如何影响表格。

- 先列矛盾与未确认条件，再给条件式建议；存在反证时修订相关行并保留旧版，避免相互矛盾的承诺或计算同时有效。

- 收尾检查表头、合计、状态及来源索引一致，交付文本草案和人工处理清单；不声称联网检测、自动派发或修改系统记录。

## 假设案例

假设区域甲剩余30平方米，材料到场及上道工序交接两项条件同时必要。材料周一反馈到场、交接仍待确认，则释放条件完成1项共2项，不能说任务已可开始。用户给定每日15平方米的计划能力，仅在两个条件满足后估计需30÷15＝2个作业日；这个估算不代表现场实际工期。若可用能力变为10平方米，条件计划改为3日并保留原版。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
