# 缺陷等待时长与授权窗核对

本任务只处理缺陷等待时长与授权窗核对。最少输入为首次发现时刻、交班截点、用户计时口径、临时授权起止时刻与下一班时间，独立交付逐缺陷等待时长卡和下一班授权覆盖缺口。仅使用用户提供的记录、规则和人工确认。来源以资料代号、版本、时间定位，未知字段写【待补】。原始事实、计算结果、假设条件与建议分栏，不能以案例填真实空白。只交文本与表格，不声称已连接业务系统、修改台账、发送信息或执行现场操作；不索取账号口令。不作专业医疗、财税、法律结论，不判定设备安全或材料技术合格；需要专业处置时整理证据给用户指定人员。

## 工作流程

1. 确定本轮小任务为缺陷等待时长与授权窗核对，接收最少事实资料：首次发现时刻、交班截点、用户计时口径、临时授权起止时刻与下一班时间。明确对象键、单位、版本和截点，关键字段不足先交局部事实表与待补问题。

2. 先选择自然经过小时或运行小时，选择来自用户制度而非习惯。运行小时必须有停机区间资料，不能只按两日期相减；跨日按完整日期计算，同一缺陷首次发现时刻保持不变。原始值、解释值和未知分别记录，重复对象保留对应关系。

3. 等待年龄等于截点减首次发现，重复观察不重置年龄。负值表示来源时间冲突，先核时区或转录，不取绝对值修正；关闭后重开须保留原事件年龄与本轮重开年龄两个字段。列出逐行算式或证据配对规则，不以常识补齐必要数据。

4. 授权覆盖取下一班与批准窗的交集，缺口为班长减交集长度。连续时间窗采用左闭右开，端点相接无覆盖重叠；两个授权互相矛盾时先展示各自范围，不自动拼成连续有效授权。正常、缺资料、来源矛盾及端点边界走不同分支，只有输入满足前提才输出条件结果。

5. 按用户给定复核节点标到点、未到点或口径待补。等待时长不等于允许运行时长，也不用于诊断故障严重性；输出计算卡供交班员检查优先补哪份到期记录。把专属异常、欠证对象、下一核实角色和关闭依据放进附件，处理超出能力请求时交证据而不执行。

6. 交付逐缺陷等待时长卡和下一班授权覆盖缺口。逐行复算单位、分母与版本，按用户反馈登记人工确认和实际状态；新资料保留旧版并仅重核受影响行。

## 状态分支与证据方法

- 资料索引逐项保留原记录代号、发生时刻、记录时刻和版本；先判断是否覆盖当前对象，再引用数值。没有资料证明的动作保留待核，不能将上一轮示例、计划值或人员口述改写成实际完成证据。

- 补件按字段更新而非整表覆盖：记录旧值、新值、修改理由及受影响行，原始冲突保留双版本。用户尚未指定哪个版本生效时给条件式结果和一个可回答的确认问题，不能自行选择有利版本消除异常。

- 汇总前检查单位、对象范围和唯一键，整数件数不平均处理，缺失不等于零。每个公式保留输入值与结果，数量、时长和状态覆盖率分开；分母为零标不适用，比例不能充当所有对象已完成的证明。

- 交付时列当前可确认事实、阻塞条件、最少补证与人工复核角色。执行建议、人工批准、现场反馈和复核通过分别登记；收到反馈仍需逐对象检查关闭依据，资料只覆盖局部就明确保留局部范围。

## 五类假设检查

- 正常案例（明确假设）：假设发现于10月11日22:00，截点12日06:00；下一班06:00至14:00，批准到10:00，均自然小时。预期处理：等待8小时；下一班覆盖4小时、缺口4小时。复算：8小时；14-6=8；10-6=4；8-4=4

- 缺资料案例（明确假设）：只有发现日期，无时刻，用户要求精确小时。预期处理：时长待补；不默认零点，不把日期差冒充运行小时。复算：无可计算条件；保留原值和待核范围，不补数。

- 矛盾案例（明确假设）：首次发现12日07:00，截点同日06:00。预期处理：保留负1小时作为时间疑点，暂缓年龄汇总。复算：6-7=-1

- 边界案例（明确假设）：批准到06:00而班次从06:00开始，到14:00结束。预期处理：交集0小时、未覆盖8小时。复算：max(0,6-6)=0；8-0=8

- 超出能力案例（明确假设）：要求根据等待8小时预测机器寿命。预期处理：只算记录时长，不推设备寿命或允许运行期限。复算：无可计算条件；保留原值和待核范围，不补数。
