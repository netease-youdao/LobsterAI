# 等位顺序与等待计算

## 要解决的具体问题
依据已确认公平规则把客组落实到桌号与时刻，保留预估条件。
这是专家工作链中的第2项独立能力。只处理本节写明的对象与口径，不接管其它子任务。用户可以直接给脱敏文字表格，交付也是可复制的文本；没有外部服务依赖。

## 最低输入与进入条件
客组到店时刻、候选桌集、释放时刻及确定性、叫号规则、当前已入座状态。
先以任务代号固定对象，再写本轮截点。输入有一项缺失时，先把已知对象写进本节的交付格式；只有依赖缺项的计算或措辞暂留【待补】，不让用户重填全部材料。对真正影响决策的缺口一次最多问三个问题。

## 专属操作方法
锁定已入座，再按确认的顺序逐组寻找候选桌。就座时刻取客组准备时刻与桌释放时刻较大值，分配后将桌从本轮可用池移除。只有提供预计用餐时长才可继续排后轮，并标明假设。等待按就座减到店逐组计算，实际与预计分开汇总。

## 可直接使用的输出与已填例子
假设T1/T2于18:00可用，A2人17:50到、B3人17:55到；A到T1等10分钟，B到T2等5分钟，当前共等15分钟。C依赖预计18:20翻台，只能列预计等待。

## 复核、异常与回传
不得把负等待记成提前服务，未来到店组另列预订。两组同桌同轮须有明确拼桌同意。不同桌容量不适配的客组之间不比较所谓插队。
每个派生数字标单位及代入式，排序结果保留触发规则，不把排序靠前写成已经批准。一次改动只替换被证实改变的输入，同时重算本子任务所有相关结果；把改动前后两列保留下来，使主专家可以接续而无需猜测哪个版本生效。回传至少包含对象号、本轮结论、形成结果的输入、需要人工确认的最后一步。主专家若改变其它约束，应重新调用本能力，而不能直接改结果数字。

## 独立完成标准
交付逐组桌号和等待算式，现场可用安排与未来候选清楚分开。
样例是清楚标注的假设，不能改成客户成效。工具没有接入真实业务系统，不写已经发通知、改状态、分配资源或完成现场作业。用户说明采纳只记为采纳，现场完成仍须用户另行反馈。


### 与最终成果的一致性
方案等待、未来预计等待、实际等待分栏；C预计安排不能计入实际安排组数，数值用同一时间账复算。将模块数值和依据交给主流程，正文、表格与话术须使用同一版本，不以模块自评代替最终工具与事实复核。
