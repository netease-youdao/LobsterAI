# 过号与延迟解释话术

## 要解决的具体问题
把排程变化写成迎宾能当场说的短句，说明具体选择而不空泛道歉。
这是专家工作链中的第3项独立能力。只处理本节写明的对象与口径，不接管其它子任务。用户可以直接给脱敏文字表格，交付也是可复制的文本；没有外部服务依赖。

## 最低输入与进入条件
已确认的过号规则、原新版桌位、等待变化、客组可选择项、未知释放条件。
先以任务代号固定对象，再写本轮截点。输入有一项缺失时，先把已知对象写进本节的交付格式；只有依赖缺项的计算或措辞暂留【待补】，不让用户重填全部材料。对真正影响决策的缺口一次最多问三个问题。

## 专属操作方法
每条话术包含当前事实、变化缘由、时间确定性、一个明确选择。规则未知时先产出经理可选的两种草案，不把草案说成既有店规。翻台延后只讲与该客组有关的影响；若不能给时刻，就给下一次现场确认点，不能凑一个保证时间。

## 可直接使用的输出与已填例子
假设C由预计18:20改18:35，文稿：“目前预计18:35可安排，比刚才估计晚15分钟；您可继续保留等位或取消，请告诉我们您的选择。桌位释放后仍需现场确认。”

## 复核、异常与回传
不能用其他客人身份、消费金额作为解释。不得保证马上有桌或声称已发短信。用户选择继续等位只更新意向，不代表已经入座。
每个派生数字标单位及代入式，排序结果保留触发规则，不把排序靠前写成已经批准。一次改动只替换被证实改变的输入，同时重算本子任务所有相关结果；把改动前后两列保留下来，使主专家可以接续而无需猜测哪个版本生效。回传至少包含对象号、本轮结论、形成结果的输入、需要人工确认的最后一步。主专家若改变其它约束，应重新调用本能力，而不能直接改结果数字。

## 独立完成标准
交付过号与翻台延后各一段具体话术，均保留选择和未确认条件。
样例是清楚标注的假设，不能改成客户成效。工具没有接入真实业务系统，不写已经发通知、改状态、分配资源或完成现场作业。用户说明采纳只记为采纳，现场完成仍须用户另行反馈。


### 与最终成果的一致性
话术中的已安排、已入座、已发出等完成词须有相应用户反馈，只有草案时采用条件句。将模块数值和依据交给主流程，正文、表格与话术须使用同一版本，不以模块自评代替最终工具与事实复核。
