# 调拨跨库位双端悬挂核查

按调拨编号配对出入端，识别单端凭据与发生时间跨窗。。输入范围仅限用户给定的仓储物流业务材料；与公开技能分工，独立完成此项中间成果再交专家复核。

## 工作流程

1. 收齐调拨单号行号、起终库位、批次、数量与两端发生记录，明确本次截止时刻和计量单位。

2. 按调拨单行和批次配对，不用相同数量作为唯一关联依据，重复单行保留但从加总集合排除。

3. 将完整配对、只有出端、只有入端和数量不一致四种状态分组，跨时间窗记录两端各自归属。

4. 对只有出端的记录核在途说明；只有入端核起点凭据，缺证据不能直接补造对端行。

5. 逐组复核货主与状态，不把不同货主或隔离状态的货物借数量相同抵销。

6. 输出双端悬挂表及取证顺序，建议由经办人补单据，用户确认前不把悬挂记成已平。

## 专属核查方法

- 双端匹配用复合键，拆分调拨要将子行关联父行而非强行一对一。

- 跨库调拨与同库移位分别统计，业务类型不同不能混用在途口径。

- 记录起点减少与终点增加的相反方向，统一基础件数后再比较。

- 悬挂清单保留首次发现时刻与补证日期，验证闭环要看两端证据。

## 证据与状态控制

- 先按本任务的复合业务键标记每条材料，保留原值与来源日期，关键字段缺失时只输出可确认部分及补证问题。

- 将输入事实、计算中间值与建议动作分列，复算结果需要能够回到对应单据或记录，不能靠结论倒填来源。

- 用户给定规则只在明确范围内使用，规则变更需记录版本；冲突时列适用条件，不将其他批次或其他任务的规则直接迁移。

- 输出给经办与复核角色审阅，确认资料齐全并不等于业务执行完成，任何现场结果须由用户补充反馈及验证记录。

## 交付与异常

- 输出本任务的领域表格与逐行问题，单位、时间、状态必须写全；没有依据的字段填【待补】，不以零代替缺失。

- 对异常记录给出最小补证动作及其预期证明的条件，不能仅写需要核查，必须说明核哪一项以及结果如何影响表格。

- 先列矛盾与未确认条件，再给条件式建议；存在反证时修订相关行并保留旧版，避免相互矛盾的承诺或计算同时有效。

- 收尾检查表头、合计、状态及来源索引一致，交付文本草案和人工处理清单；不声称联网检测、自动派发或修改系统记录。

## 假设案例

假设调拨T1出库30件、入库28件，双端差额2件；T2出库12件、尚无入库凭据，悬挂12件。T1的缺口不能由T2未来到货抵消。T3出入各10件，但入库记录重复导出两次，唯一行仍为10件而非20件。三单唯一出库量52件，已有对应入库量38件，未匹配量14件由2件数量差和12件单端悬挂构成；这是核查清单，不等于实际短少14件。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
