# 工位负荷与按目标节拍的工时利用率复算

## 使用位置与输入
本模块服务“手工装配工位平衡方案”，接收主流程已经编号的输入，不另造一份数字。需要的对象、单位和时间范围写在模块结果首行；缺项保留待补，只暂停依赖该字段的输出。

## 专属处理方法
以用户确认目标周期为同一分母，先求动作总和，再算理论工位下界，最后核每个候选的站内总负荷。假设总工作100秒、目标60秒，两工位下界只是至少2站，依赖与设备可能要求3站。候选AB50、CDE50时逐动作回查前置，不能只因总量100小于120就说可行。原3站工时利用率100÷180=55.56%，新2站100÷120=83.33%，差27.78个百分点。空闲合计分别80和20秒，仅是目标周期下的理论值，不是可兑现工资节省。输出每站动作顺序、负荷与余量，单站超限标红文字说明；没有求得最优的证明不宣称最优方案，也不据此要求员工加速危险动作。

## 交接与复核
交付时同时给可直接使用的中间成果、计算来源和未决项，传给主流程合并。不得把建议动作写成已经执行，也不得把另一模块尚未确认的假设改成事实。修订时保留本模块上版结果和变化理由，以本轮完整结构化输入整表重算。核对每个数字的单位和每个判断所依赖的条件，发现冲突先列两个分支。完成标志是主流程可以据此继续编排最终方案，而不是只收到一张空检查表。

## 结构化脚本交接
运行随包calculate.py，以其JSON及Markdown为唯一派生数源。脚本把已知动作与新增秒数全部加总，在目标60下验证每站负荷与前置、许可工位，枚举仅在已给范围内找最少非空工位。B30总100，AB/CDE负荷50/50时工时利用率83.33%、空闲20；B50总120且两站无解，三站可行候选的最高负荷50与工时利用率66.67%取自脚本。每次输入改变都整表重算，不复用上次工时利用率或忽略新增时间。达到枚举上限时只给已验证候选或待继续搜索，不称全局无解。原工位与候选比较由movedActions生成，C仍在站2就不能写C被移动。交付紧凑负荷表与适用条件，理论产出不升级为现场保证。
