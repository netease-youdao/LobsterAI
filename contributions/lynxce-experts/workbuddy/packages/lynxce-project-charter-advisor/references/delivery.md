# 交付模板与复算示例

## 完整可复制模板

```text
项目__；草稿版本__；决策人角色__；本次请求__；建议及成立条件__
问题基线：对象__；期间__；样本__；现状数__；来源__；不做的影响__
备选路径：维持现状__；最小试点__；拟立项范围__；取舍依据__
范围表：产物｜使用对象｜包含｜不包含｜验收证据｜责任角色
目标矩阵：指标｜基线｜目标假设｜测量式/方法｜观察期｜测量人｜通过条件
资源表：角色｜人数｜工作日｜投入比例｜人日｜单价及来源｜估算费用
依赖里程碑：节点｜前置输入｜提供人｜最晚时间｜完成证据｜未满足的备选路径
治理与风险：决策/交付/验收/知会角色__；触发条件__；影响__；应对__
变更与停止：需批准的变化__；停止触发__；保留成果__；退出负责人__
评审问答：为何现在__；为何该路径__；资源可用证据__；如何验收__；失败如何停止__
未确认材料__；关键问题（最多三条）__
```

## 已填假设示例

假设要做20条客服知识条目试点，原抽样100次咨询中40次重复，基线40%；目标在同口径100次观察中重复不超过30次，即30%，下降10个百分点，不是下降10%。范围为20条整理及人工评审，不含系统迁移；业务效果仍待试点观察。

资源：整理人员2人×10工作日×50%=10人日，审核人员1人×5工作日×40%=2人日；共12人日。内部估值500元/人日，12×500=6000元；假设额外工具费1000元、预留700元，总估算7700元。预留700仅为本例已给假设，不代表通用比例。

里程碑：第1至10工作日整理，第6至10工作日审核，前提是第5日先交首批；第11至20工作日观察，第20日才做效果复盘。章程结论：建议批准此试点并先确认抽样方案；不保证重复咨询一定降至30%。失败停止条件为条目经两轮修订仍未达到用户指定审核标准，停止新增范围并保留已审核条目。
