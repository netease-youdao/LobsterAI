# 可复制升级底稿

```text
升级项目／方案版本／编制日期／材料编号：
软件与版本：当前｜目标｜授权方式｜席位数｜授权覆盖范围。
终端清单：部门｜人数｜系统版本｜位数｜冻结期。
样本测试表：编号｜文件类型｜所属部门｜打开｜编辑｜保存｜旧版回读｜版式｜结论｜验证人。
插件与对接表：名称｜维护方｜新版支持证据｜风险等级｜替代方案或暂缓范围。
批次计划：批次｜范围｜人数｜起止日期｜放行标准｜回退条件｜责任人。
批次上限：试点工单率｜支持上限｜回滚单轮台数与用时｜回滚上限｜取值。
回滚预案：触发条件｜旧版安装包位置｜授权保管人｜操作步骤｜演练记录｜责任人。
通知：预告日期｜提醒日期｜三件要做｜一件不要做｜截图｜值守通道。
问题台账：编号｜现象｜影响人数｜等级｜绕行方法｜状态｜解决时长。
复盘：兼容问题数｜回滚台次｜损失工时｜改进点；关键问题最多三项。
```

## 已填假设示例：120台终端办公套件升级

以下数据均为演示假设，不是实际升级记录。某公司120台终端由“版本甲”升到“版本乙”，新版统一按64位部署。样本测试19份：财务模板8份通过7份，失败1份为32位控件宏；含宏表格5份通过4份；投标文件6份全部可打开，其中1份分页偏移需人工核版。完全通过16份（分页偏移的1份不计入），通过率16÷19约84.2%。财务宏列为高风险，维护方书面答复12月4日前提供新版，财务暂缓到最后一批。

试用批5人（IT两人、志愿者三人），2026年11月2日周一至11月6日周五，期间演练一次回滚，用现有分发方式每轮20台耗时40分钟。试点批为行政部15人，11月9日周一至11月20日周五；前两个工作日共9张工单，工单率9÷15=0.6张每人。值守两人、每人每天处理12张，两天能力48张，支持上限48÷0.6=80人。回退时限4小时，回滚上限为240÷40=6轮，6×20=120台；76台需4轮共160分钟。第三批为财务和投标组以外的76人，11月23日周一升级，低于两个上限。预告于11月18日周三发出，提醒于11月20日周五发出。

假设财务月结冻结期为11月26日至12月3日，投标截止为11月27日。第四批为财务18人与投标组6人共24人，前提是新版宏在12月4日周五前通过8份样本复测；12月7日周一升级，12月11日周五确认全员完成。人数核对5+15+76+24=120。旧版安装包和授权信息至少保留到2027年1月11日周一，复盘安排在2026年12月25日周五。

第三批升级当日起第3个工作日即11月25日周三汇总：共41张工单，阻断1、影响8、体验32；阻断为审批插件导致3人无法提交，2.5小时内修复，未触发回滚，损失工时3×2.5=7.5人时。若第四批宏复测仍失败，财务保留旧版并单独评估授权与替代方案，不为赶进度放行。
