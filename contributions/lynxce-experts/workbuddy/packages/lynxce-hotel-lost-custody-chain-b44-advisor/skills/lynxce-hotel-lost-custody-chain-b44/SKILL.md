# 酒店遗失物跨班保管链

公共独立小任务：检查每件遗失物从发现到当前保管位置的事件链断点。用户为酒店跨班保管员。输入只需物品代号、发现时间、封存号、移位交出及接收记录、班次截止时点。此项按自己的证据键、方法和输出表工作，不以专家摘要替代专项交付，不依赖任何外部接入。

## 工作流程

1. 锁定本项任务：检查每件遗失物从发现到当前保管位置的事件链断点。最少输入为物品代号、发现时间、封存号、移位交出及接收记录、班次截止时点；先给材料范围和截止时点，超出本项范围的请求单独记录。

2. 按最少字段建立证据索引：把发现登记作为链首，用物品代号而非客人姓名关联，房间等位置用内部代号；发现日期与登记日期分列。

3. 建立对象与事件关系：按事件实际时点排序交出、接收、临时取用和归还，接收必须对应同次交出事件，不能用后来接收倒填前班断点。

4. 执行专项推演：链尾的当前保管位置只取最后一对经确认的交接；有交出无接收时当前去向待核，不能默认已到下一班。

5. 检查专属异常与边界：数量核期初＋新发现－已确认领出＝期末；临时取出未归还留在保管责任集合内并单列位置待核。 对照缺资料与冲突案例，确认缺项没有被填成示例值。

6. 交付酒店遗失物跨班保管链文本表与补证队列，逐格保留资料编号及状态。重新核正常与边界算式，给负责人确认入口；实际完成状态以用户后续反馈为准。

## 专项方法与证据顺序

- 把发现登记作为链首，用物品代号而非客人姓名关联，房间等位置用内部代号；发现日期与登记日期分列。

- 链尾的当前保管位置只取最后一对经确认的交接；有交出无接收时当前去向待核，不能默认已到下一班。

- 数量核期初＋新发现－已确认领出＝期末；临时取出未归还留在保管责任集合内并单列位置待核。

## 专属异常和采用条件

- 封袋完整与物品特征确认分开，现场未开袋时不推断袋内状态。

- 两件同色手机不能合并，物品代号及发现事件不同就保留两行。

- 贵重、易腐或危险物只引用酒店既定处置规则，没有规则不编保管天数。

- 签收并不证明领取人为所有人，认领材料走独立人工复核，不在此阶段关闭。

## 资料状态与交付复核

- 引用材料使用资料代号、版本和行号，事实摘录与推演结果分栏。未知值统一写【待补】；补证问题指出缺什么、为什么影响本项判断，以及用户应返回哪一格资料，不能仅泛称完善材料。

- 所有统计注明对象、单位及截止时点，记录数、唯一对象数与关联边数分开。计算从原始值逐步列算式，残差保留符号；不通过四舍五入隐藏冲突，零分母写不适用而非百分之百。

- 文本表是材料审阅草案。建议动作、用户确认拟执行、用户反馈实际完成采用不同状态；无反馈时不得变为完成。这里只用已给文字与表格手工推演，不声称已查询系统、通知人员或操作实物。
