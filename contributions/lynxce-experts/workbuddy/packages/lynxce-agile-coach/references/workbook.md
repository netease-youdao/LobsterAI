# 可复制迭代工作底稿

```text
迭代编号／周期／目标／材料版本：
故事表：编号｜用户结果｜前置条件｜操作｜预期行为｜失败边界｜依赖｜估算依据。
容量表：角色｜人数天数小时｜缺勤｜固定事务｜缓冲比例及基数｜计划容量。
范围表：必做｜候选｜暂缓｜理由｜依赖决策点｜超容量取舍。
站会表：故事编号｜完成证据｜下一步｜阻塞｜需决定内容｜责任角色｜时点。
变更账本：新增范围｜估算｜挤出事项｜决定依据｜批准角色｜版本。
回顾：目标结果｜完成延期取消｜主要事实｜流程原因假设。
行动表：最多三项｜负责人｜下一轮完成证据｜检查日期。
下次交接摘要：当前版本｜未决事项｜保留行动｜需用户补充材料。
```

## 已填假设示例：客服检索迭代

假设四人团队安排十个工作日，每人每日可投入六小时，名义容量为4×10×6=240小时。缺勤24小时、会议及固定支援40小时，剩余176小时；在该基数上预留20%，缓冲35.2小时，计划容量140.8小时。本例每日六小时尚未扣会议；若已经扣过，不可重复扣减。

原候选故事为只读检索120小时、权限范围校验80小时、导出文件100小时、自定义列60小时，合计360小时，超出219.2小时。仅延后自定义列后仍需300小时，仍超出159.2小时，因此原取舍不可行。不能擅自压低估算凑入容量。

一条可供团队讨论的选择：仅在既有权限控制被提供材料证实足够、验收边界成立时，将本轮目标限定为授权测试角色的只读检索，纳入120小时，计划容量余量20.8小时；新增权限规则、导出、自定义列均列后续候选。若既有权限边界不足，此方案也不可承诺交付，应拆出有权限边界的更小故事并由团队重新估算。还须核对各角色的时段与依赖，容量可容纳不等于保证按期完成。

后续候选S03的导出验收草稿：给定客服有导出权限且筛选出三条可见记录，导出文件包含相同记录及约定列，越权记录不出现；无权限时不生成文件。真实格式与提示文案待契约确认。S03不属于本轮承诺，不计本轮完成率。

本轮若唯一承诺的检索故事尚缺权限回归证据，则已验收完成0项、承诺1项，计数完成率0%；不能以编码完成称验收通过。证据补齐后另记录验收日期及结论。回顾行动为下一轮排期前提供含三类角色的权限矩阵，由产品交付、测试复核；交接保留当前范围、未决权限及后续S03候选，由用户提供资料继续更新。
