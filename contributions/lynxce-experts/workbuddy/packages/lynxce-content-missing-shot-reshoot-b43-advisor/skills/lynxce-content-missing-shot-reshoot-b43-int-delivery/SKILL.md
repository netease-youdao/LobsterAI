# 补拍素材缺口映射

内部专项任务：补拍素材缺口映射。只处理补拍条号到粗剪缺口的覆盖矩阵，不替代公开任务的完整交付。核心方法为：以缺口为行、素材条号为列，标完整覆盖、部分覆盖和不可用；一条素材覆盖多个缺口时仍逐缺口检查叙事与连续性，不用素材总数代替覆盖数量。

## 工作流程

1. 确认专项输入为已确认脚本、场记、粗剪缺镜单与剩余档期，锁定所用版本及本次范围，仅抽取与补拍素材缺口映射有关的字段；缺项标【待补】，不要套用演示例子作为事实。

2. 建立补拍条号到粗剪缺口的覆盖矩阵的原始证据列，记录资料编号、原文片段与目前状态；将事实与经办人的解释分栏，矛盾内容保留两种记录。

3. 以缺口为行、素材条号为列，标完整覆盖、部分覆盖和不可用；一条素材覆盖多个缺口时仍逐缺口检查叙事与连续性，不用素材总数代替覆盖数量。拟以替代素材取消拍摄时，逐缺口核素材清单及入出点、需求/可用时长、适用的使用授权、叙事与连续性记录、同版本负责人批准；全部齐备且一致才能条件取消。缺项、冲突或批准撤回时保留待拍/风险，按受影响缺口重算排程，不能沿用其他缺口的批准。

4. 逐项采用专属方法核查：可用条记录镜号、条号、用户提供的文件代号、头尾范围和对应缺口，一个条目覆盖多个段落需分别标出适用范围，避免同一素材被误算成多份新拍摄。保留原始值和推演值，让复核人能够独立重现过程。

5. 用专项示例检查数量守恒及分类互斥：假设4处待补缺口，收到6条素材，其中3处完整覆盖、1处仅部分覆盖，完整覆盖率3÷4＝75%；收到6条不代表已完成全部4处。遇到不闭合结果，先找遗漏与重叠，不能为了闭合改写事实。

6. 输出补拍条号到粗剪缺口的覆盖矩阵并列待补项、影响范围、复核人及下次更新条件；没有用户反馈的条目不变更为已完成，专项结果交由主流程采用。

## 专项证据方法

- 对收音失败的镜头列同期重录、旁白替代等文本方案及适用条件，不宣称已经降噪或恢复音轨；人物口型必须匹配时由剪辑负责人确认可接受方式。

- 可用条记录镜号、条号、用户提供的文件代号、头尾范围和对应缺口，一个条目覆盖多个段落需分别标出适用范围，避免同一素材被误算成多份新拍摄。

- 补拍后逐项对照原缺镜清单，关键缺口未补齐时保持未完成；用户反馈现场新增缺口，单列追加范围与窗口影响，不悄悄挤占原先已经承诺的时间块。

- 最终成果附剪辑交付注意项、连续性未确认项和负责人选择，表格仅为执行依据；材料没有实际验看记录时不能输出可用率或已完成补拍的确定说法。

## 专项模板与决策

- 以缺口为行、素材条号为列，标完整覆盖、部分覆盖和不可用；一条素材覆盖多个缺口时仍逐缺口检查叙事与连续性，不用素材总数代替覆盖数量。

- 每一行以专项对象编号为主键，与公开成果只通过资料编号关联，不复写公开交付全文；表头固定包含原状态、证据位置、专项判断和待核动作。

- 分支状态采用已确认、待证据和存在冲突三类；待证据不是否定，存在冲突不能合并为已确认，后续反馈到来后再记录原状态和新状态。

- 复核意见必须包含可观察依据与采用版本，确认人没有提供时标【待补】；文字建议与实际执行分栏，避免专项草案被误读为已经完成的业务。

## 复核与版本

- 资料入口采用最小必要字段，先核用户提供的版本、时间与适用范围；原始记录和解释意见分别保存，缺项统一写【待补】。存在两份冲突资料时并排列出，不擅自选更有利的一份，也不把演示数字补成真实业务事实。

- 输出每条判断对应的资料编号、所用方法和状态，记录谁需要确认以及确认后会改变哪一项结果。所有数量注明单位，计算保留分子分母和逐步算式；舍入只用于展示，原值与修正值均保留以便复核。

- 表格是根据给定资料编写的文本草案，计划、人员自报、资料核对通过和实际完成分开记录。没有实际反馈就维持待确认，不能声称已经读取业务系统、发送通知或执行现实任务；也不提供任何资格认定或虚构外部验证。

- 完成前先检查每条输入是否有去向、每条输出是否有来源、每个异常是否有承接动作。后续更新只改有新证据的条目，保留旧版本与变更理由；超出本任务的请求列具体缺项或交接建议，不把未核实事实写进结论。

## 假设案例

以下为专项假设，非真实业务结果：假设4处待补缺口，收到6条素材，其中3处完整覆盖、1处仅部分覆盖，完整覆盖率3÷4＝75%；收到6条不代表已完成全部4处。该示例只演示专项判断的分类与数值核对。实际使用时先把资料对象逐行编号，保留原始证据，再执行所列方法；不符合前置条件的对象必须单列待核，不能放入已确认数量。若用户补充记录导致判断改变，记录新增依据、原状态和新状态，重新计算受影响的分母与合计。最终只输出文本对照表和复核建议，不宣称已执行外部任务。复核时逐项检查对象总数、已确认数和待核数是否闭合，注明所用资料版本与计量单位；发现输入修订时只重算受影响条目，并在输出中保留旧值、修订值和差异原因，交由业务负责人确认后再更新主流程记录。
