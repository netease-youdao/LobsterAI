# 家政遗留事项接续单

内部专项任务：家政遗留事项接续单。只处理跨次事项状态与承接条件清单，不替代公开任务的完整交付。核心方法为：为每个遗留事项设置关闭依据及重开原因，等待条件与未完成分开；本次无授权事项不得占已承诺容量，关闭项只有出现新证据才重新进入下次清单。

## 工作流程

1. 确认专项输入为上次服务记录、遗留事项、家庭授权范围与本次时段，锁定所用版本及本次范围，仅抽取与家政遗留事项接续单有关的字段；缺项标【待补】，不要套用演示例子作为事实。

2. 建立跨次事项状态与承接条件清单的原始证据列，记录资料编号、原文片段与目前状态；将事实与经办人的解释分栏，矛盾内容保留两种记录。

3. 为每个遗留事项设置关闭依据及重开原因，等待条件与未完成分开；本次无授权事项不得占已承诺容量，关闭项只有出现新证据才重新进入下次清单。每项都说明判断顺序、触发条件和例外，缺关键条件时不强行给确定结论。

4. 逐项采用专属方法核查：对异常物品状态保留原描述、发现时点和待确认人，不评价身份或资质；如用户希望赔偿结论，只整理所给约定和事实缺口，交相关负责人员判断。保留原始值和推演值，让复核人能够独立重现过程。

5. 用专项示例检查数量守恒及分类互斥：假设上次7项，其中3项已确认关闭、2项待授权、2项本次承接，3＋2＋2＝7；本次完成承接1项后，未关闭剩3项，不能报成全部7项仍待做。遇到不闭合结果，先找遗漏与重叠，不能为了闭合改写事实。

6. 输出跨次事项状态与承接条件清单并列待补项、影响范围、复核人及下次更新条件；没有用户反馈的条目不变更为已完成，专项结果交由主流程采用。

## 专项证据方法

- 复核采用具体可观察状态，如工具归位、清单动作完成和遗留问题有记录，不用满意度代替任务证据；用户未现场确认时区分人员自报与委托人已确认。

- 对异常物品状态保留原描述、发现时点和待确认人，不评价身份或资质；如用户希望赔偿结论，只整理所给约定和事实缺口，交相关负责人员判断。

- 下次复查事项给观察时间与允许动作，持续渗漏或设备异常不转成一般保洁任务；依据用户提供安排记录转交建议，不能声称已经安排维修或联系他人。

- 交付时用已关闭、待确认、待条件与下次承接四类汇总，每项只计一次；下次更新保留上次版本与关闭依据，避免跨次清单不断累积已经解决的问题。

## 专项模板与决策

- 为每个遗留事项设置关闭依据及重开原因，等待条件与未完成分开；本次无授权事项不得占已承诺容量，关闭项只有出现新证据才重新进入下次清单。

- 每一行以专项对象编号为主键，与公开成果只通过资料编号关联，不复写公开交付全文；表头固定包含原状态、证据位置、专项判断和待核动作。

- 分支状态采用已确认、待证据和存在冲突三类；待证据不是否定，存在冲突不能合并为已确认，后续反馈到来后再记录原状态和新状态。

- 复核意见必须包含可观察依据与采用版本，确认人没有提供时标【待补】；文字建议与实际执行分栏，避免专项草案被误读为已经完成的业务。

## 复核与版本

- 资料入口采用最小必要字段，先核用户提供的版本、时间与适用范围；原始记录和解释意见分别保存，缺项统一写【待补】。存在两份冲突资料时并排列出，不擅自选更有利的一份，也不把演示数字补成真实业务事实。

- 输出每条判断对应的资料编号、所用方法和状态，记录谁需要确认以及确认后会改变哪一项结果。所有数量注明单位，计算保留分子分母和逐步算式；舍入只用于展示，原值与修正值均保留以便复核。

- 表格是根据给定资料编写的文本草案，计划、人员自报、资料核对通过和实际完成分开记录。没有实际反馈就维持待确认，不能声称已经读取业务系统、发送通知或执行现实任务；也不提供任何资格认定或虚构外部验证。

- 完成前先检查每条输入是否有去向、每条输出是否有来源、每个异常是否有承接动作。后续更新只改有新证据的条目，保留旧版本与变更理由；超出本任务的请求列具体缺项或交接建议，不把未核实事实写进结论。

## 假设案例

以下为专项假设，非真实业务结果：假设上次7项，其中3项已确认关闭、2项待授权、2项本次承接，3＋2＋2＝7；本次完成承接1项后，未关闭剩3项，不能报成全部7项仍待做。该示例只演示专项判断的分类与数值核对。实际使用时先把资料对象逐行编号，保留原始证据，再执行所列方法；不符合前置条件的对象必须单列待核，不能放入已确认数量。若用户补充记录导致判断改变，记录新增依据、原状态和新状态，重新计算受影响的分母与合计。最终只输出文本对照表和复核建议，不宣称已执行外部任务。复核时逐项检查对象总数、已确认数和待核数是否闭合，注明所用资料版本与计量单位；发现输入修订时只重算受影响条目，并在输出中保留旧值、修订值和差异原因，交由业务负责人确认后再更新主流程记录。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
