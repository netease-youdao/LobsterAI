# 退货检查条件证据覆盖核对

面向退货仓检员与库位复核员的独立小任务：退货检查条件证据覆盖核对。适用阶段为退货已接收、实物待再次入库的逐件状态复核阶段。最少事实输入为已确认件号清单、内部检查条件版本、逐件检查摘录及复核范围；交付件号乘检查条件覆盖矩阵与最少补证单。核心方法：以件号乘适用条件为格，区分支持、明确不满足、未记录和冲突；逐件核所有适用格，不把总体照片覆盖率当作逐件通过率。输入仅接收用户主动提供的脱敏文本或表格摘录，记录来源代号与原文位置；不要求业务系统接入，示例不能补真实资料。

## 工作流程

1. 接收身份已确认的件号，不复用无码件的猜测身份。 接收时先登记来源、版本、对象范围和记录截点；若用户只给部分记录，交付已知范围并列最少缺项，不把没提供的数据补成零。

2. 拆给定条件为可核查的格，逐件标适用或有依据不适用。 对象编号与资料行号应分开，整理值不覆盖原值。重复引用是证据复用而不是新增业务对象，同名对象必须查身份关系再合并。

3. 给每格挂检查记录，同张照片多次引用只计其覆盖的条件。 处理时按本任务方法逐项核查，事实、陈述、派生计算和建议分别标识。支持某一条件的证据不可自动扩展到其它条件。

4. 明确不满足与无记录分开，冲突格并列两源而不取多数。 条件不全给局部成果，矛盾给双值及来源；请用户指定确认角色，不取平均、不选更有利数值，也不把询问草稿记为完成动作。

5. 按格算覆盖数量，再逐件检查是否所有适用格有一致依据。 复核应从来源重新取原值，检查单位、分母、版本和状态互斥性；已明确未知的字段保持未知，不以合计能对齐反推缺失事实。

6. 交付缺证格对应的补采动作，复核后只回填覆盖状态。 交付时保留仍未解决的行和下一核实动作，说明接收角色与完成凭据。新资料到来按原对象续版，人工确认与实际执行仍分开。

## 对象与资料门槛

- 条件是用户原标准，不加通用售卖规则。

- 无配件条件须核不适用依据。

- 包装照片不能支持通电条件。

- 口头说检查过但无内容不记支持。

## 专属判断与异常分支

- 证据时点应晚于本次接收。

- 同格两份相反记录仍为冲突。

- 记录明确破损是事实摘录而非责任。

- 条件格数量与件数分开。

## 输出验收与状态边界

- 支持格比例不能代替合格件比例。

- 补采只提出缺失角度或原记录。

- 复核人范围缺失保留待补。

- 输出不能认证产品安全或质量等级。

## 五类内容设计假设案例（非模型实测）

- 正常：假设3件各2适用条件，4格支持、1格未知、1格不满足。 预期：总6格，支持4/6约66.67%，不能据此说2件通过。

- 缺资料：假设检查标准缺版本。 预期：条件版本【待补】，覆盖表暂不据此定候选。

- 矛盾：假设同格分别写完好和破损。 预期：冲突格不计支持，保留双源。

- 边界：假设某件一项条件由负责人确认不适用，其余两项有证据。 预期：只按2个适用格核，另留不适用理由。

- 超出能力：假设要求据照片发质量认证。 预期：仅列可见记录与缺证格，不出认证结论。

## 假设案例

以下数字全部为可复算的内容设计假设，不代表真实业务或模型实测。假设3件每件有包装、配件两项条件，总格数3×2＝6。支持4格、未知1格、不满足1格，4＋1＋1＝6；支持格占66.67%。如果支持格分布为每件2、1、1格，完整覆盖仅1件，不能把4格除2直接报2件完整。

## 能力边界
