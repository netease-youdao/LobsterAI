# 退货逐件再入库状态证据表

面向退货仓检员与库位复核员的独立小任务：退货逐件再入库状态证据表。适用阶段为退货已接收、实物待再次入库的逐件状态复核阶段。最少事实输入为退货件号、货号批次、接收清单、逐件外观及配件检查摘录、商家给定再入库条件、复核角色；交付逐件状态证据矩阵、候选再入库件清单、待补或隔离复核清单。核心方法：以件号关联身份、状态和授权三个门槛；每个门槛分别查证据，不用数量相等替代状态满足。候选量只计三个门槛均有依据的件，实际过账另待用户反馈。输入仅接收用户主动提供的脱敏文本或表格摘录，记录来源代号与原文位置；不要求业务系统接入，示例不能补真实资料。

## 工作流程

1. 先选已实际接收且尚未再次入库的一批退货，记录清单版本和截点；申请退货的数量只作背景，未接收件不进入本批。 接收时先登记来源、版本、对象范围和记录截点；若用户只给部分记录，交付已知范围并列最少缺项，不把没提供的数据补成零。

2. 为每件绑定退货件号、货号和批次，将同箱多件拆行；无码件单列待识别，不能用客户订单中的商品名代替实物身份。 对象编号与资料行号应分开，整理值不覆盖原值。重复引用是证据复用而不是新增业务对象，同名对象必须查身份关系再合并。

3. 把用户给定条件拆为外观、配件、包装或其它适用项，每一项关联逐件检查记录；只有包装照片不能确认内部配件齐全。 处理时按本任务方法逐项核查，事实、陈述、派生计算和建议分别标识。支持某一条件的证据不可自动扩展到其它条件。

4. 逐门槛核身份一致、条件满足和复核授权；三个门槛均有依据才写候选，不满足、缺资料与冲突分别保留，不替店铺制定可售标准。 条件不全给局部成果，矛盾给双值及来源；请用户指定确认角色，不取平均、不选更有利数值，也不把询问草稿记为完成动作。

5. 核每件只归一个当前状态，候选加待补加冲突加不满足应等于已接收件数；发现件号重复先排查重贴标或错映射。 复核应从来源重新取原值，检查单位、分母、版本和状态互斥性；已明确未知的字段保持未知，不以合计能对齐反推缺失事实。

6. 交付候选清单及需人工确认的库位、数量、证据，说明候选不等于已过账；收到新检查摘录只重核对应件并留前后版本。 交付时保留仍未解决的行和下一核实动作，说明接收角色与完成凭据。新资料到来按原对象续版，人工确认与实际执行仍分开。

## 对象与资料门槛

- 接收数量以件为单位，箱数保留在包装栏；一箱六件不能登记成一件，也不能默认六件来自同一批次。

- 照片必须能对应件号与检查时点；无法读出标签时只记录可见状态，不凭相似外观认定同一件。

- 条件版本缺失时可整理已有证据，但候选栏仍待补；不引用其它商家的二次销售经验填充门槛。

- 每个不适用条件要有用户确认理由；例如该货无独立配件，不能把配件栏空白直接当作齐全。

## 专属判断与异常分支

- 配件检查和功能检查互不替代；记录写配件齐全不意味着功能正常，记录写通电不意味着符合全部条件。

- 授权仅核记录中的确认范围；仓检人员签字不能自动推成店铺负责人已允许销售或已批准过账。

- 身份冲突件停止状态汇总中的候选计数；仍保留已接收总量，不删除问题件让表面通过率上升。

- 同件同时出现在候选与隔离单时，保留两个来源并要求确认生效状态，不以文件修改时间直接覆盖。

## 输出验收与状态边界

- 已出库的原件被再次退回应建新接收事件；原检查可引用为历史，不继承为本次现况证据。

- 部分套件缺件必须按用户给出的套件规则核，不能把可见主件拆售当作已被授权的处理方法。

- 拟接收库位和实际放置库位分列，没有现场确认时位置写待确认；不得宣称已经移动货品。

- 验收逐件抽回来源核对身份、条件与授权三栏；未知值不计为否，也不计为是，必须独立计数。

## 五类内容设计假设案例（非模型实测）

- 正常：假设已接收12件，8件三个门槛完整、2件少配件照片、1件标签冲突、1件按给定规则不满足。 预期：候选8、待补2、冲突1、不满足1，总数12；候选比例8/12约66.67%，只建议人工复核这8件。

- 缺资料：假设12件都有接收记录，检查表未给批次身份，其中8件有外观照片。 预期：仍记录接收12件，批次身份【待补】；不能将8件照片数当作候选数，也不能据缺资料判定12件不合格。

- 矛盾：假设件R3在候选单为完整，隔离单写缺电源线，两单均未指定生效版本。 预期：R3记冲突并从候选建议中排除，两个原值均保留；需核配件检查原记录及授权确认。

- 边界：假设一套含主件1件和附件2件，用户规则只允许整套再入库，现场只有主件及附件1件。 预期：实收2件而所需3件，缺1件；不能将主件写成一个合格整套，套与件在不同栏。

- 超出能力：假设要求直接把候选8件改成可售库存，并判定退款责任。 预期：仅输出8件待审批证据清单，过账与责任决定交授权人员；不操作库存或作法律责任结论。

## 本任务结果的使用顺序

- 先核退货件号/货号批次与来源：本成果的每行以该对象为锚，后续收到修订资料必须回填同一对象。对象换了要新建行，不能沿用旧证据省略核对。

- 再核方法是否具备前提：以件号关联身份、状态和授权三个门槛；每个门槛分别查证据，不用数量相等替代状态满足。候选量只计三个门槛均有依据的件，实际过账另待用户反馈。 没有对应输入时只交缺项说明，不将演示算式当成业务记录。

- 异常行独立交接：逐件状态证据矩阵、候选再入库件清单、待补或隔离复核清单中每个待确认项注明影响字段、缺少的事实材料、接收角色和复核时点。只提能改变判断的问题，不要求与本任务无关的整套资料。

- 最终验收按下一人工复核及版本记录复核，逐条回查证据。文本完成、负责人确认、现场执行是不同状态；本表整理完成不代表整段业务已闭环，也不替用户作专业结论。
