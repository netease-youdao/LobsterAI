# 退货件号与原货批次映射

面向退货仓检员与库位复核员的独立小任务：退货件号与原货批次映射。适用阶段为退货已接收、实物待再次入库的逐件状态复核阶段。最少事实输入为接收件号表、用户提供原货批次摘录、实物标签转录、重贴标关联记录；交付件号到批次映射表与无码重号例外单。核心方法：以接收事件加件号为主键，按原标签、重贴标凭据、批次摘录做链式映射；缺任一连接不补猜，多对一映射保留候选而不强制归并。输入仅接收用户主动提供的脱敏文本或表格摘录，记录来源代号与原文位置；不要求业务系统接入，示例不能补真实资料。

## 工作流程

1. 限定同一接收事件，收齐件号与标签转录，不读取任何未提供的订单系统。 接收时先登记来源、版本、对象范围和记录截点；若用户只给部分记录，交付已知范围并列最少缺项，不把没提供的数据补成零。

2. 保存标签原串及标准化串，前导零与字母大小写差别先按用户编码规则处理。 对象编号与资料行号应分开，整理值不覆盖原值。重复引用是证据复用而不是新增业务对象，同名对象必须查身份关系再合并。

3. 用重贴标凭据连接新旧标签，没有凭据的新标签不凭相似数字归原件。 处理时按本任务方法逐项核查，事实、陈述、派生计算和建议分别标识。支持某一条件的证据不可自动扩展到其它条件。

4. 逐件检查匹配条数，零条记待识别、一条核依据、多条记冲突，不任选首条。 条件不全给局部成果，矛盾给双值及来源；请用户指定确认角色，不取平均、不选更有利数值，也不把询问草稿记为完成动作。

5. 核唯一映射件数与例外件数合计接收件数，并检查同一原件是否被重复映射。 复核应从来源重新取原值，检查单位、分母、版本和状态互斥性；已明确未知的字段保持未知，不以合计能对齐反推缺失事实。

6. 交付映射与例外单，只有身份核对结果可回填状态表，不能代替状态检查。 交付时保留仍未解决的行和下一核实动作，说明接收角色与完成凭据。新资料到来按原对象续版，人工确认与实际执行仍分开。

## 对象与资料门槛

- 接收事件不同的同件号不可合并。

- 货号一致不能覆盖批次不一致。

- 编码中的连字符按原串保存。

- 用户未给编码规则不擅自去零。

## 专属判断与异常分支

- 重贴标应有双端编号及时点。

- 映射来源记录页码或行号。

- 同一原件对应两新码须核拆件记录。

- 无码件仍占接收总量。

## 输出验收与状态边界

- 冲突不取最相似候选。

- 人工更正保留原串与理由。

- 身份唯一不等于外观正常。

- 输出仅给身份核对状态。

## 五类内容设计假设案例（非模型实测）

- 正常：假设5件中3件唯一映射、1件无码、1件重号。 预期：唯一3、例外2，3+1+1=5。

- 缺资料：假设有新标签但无重贴标关联记录。 预期：原件连接【待补】，不依据号段补猜。

- 矛盾：假设一新码对应甲乙两个批次。 预期：保留两个候选，身份冲突。

- 边界：假设标签007与7同时出现且编码规则不明。 预期：保留两串，不能去零合并。

- 超出能力：假设要求认证标签真伪。 预期：只核资料映射，真伪鉴定交授权专业人员。
