# 出餐工序负荷核算

内部技能独立任务：工序展开与人秒守恒核对。输入为工序件数、实测秒数、停顿与可用窗口，输出为工序需求能力明细与边界表；每行固定一个工序与窗口，将批次工时分摊口径写明；并行工位计算总人秒，串行设备另做设备秒数限制，最终可行性同时满足人员与设备两类约束。

## 工作流程

1. 1、限定子任务为工序展开与人秒守恒核对，仅接收工序件数、实测秒数、停顿与可用窗口。保留资料版本、对象代号、人工确认范围与记录日期，缺少关键字段先列【待补】，不扩大为整段业务的最终决定。

2. 2、用子任务独立编号关联公开技能的问题行，输入原值与派生值分开；核同名对象、重复事件与单位。每行固定一个工序与窗口，将批次工时分摊口径写明；并行工位计算总人秒，串行设备另做设备秒数限制，最终可行性同时满足人员与设备两类约束。

3. 3、建立工序展开与人秒守恒核对的判定分支：输入完整则进入方法核对，存在冲突则并列两值待确认，条件不足则产出局部表格和补证问题，不能绕过依赖直接给结论。

4. 4、按照独特方法形成工序需求能力明细与边界表，逐行说明原记录、处理动作、依据及状态；需要人工确认的动作保留草案标签，不替工作人员填写已经完成或署名。

5. 5、复核本子任务中的数量、日期、证据覆盖与状态边界，随机抽回原文检查字段是否走样。发现错误保存原值、修正值和理由，不把空白直接当作零或默认同意。

6. 6、将工序需求能力明细与边界表回填为专家流程的中间成果，写明未解决的依赖与下一接收角色；尚未完成的子任务不升级为业务闭环，后续新资料按版本再次核对。

## 独特方法与证据粒度

- 每行固定一个工序与窗口，将批次工时分摊口径写明；并行工位计算总人秒，串行设备另做设备秒数限制，最终可行性同时满足人员与设备两类约束。

- 把工序件数、实测秒数、停顿与可用窗口按对象与事件分别编号，材料数量不等于已证实事项数量，合并记录前保留合并依据和关联行号。

- 对子任务输出工序需求能力明细与边界表明确字段定义，原值、解释与动作分列；每个解释只覆盖来源实际支持的范围。

- 两条记录相似时核对象与时间，不因语义相近删掉真实独立事件；同一记录多次出现时保留一次计数及引用位置。

## 子任务决策与模板使用

- 资料齐全且无矛盾时按工序展开与人秒守恒核对执行，输出可复核中间表而不是整项业务完成声明。

- 关键条件缺失时列三项以内最小补充问题，写明每个问题改变哪一行判断，已经被用户说明未知的字段不反复追问。

- 冲突条目保留双方原话、发生时点和证据代号，请用户指定的业务负责人确认后再修订，未经确认保持待核。

- 模板里的【待补】需要逐项填写依据；该字段确实不适用时明确写不适用及原因，不用空白掩盖缺资料。

## 异常与验收

- 检查工序需求能力明细与边界表能否回连原问题编号，脱离对象的泛化建议移至说明区，不能混入事实表。

- 若补证只解决一部分条件，其他条件仍维持原状态；不要把一条新记录当成全部矛盾均已解决。

- 数值例子仅作方法演示，实务必须换成用户给出的数字并复算；单位、分母和时间截点均写在结果旁。

- 交付复核角色、仍欠资料和下一确认动作；只提供文本表格，不声称连接业务系统或已执行人员调度。

## 假设案例

以下为独立子任务的假设演示：假设二十件装配每件18秒，需360人秒；一人窗口300秒，负荷120%，短缺60人秒。即使相邻站有100秒空闲，未确认该人员装配能力前仍保持短缺60秒。本例与公开技能的整段成果分开，先保留输入原值，再写方法对应的派生字段、未完成条件及下一次核对动作。收到新证据时须核同一对象和版本是否适用，确认后回填原问题编号；不能用本例默认值补真实记录。复核人员应逐行看原值与结果的映射，若用户没有给出复核结果，交付状态仍写待人工复核。示例数字只供解释计算与状态边界，不代表实际订单、门店人数、执行结果或任何系统数据。

## 能力边界
