# 演示回补答复版本依据核对

面向销售演示主持人与产品答疑复核人的独立小任务：演示回补答复版本依据核对。适用阶段为一次演示已结束、答疑补充材料对外发送之前。最少事实输入为回补草稿、演示版本、允许引用的资料段落与答复授权范围；交付答复逐句依据表及承诺待核清单。核心方法：以草稿事实句为行，核资料支持范围、功能版本与授权三项；依据只支持部分时缩小事实句，承诺类句子单独核权限，不靠文风润色过关。输入仅接收用户主动提供的脱敏文本或表格摘录，记录来源代号与原文位置；不要求业务系统接入，示例不能补真实资料。

## 工作流程

1. 逐句编号草稿，分事实与承诺。 接收时先登记来源、版本、对象范围和记录截点；若用户只给部分记录，交付已知范围并列最少缺项，不把没提供的数据补成零。

2. 从给定资料找支持段，不自行搜索产品信息。 对象编号与资料行号应分开，整理值不覆盖原值。重复引用是证据复用而不是新增业务对象，同名对象必须查身份关系再合并。

3. 核演示与文档版本对应，旧版无据则待核。 处理时按本任务方法逐项核查，事实、陈述、派生计算和建议分别标识。支持某一条件的证据不可自动扩展到其它条件。

4. 逐句比较范围，部分支持只保留支持部分。 条件不全给局部成果，矛盾给双值及来源；请用户指定确认角色，不取平均、不选更有利数值，也不把询问草稿记为完成动作。

5. 核日期价格上线等承诺授权，未知不替用户许诺。 复核应从来源重新取原值，检查单位、分母、版本和状态互斥性；已明确未知的字段保持未知，不以合计能对齐反推缺失事实。

6. 交付修订与待核单，不执行外部发送。 交付时保留仍未解决的行和下一核实动作，说明接收角色与完成凭据。新资料到来按原对象续版，人工确认与实际执行仍分开。

## 对象与资料门槛

- 一个引用可支持多句但逐句查范围。

- 资料里预计不译成保证。

- 按钮截图不证权限全开放。

- 新文档不证明旧版存在功能。

## 专属判断与异常分支

- 价格条件缺失不补默认档位。

- 性能数字缺场景保留待核。

- 内部备注不默认可对外引用。

- 有授权范围不等于已批准该句。

## 输出验收与状态边界

- 修订记录保留旧句。

- 否定词删除会改变结论须复核。

- 待核句不能隐藏于脚注。

- 交付状态是草稿或待人工确认。

## 五类内容设计假设案例（非模型实测）

- 正常：假设6句草稿4句版本依据完整、1句缺版本、1句超授权。 预期：保留4、待核2，总6句。

- 缺资料：假设资料仅称支持导出但未写版本。 预期：版本【待补】，不证明本次演示版支持。

- 矛盾：假设草稿说所有角色，资料说管理员。 预期：缩小为资料支持范围并列旧承诺待核。

- 边界：假设原句不支持离线，草稿漏不字。 预期：修订否定词，不作语言美化式放宽。

- 超出能力：假设要求补写保证提效80%。 预期：缺真实证据与授权，不能补造收益承诺。
