# 电商售前需求事实表

本技能用于售前对话中的使用条件与规格事实。使用者提供脱敏售前对话、用户使用场景、商家已确认规格、回复权限与资料版本，交付逐句事实需求表、未确认问题清单与中性客服回复草案。先列影响判断的缺项和冲突，再按问题编号展示证据；只根据实际给出的业务资料制作文本与表格，不作资质结论，不代替岗位人员确认事实。

## 工作流程

1. 1、将“适合我吗”拆成使用对象、环境条件、已有约束和待确认规格，保留用户原话，不把询问意向改写为决定。输入只来自用户提供的文本或表格，先列来源、日期和可用范围。资料里带个人信息时用代号替代，保留与任务有关的事实；没有提供的记录写【待补】，示例不参与实际判断。

2. 2、把必须满足的条件与一般偏好分列，只有用户明确确认的条件才标为硬约束，颜色喜好不升级为兼容要求。逐条编号并建立对象映射，原句与整理后的字段分开保存。一个对象有多条记录时先核是否同一事件、同一版本，不能因文本相似删除真实不同记录，无法确定则列待核。

3. 3、对“可以”“可能”“待核实”逐词检查证据强度，资料只说明一个规格时不能扩展成整个场景均适用。明确本次判断依赖哪些事实和业务条件，把未知、冲突、已确认分开。条件欠缺时给出能继续的局部成果和最少补充清单，不把信息缺失解释为不存在问题。

4. 4、客户条件变动后只重核受影响字段，保留前后版本与变化原因；原答案涉及该字段的句子标为需要重新确认。按方法生成可由岗位人员审阅的文本草案，每个动作注明依据、前置条件、责任角色与待确认点。只组织给定资料，不声称已经通知人员、修改记录或执行现场动作。

5. 5、对有证据的问题产出可回答清单，对缺证据问题产出向商家核实的问题单，接收新资料后以原问题编号回填。检查数字单位、分母、时间截点、对象重复和状态转换，另请用户指定复核角色。新证据改变判断时保留原版本与修正原因，历史结论不静默替换，未复核项仍单列。

6. 6、交接给下一位客服时保留用户已经回答的条件，避免重复询问；未确认参数必须仍标未知，不因交接而变为肯定。按模板交付主要表格、异常表和下一步问题，说明哪部分能直接复用、哪部分必须补资料。验收只依据本任务已确认条件，计划、人工确认与实际完成分别表述。

## 资料与对象界定

- 将“适合我吗”拆成使用对象、环境条件、已有约束和待确认规格，保留用户原话，不把询问意向改写为决定。 每条结论附对象编号和原文出处代号，便于业务人员回看；来源没有覆盖到的内容保持未知，不能由相邻记录或习惯做法推补。

- 把必须满足的条件与一般偏好分列，只有用户明确确认的条件才标为硬约束，颜色喜好不升级为兼容要求。 若两个来源不一致，保留双方值并指出影响哪些后续判断；没有指定生效版本时，请负责人确认，不自行挑选更有利的一方。

- 每个规格事实对应商家提供的资料页代号和版本，同一字段有两个版本时并列记录，不能按更新时间猜测生效关系。 输出时将已确认、待补、存在冲突分栏，字段变化须记录版本和原因；表格可供人工复核，但不能替代尚未发生的现场检查。

- 将会话按客户问题编号归档，一个问题对应一个回答范围；涉及没有提供的参数时明确列入待补，不用常见经验替代。 用给出的数字复算汇总并展示单位与分母，空值不视为零；异常必须有下一核实动作和责任角色，不能只写模糊的继续关注。

## 业务分支与处理方法

- 先问会改变回答的关键缺项，例如使用空间与已知尺寸，再问表达偏好；每轮最多提出三项紧要问题并说明所需单位。 每条结论附对象编号和原文出处代号，便于业务人员回看；来源没有覆盖到的内容保持未知，不能由相邻记录或习惯做法推补。

- 将中性答复分为已确认事实、尚不能确认的条件、需要客户补充的资料三部分，不加入商品排序或成交推动。 若两个来源不一致，保留双方值并指出影响哪些后续判断；没有指定生效版本时，请负责人确认，不自行挑选更有利的一方。

- 对“可以”“可能”“待核实”逐词检查证据强度，资料只说明一个规格时不能扩展成整个场景均适用。 输出时将已确认、待补、存在冲突分栏，字段变化须记录版本和原因；表格可供人工复核，但不能替代尚未发生的现场检查。

- 客户条件变动后只重核受影响字段，保留前后版本与变化原因；原答案涉及该字段的句子标为需要重新确认。 用给出的数字复算汇总并展示单位与分母，空值不视为零；异常必须有下一核实动作和责任角色，不能只写模糊的继续关注。

## 异常复核与成果验收

- 对有证据的问题产出可回答清单，对缺证据问题产出向商家核实的问题单，接收新资料后以原问题编号回填。 每条结论附对象编号和原文出处代号，便于业务人员回看；来源没有覆盖到的内容保持未知，不能由相邻记录或习惯做法推补。

- 交接给下一位客服时保留用户已经回答的条件，避免重复询问；未确认参数必须仍标未知，不因交接而变为肯定。 若两个来源不一致，保留双方值并指出影响哪些后续判断；没有指定生效版本时，请负责人确认，不自行挑选更有利的一方。

- 复核表检查用户条件与商家事实是否混写，检查单位、时间和版本；回复中的每个事实都应回到对应证据行。 输出时将已确认、待补、存在冲突分栏，字段变化须记录版本和原因；表格可供人工复核，但不能替代尚未发生的现场检查。

- 成果验收以问题覆盖、未知保留和事实可追溯为准，不用销量、转化率或用户购买行为判断澄清是否完成。 用给出的数字复算汇总并展示单位与分母，空值不视为零；异常必须有下一核实动作和责任角色，不能只写模糊的继续关注。

## 假设案例

假设客服收到六个售前问题，编号Q1至Q6。商家版本甲资料能够直接回答Q1、Q2、Q3、Q4，Q5缺少用户的安装净宽，Q6缺少商家提供的边界条件。已可回答四项，待确认两项，四加二等于六；可回答覆盖率为4÷6×100%=66.67%，分母是六个去重问题而非聊天句数。用户后来给出净宽58厘米，但商家规格页写外廓60厘米，不能因为用户表示愿意尝试就写“可以使用”。将Q5标为条件冲突，回复草案说明两项数值来自不同来源、当前条件仍需核实；Q6继续待补。第二版仍有四项可回答，一项冲突、一项缺证据，三组数量合计六。若用户撤回Q5，新版本应注明撤回一项、有效问题五项，可回答覆盖率改为4÷5×100%=80%，不得沿用66.67%。此例只演示事实整理，不形成商品推荐或下单建议，实际尺寸与资料以用户给出的记录为准。
