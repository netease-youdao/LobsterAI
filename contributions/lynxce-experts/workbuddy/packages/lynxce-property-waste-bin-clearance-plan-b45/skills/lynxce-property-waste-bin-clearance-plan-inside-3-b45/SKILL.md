# 漏班后重排与班次说明

## 要解决的具体问题
把一次未清运或增量落实到剩余班次，给保洁协调员可执行的短句。
这是专家工作链中的第3项独立能力。只处理本节写明的对象与口径，不接管其它子任务。用户可以直接给脱敏文字表格，交付也是可复制的文本；没有外部服务依赖。

## 最低输入与进入条件
原版班次、变更截点、用户反馈已清数量或清后余量、剩余窗口、班组可用分钟。
先以任务代号固定对象，再写本轮截点。输入有一项缺失时，先把已知对象写进本节的交付格式；只有依赖缺项的计算或措辞暂留【待补】，不让用户重填全部材料。对真正影响决策的缺口一次最多问三个问题。

## 专属操作方法
锁定已发生段，漏班清走量改零后逐段重算。只用尚可发生的窗口恢复安排；若窗口前已超容明确原方案不可维持，提出加容或新窗口待确认。班次短句写点位、具体时间、清后目标余量及要回报的一个实测点，不说系统已派工。

## 可直接使用的输出与已填例子
假设原10点清100升但漏班，12点前累计230升对192升超38升；不能只说12点清空即可恢复全天正常。草稿：“P点原10点清运未执行，至12点按预测超38升，请确认是否增加临时容量或提供段内清运窗口。”

## 复核、异常与回传
历史未发生动作不补成已做。投放增长不改变已记录清后余量；人员不足时交冲突与候选，不假设保洁员可以同时在两点。
每个派生数字标单位及代入式，排序结果保留触发规则，不把排序靠前写成已经批准。一次改动只替换被证实改变的输入，同时重算本子任务所有相关结果；把改动前后两列保留下来，使主专家可以接续而无需猜测哪个版本生效。回传至少包含对象号、本轮结论、形成结果的输入、需要人工确认的最后一步。主专家若改变其它约束，应重新调用本能力，而不能直接改结果数字。

## 独立完成标准
交付新版递推、原版失效范围和一段具体班次或升级说明。
样例是清楚标注的假设，不能改成客户成效。工具没有接入真实业务系统，不写已经发通知、改状态、分配资源或完成现场作业。用户说明采纳只记为采纳，现场完成仍须用户另行反馈。


### 与最终成果的一致性
冲突未裁定不得按较大容量执行风险自负；短稿只给共同可行部分和待确认升级，峰值从底表取最大。将模块数值和依据交给主流程，正文、表格与话术须使用同一版本，不以模块自评代替最终工具与事实复核。
