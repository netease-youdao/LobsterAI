# 退换货事实冲突沟通表

本技能用于退换货双方陈述中的证据冲突。使用者提供脱敏订单摘录、退换货双方原话、收寄签收记录、商家提供的规则版本与授权范围，交付双方事实分歧矩阵、待核实时间线与不归责沟通草案。先列影响判断的缺项和冲突，再按问题编号展示证据；只根据实际给出的业务资料制作文本与表格，不作资质结论，不代替岗位人员确认事实。

## 工作流程

1. 1、先区分申请时间、寄出时间、签收时间与检验时间，保留记录原时区和日期格式，不把签收等同于完成检验。输入只来自用户提供的文本或表格，先列来源、日期和可用范围。资料里带个人信息时用代号替代，保留与任务有关的事实；没有提供的记录写【待补】，示例不参与实际判断。

2. 2、客户描述与商家描述分别记录，陈述相同但无证据时只能称双方一致陈述，不能提升为已经证实的事实。逐条编号并建立对象映射，原句与整理后的字段分开保存。一个对象有多条记录时先核是否同一事件、同一版本，不能因文本相似删除真实不同记录，无法确定则列待核。

3. 3、回复先确认已收到的信息，再复述双方尚未一致的事实，最后提出最少必要补充材料，避免指责、施压或归责。明确本次判断依赖哪些事实和业务条件，把未知、冲突、已确认分开。条件欠缺时给出能继续的局部成果和最少补充清单，不把信息缺失解释为不存在问题。

4. 4、客户不同意补充资料时给出仍可确认的事实摘要和授权复核路径，不写客户默认同意，也不代为撤销申请。按方法生成可由岗位人员审阅的文本草案，每个动作注明依据、前置条件、责任角色与待确认点。只组织给定资料，不声称已经通知人员、修改记录或执行现场动作。

5. 5、规则冲突时提交两个原文版本及订单时间供授权人员确认，沟通草案只说明等待复核的具体问题与责任岗位。检查数字单位、分母、时间截点、对象重复和状态转换，另请用户指定复核角色。新证据改变判断时保留原版本与修正原因，历史结论不静默替换，未复核项仍单列。

6. 6、一个争议点已经确认不意味着整单可闭环；逐项检查寄回数量、物品身份与状态证据是否仍有待核实字段。按模板交付主要表格、异常表和下一步问题，说明哪部分能直接复用、哪部分必须补资料。验收只依据本任务已确认条件，计划、人工确认与实际完成分别表述。

## 资料与对象界定

- 先区分申请时间、寄出时间、签收时间与检验时间，保留记录原时区和日期格式，不把签收等同于完成检验。 每条结论附对象编号和原文出处代号，便于业务人员回看；来源没有覆盖到的内容保持未知，不能由相邻记录或习惯做法推补。

- 客户描述与商家描述分别记录，陈述相同但无证据时只能称双方一致陈述，不能提升为已经证实的事实。 若两个来源不一致，保留双方值并指出影响哪些后续判断；没有指定生效版本时，请负责人确认，不自行挑选更有利的一方。

- 把“收到时破损”拆成包装状态、物品状态、拍摄时间和照片对象四项，证据仅覆盖包装时不能推断物品损坏原因。 输出时将已确认、待补、存在冲突分栏，字段变化须记录版本和原因；表格可供人工复核，但不能替代尚未发生的现场检查。

- 只引用商家实际提供的规则原文与适用版本，缺少生效时间或订单适用关系时标待核实，不替代授权人员作决定。 用给出的数字复算汇总并展示单位与分母，空值不视为零；异常必须有下一核实动作和责任角色，不能只写模糊的继续关注。

## 业务分支与处理方法

- 按争议点把证据分为支持、反驳、无关与无法判读，同一照片可支持状态却不能支持发生时间，分别说明覆盖边界。 每条结论附对象编号和原文出处代号，便于业务人员回看；来源没有覆盖到的内容保持未知，不能由相邻记录或习惯做法推补。

- 建立事件时间线时保留原始值和标准化值，日期倒置先核时区及录入误差，不通过重排事件掩盖冲突。 若两个来源不一致，保留双方值并指出影响哪些后续判断；没有指定生效版本时，请负责人确认，不自行挑选更有利的一方。

- 回复先确认已收到的信息，再复述双方尚未一致的事实，最后提出最少必要补充材料，避免指责、施压或归责。 输出时将已确认、待补、存在冲突分栏，字段变化须记录版本和原因；表格可供人工复核，但不能替代尚未发生的现场检查。

- 客户不同意补充资料时给出仍可确认的事实摘要和授权复核路径，不写客户默认同意，也不代为撤销申请。 用给出的数字复算汇总并展示单位与分母，空值不视为零；异常必须有下一核实动作和责任角色，不能只写模糊的继续关注。

## 异常复核与成果验收

- 规则冲突时提交两个原文版本及订单时间供授权人员确认，沟通草案只说明等待复核的具体问题与责任岗位。 每条结论附对象编号和原文出处代号，便于业务人员回看；来源没有覆盖到的内容保持未知，不能由相邻记录或习惯做法推补。

- 一个争议点已经确认不意味着整单可闭环；逐项检查寄回数量、物品身份与状态证据是否仍有待核实字段。 若两个来源不一致，保留双方值并指出影响哪些后续判断；没有指定生效版本时，请负责人确认，不自行挑选更有利的一方。

- 经办更正记录时保留原陈述、修正值、依据和复核人；补充材料不得覆盖早期证据或静默修改时间线。 输出时将已确认、待补、存在冲突分栏，字段变化须记录版本和原因；表格可供人工复核，但不能替代尚未发生的现场检查。

- 成果交付包含中性客服文本和核实表，不计算优惠扣回、保险赔偿或退款承诺，不作法律责任与资格判断。 用给出的数字复算汇总并展示单位与分母，空值不视为零；异常必须有下一核实动作和责任角色，不能只写模糊的继续关注。

## 假设案例

假设订单甲有三件物品，客户申请退回两件。寄件清单写两件，签收摘录只记一箱，商家初检记录写一件。箱数与件数单位不同，因此不能把“一箱”当成“一件”来支持少寄结论。现阶段可确定申请两件、清单陈述两件、签收一箱、初检陈述一件，数量分歧为2－1=1件，但分歧不是客户少寄的事实。假设四个事件时间分别为5日10时申请、6日14时寄出、8日9时签收、8日11时初检，寄出到签收为43小时，签收到初检为2小时；只说明记录间隔，不推断运输责任。客服草案应复述清单与初检数量不同，请核对拆箱连续记录及物品代号。若后续授权人员确认另一件在同箱独立隔层，初检修正为两件，数量分歧为零；仍需分别核实两件物品状态，不能宣布退款已完成。此例所有数字均为假设，凭据与规则仍由用户提供，成果只用于沟通和事实留痕。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
