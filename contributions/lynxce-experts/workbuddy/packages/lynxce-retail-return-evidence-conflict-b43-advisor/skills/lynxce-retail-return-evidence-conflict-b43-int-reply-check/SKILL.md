# 退换货中性回复复核

内部技能独立任务：将归责句改写为事实与核实请求。输入为双方原话、事实矩阵、客服草稿，输出为归责词审阅表与两版中性回复；用“已知事实—存在分歧—下一核实项”结构，逐句删除无依据责任判断；没有获授权的期限和金额不出现在承诺句，保留客户诉求原意。

## 工作流程

1. 1、限定子任务为将归责句改写为事实与核实请求，仅接收双方原话、事实矩阵、客服草稿。保留资料版本、对象代号、人工确认范围与记录日期，缺少关键字段先列【待补】，不扩大为整段业务的最终决定。

2. 2、用子任务独立编号关联公开技能的问题行，输入原值与派生值分开；核同名对象、重复事件与单位。用“已知事实—存在分歧—下一核实项”结构，逐句删除无依据责任判断；没有获授权的期限和金额不出现在承诺句，保留客户诉求原意。

3. 3、建立将归责句改写为事实与核实请求的判定分支：输入完整则进入方法核对，存在冲突则并列两值待确认，条件不足则产出局部表格和补证问题，不能绕过依赖直接给结论。

4. 4、按照独特方法形成归责词审阅表与两版中性回复，逐行说明原记录、处理动作、依据及状态；需要人工确认的动作保留草案标签，不替工作人员填写已经完成或署名。

5. 5、复核本子任务中的数量、日期、证据覆盖与状态边界，随机抽回原文检查字段是否走样。发现错误保存原值、修正值和理由，不把空白直接当作零或默认同意。

6. 6、将归责词审阅表与两版中性回复回填为专家流程的中间成果，写明未解决的依赖与下一接收角色；尚未完成的子任务不升级为业务闭环，后续新资料按版本再次核对。

## 独特方法与证据粒度

- 用“已知事实—存在分歧—下一核实项”结构，逐句删除无依据责任判断；没有获授权的期限和金额不出现在承诺句，保留客户诉求原意。

- 把双方原话、事实矩阵、客服草稿按对象与事件分别编号，材料数量不等于已证实事项数量，合并记录前保留合并依据和关联行号。

- 对子任务输出归责词审阅表与两版中性回复明确字段定义，原值、解释与动作分列；每个解释只覆盖来源实际支持的范围。

- 两条记录相似时核对象与时间，不因语义相近删掉真实独立事件；同一记录多次出现时保留一次计数及引用位置。

## 子任务决策与模板使用

- 资料齐全且无矛盾时按将归责句改写为事实与核实请求执行，输出可复核中间表而不是整项业务完成声明。

- 关键条件缺失时列三项以内最小补充问题，写明每个问题改变哪一行判断，已经被用户说明未知的字段不反复追问。

- 冲突条目保留双方原话、发生时点和证据代号，请用户指定的业务负责人确认后再修订，未经确认保持待核。

- 模板里的【待补】需要逐项填写依据；该字段确实不适用时明确写不适用及原因，不用空白掩盖缺资料。

## 异常与验收

- 检查归责词审阅表与两版中性回复能否回连原问题编号，脱离对象的泛化建议移至说明区，不能混入事实表。

- 若补证只解决一部分条件，其他条件仍维持原状态；不要把一条新记录当成全部矛盾均已解决。

- 数值例子仅作方法演示，实务必须换成用户给出的数字并复算；单位、分母和时间截点均写在结果旁。

- 交付复核角色、仍欠资料和下一确认动作；只提供文本表格，不声称连接业务系统或已执行人员调度。

## 假设案例

以下为独立子任务的假设演示：假设六句客服草稿含两句归责、一句越权承诺、三句事实，保留三句事实，重写两句归责，将承诺改为复核请求，六句均有处置记录但不代表争议解决。本例与公开技能的整段成果分开，先保留输入原值，再写方法对应的派生字段、未完成条件及下一次核对动作。收到新证据时须核同一对象和版本是否适用，确认后回填原问题编号；不能用本例默认值补真实记录。复核人员应逐行看原值与结果的映射，若用户没有给出复核结果，交付状态仍写待人工复核。示例数字只供解释计算与状态边界，不代表实际订单、门店人数、执行结果或任何系统数据。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
