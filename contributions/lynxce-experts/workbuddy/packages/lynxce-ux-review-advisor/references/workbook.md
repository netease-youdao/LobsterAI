# 可复制走查交付单

```text
产品版本／目标用户／任务编号／材料编号：
任务：开始条件｜用户目标｜成功标志｜权限设备｜材料覆盖范围。
路径表：步骤｜用户意图｜界面动作｜系统状态｜可见反馈｜证据。
问题表：编号｜触发前提｜复现步骤｜实际表现｜任务影响｜严重级别｜频率依据。
改稿表：原提示｜建议提示｜主动作｜恢复去向｜所依赖的真实系统能力。
状态表：初次空态｜搜索空态｜加载｜失败｜权限不足｜完成；各列条件与反馈。
复测表：任务说明｜不提示答案的引导语｜预期完成证据｜求助记录｜结果。
优先清单：问题编号｜主改动｜责任角色｜验收标准｜待确认实现。
结论：已覆盖／未观察／下一步；末尾最多三个关键问题。
```

## 已填假设示例：活动报名

示例假设报名流程为选择场次、填写联系资料、提交、查看报名编号；截图显示提交失败时只提示“出错了”，并清空已填内容。任务目标是报名成功后看到编号。问题U01判为“影响”：失败后可以重新填写，但用户不知道是否已提交，也无法保留输入；若材料进一步证实无任何可恢复方式且不能继续，才升级为阻断。

文案草稿为“暂未收到提交结果，请先查看报名记录，避免重复报名”。主动作为“查看报名记录”，次动作为“返回编辑”；保留输入及记录查询是否存在须由研发确认，不能把文案当成已实现功能。初次空态示例为“还没有报名记录，选择一个场次开始报名”，搜索空态为“没有符合当前条件的记录，可调整筛选后再试”。

假设五位首次使用者在相同任务下，三位独立完成，两位在错误页中断，无人求助后完成。观察完成比例为3/5即百分之六十，未完成比例为2/5即百分之四十；没有足够依据把这个比例推广到所有用户。三位完成者耗时80、100、120秒，中位数100秒；中断者计时不能直接混入“完成耗时”。

复测任务写“为周六上午场完成一份报名，并告诉观察者如何确认已完成”，不提示点击记录按钮。验收依据是参与者能找到唯一报名结果，异常后原输入仍在或有明确恢复方法。若改版后另五人四人独立完成，只报告本轮4/5为百分之八十，不把两组小样本差二十个百分点表述为因果提升保证。下次需要补交错误恢复录屏、实际重复提交规则与目标设备范围。
