# 配送承诺变更与回访核对

追踪承诺版本与履行凭证，防止改期覆盖原始约定。。输入范围仅限用户给定的仓储物流业务材料；与公开技能分工，独立完成此项中间成果再交专家复核。

## 工作流程

1. 收集历次沟通记录与承诺文本，逐条标出提出方、接收方、时间及确认状态。

2. 用承诺编号贯穿改期版本，新承诺替换旧承诺必须附变更原因和双方确认资料。

3. 把发货、尝试送达和客户收货分成不同履行动作，不以任一节点替代全部完成。

4. 按核查时点筛选未履行事项，缺时区或截止时刻则先补资料，不编超期时长。

5. 制作面向客户的效果确认问题与面向承运的履行凭证问题，避免同一问法重复。

6. 交付版本链、未履行事项和回访草稿，用户提供确认反馈后再建议结案。

## 专属核查方法

- 确认同意是对哪个版本，不能把对旧版本的接受迁移至新版本。

- 记录原始约定、变更和实际履行三个时间，区分原因与结果。

- 没有履行反馈可列待回访，不应按预计完成时间自动关闭。

- 承诺次数可统计，但改期次数不能直接归因为服务责任次数。

## 证据与状态控制

- 先按本任务的复合业务键标记每条材料，保留原值与来源日期，关键字段缺失时只输出可确认部分及补证问题。

- 将输入事实、计算中间值与建议动作分列，复算结果需要能够回到对应单据或记录，不能靠结论倒填来源。

- 用户给定规则只在明确范围内使用，规则变更需记录版本；冲突时列适用条件，不将其他批次或其他任务的规则直接迁移。

- 输出给经办与复核角色审阅，确认资料齐全并不等于业务执行完成，任何现场结果须由用户补充反馈及验证记录。

## 交付与异常

- 输出本任务的领域表格与逐行问题，单位、时间、状态必须写全；没有依据的字段填【待补】，不以零代替缺失。

- 对异常记录给出最小补证动作及其预期证明的条件，不能仅写需要核查，必须说明核哪一项以及结果如何影响表格。

- 先列矛盾与未确认条件，再给条件式建议；存在反证时修订相关行并保留旧版，避免相互矛盾的承诺或计算同时有效。

- 收尾检查表头、合计、状态及来源索引一致，交付文本草案和人工处理清单；不声称联网检测、自动派发或修改系统记录。

## 假设案例

假设承诺P1版本一为周五16:00前送达，版本二改为18:00但只有承运提出，客户未确认；18:20取得客户实际收货反馈。相对原约定晚2小时20分钟，相对未确认的提议晚20分钟，两者不可混成同一考核结论。承诺记录2版、有效改约0次，因为缺客户接受证据。回访询问物品完整及是否还有未解决事项，收货确认不能替代破损争议结案。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
