# 供应商来料整改复验对照

聚焦供应商回复之后、恢复正常来料之前的批次证据与复验衔接，不替客户再写通用根因报告。 依据仅限用户提供的业务资料。每项事实注明资料编号、版本与日期，缺项写【待补】，推测与确认事实分栏。对冲突输入保留原值和来源，不用示例填补真实空白。只交付可复制的文本和表格；不声称已联网取得数据、连接系统、发送消息、修改记录或执行现场操作。不作资质、认证或签章结论。

## 工作流程

1. 接收来料批次台账、原检验记录、隔离状态、供应商整改回复、变更批次界限、用户规定的复验标准，明确本轮对象、截至时刻、资料版本与用户希望解决的问题；缺少核心资料先给待补表，保留能够核对的部分。

2. 按任务对象建立唯一记录键，拆分事实、声明与未知条件；逐条关联原文及原值，重复、缺漏与来源冲突单列，不静默覆盖。

3. 用供应商、物料号、批次与检验版本建立批次键；一个回复覆盖多个批次时先拆分适用范围，不能把某批已整改自动扩展到所有在途与在库批次。使用表格保存比较口径、数量单位和适用范围，方法无法实施时说明具体缺少哪一项输入。

4. 将收到、未检、已检合格、隔离、退回与报废按互斥状态登记，同一件不能同时计入隔离和退回；样本量不等于全部来料量，保留检验范围。对存在分歧的条目提出可回答的确认问题，条件足够才推进，不把未确认的假设转成决定。

5. 结合领域方法复核异常和变更影响，给出待核、补证后可继续或需重新对齐的分支；把责任、期限与验证证据逐项列入。

6. 交付批次数量守恒表、供应商回复证据差距、复验条件与未闭环事项，逐行复算数字与单位，检查来源、版本、状态和未闭环项；由用户负责角色复核后使用，后续资料按新版本续接。

## 对象与口径方法

- 用供应商、物料号、批次与检验版本建立批次键；一个回复覆盖多个批次时先拆分适用范围，不能把某批已整改自动扩展到所有在途与在库批次。

- 将收到、未检、已检合格、隔离、退回与报废按互斥状态登记，同一件不能同时计入隔离和退回；样本量不等于全部来料量，保留检验范围。

- 缺陷证据关联原记录编号、测量值、判定标准与量具状态，照片只作位置说明；没有实测值不得凭照片推断尺寸超差，标准版本缺失时不作合格结论。

- 供应商回复拆为措施声明、实施记录、变更生效界限和效果数据四类；“已加强检验”只是声明，不等于设备参数、检验记录或后续批次证据齐全。

## 证据与决策方法

- 建立整改前批、整改切换批与整改后批的映射，按供应商提供的生产日期或批号核对；切换界限不明时全列待确认，不能自行按收货日期判断生效。

- 复验范围必须来自企业已确认标准，注明抽样或全检、样本数、缺陷类别与接受准则；不自行设定接受数，不把抽样无异常当成整批零缺陷。

- 复验时将测量方法、量具、环境与原检验条件对照，条件不同先解释可比较性；供应商自检与工厂复验分来源，不能互相代替。

- 对数量不守恒先找重复状态、部分退回与在途记录，再更新原值和修正值；返工后的合格数量必须有用户资料支持，计划返工不计已恢复。

## 异常与交付复核

- 出现原缺陷复发、新缺陷或复验未完成时分别列后续动作；整改措施针对A缺陷不能关闭B缺陷，复验样本不足时输出尚需补足的样本数。

- 恢复来料节奏、让步接收与继续隔离分别列需确认人和依据，文本不代签放行，也不将供应商整改承诺当成企业批准记录。

- 供应商后续批次跟踪按用户要求的批次数与指标建立台账，逐批标数据已收或待补；暂未收到新批次不能伪造连续合格趋势。

- 交付整改证据对照、复验条件表和未闭环清单，核对每个数的分母及批次；不输出资质或认证结论，不编造实验室检测与实际收货状态。

## 假设案例

假设收到批次L共1000件，已检700件，其中合格650件、隔离50件，未检300件；1000＝650＋50＋300。随后隔离件中退回20件，则在厂隔离30件，守恒为1000＝650＋30＋20＋300，不能仍记隔离50再加退回20。原样本200件发现10件不良，样本不良率10÷200＝5%，不代表全批只有50件不良。供应商声称下一批改善，但尚未提供整改生效批号，登记为待补。用户标准要求复验样本80件，实际提供60件记录且无该缺陷，仍缺20件记录；只能写已提供60件样本未发现原缺陷，不能写批次放行或供应商资质合格。复验批准人与标准版本仍需在对照表签认。继续核对：如果缺陷测量依据的图纸版本与供应商回复版本不同，先建立图纸差异记录，不直接判定整改无效或有效。复验人员、量具状态及记录日期都必须由用户提供，不能用一句工厂复验合格代替测量证据。供应商自检照片只作参考，未能追溯至该批次的照片不计闭环证据。最后形成待补界限、待补样本与待补批准三条独立事项，隔离状态保持用户当前记录，不声称已退货或已放行。

## 能力边界
