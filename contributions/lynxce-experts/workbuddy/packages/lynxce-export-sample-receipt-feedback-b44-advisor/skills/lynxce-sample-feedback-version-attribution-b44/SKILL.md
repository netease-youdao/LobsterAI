# 样品反馈版本归属核对

面向外贸跟单员与样品对接人的独立小任务：样品反馈版本归属核对。适用阶段为样品已寄出、客户签收与测试反馈待对应的阶段。最少事实输入为客户反馈原文、样品号版本清单、测试项目与条件摘录；交付反馈原句版本归属矩阵与澄清问题单。核心方法：用样品号、版本、项目、测试条件四要素绑定每条反馈；缺要素只生成候选，不将最新评论默认对应最新寄出版本。输入仅接收用户主动提供的脱敏文本或表格摘录，记录来源代号与原文位置；不要求业务系统接入，示例不能补真实资料。

## 工作流程

1. 给反馈原句编号，保留客户原语言与否定词。 接收时先登记来源、版本、对象范围和记录截点；若用户只给部分记录，交付已知范围并列最少缺项，不把没提供的数据补成零。

2. 从原句提取样品号和版本，未说的值保持未知。 对象编号与资料行号应分开，整理值不覆盖原值。重复引用是证据复用而不是新增业务对象，同名对象必须查身份关系再合并。

3. 将项目及测试条件关联标签清单，核是否同一对象。 处理时按本任务方法逐项核查，事实、陈述、派生计算和建议分别标识。支持某一条件的证据不可自动扩展到其它条件。

4. 四要素不足时给候选映射，不用寄送先后替代身份。 条件不全给局部成果，矛盾给双值及来源；请用户指定确认角色，不取平均、不选更有利数值，也不把询问草稿记为完成动作。

5. 统计可归属与待澄清条数，重复引用不增加反馈条数。 复核应从来源重新取原值，检查单位、分母、版本和状态互斥性；已明确未知的字段保持未知，不以合计能对齐反推缺失事实。

6. 交付逐句问题单，归属确认后才回填主表。 交付时保留仍未解决的行和下一核实动作，说明接收角色与完成凭据。新资料到来按原对象续版，人工确认与实际执行仍分开。

## 对象与资料门槛

- 反馈句数与样品数单列。

- 一条句子涉及两样须拆子句并留父号。

- 旧版标签照只能证旧版。

- 英文not tested不译为失败。

## 专属判断与异常分支

- 尺寸与颜色不要合并为满意度。

- 测试环境缺失不补常见条件。

- 客户转述与本人观察分栏。

- 同项目两条反向意见保留条件差。

## 输出验收与状态边界

- 最晚反馈不自动胜过早期反馈。

- 映射冲突不取多数意见。

- 不将意见当工程验收签字。

- 成果不包含认证和订单承诺。

## 五类内容设计假设案例（非模型实测）

- 正常：假设5条原句中3条四要素完整、2条缺版本。 预期：可归属3，待澄清2，共5条。

- 缺资料：假设反馈只有挺好二字。 预期：样品号、版本、项目【待补】，不归最新版。

- 矛盾：假设客户标V1，内部表标V2。 预期：保留双值，先核原标签。

- 边界：假设一条原句明确比较两款。 预期：拆2子句但原句仍1条，不把分句增加当新反馈。

- 超出能力：假设要求证明产品达到国外认证标准。 预期：仅整理反馈归属，不作认证判断。

## 假设案例

以下数字全部为可复算的内容设计假设，不代表真实业务或模型实测。假设5条反馈原句中3条均有样品号、版本、项目与条件，2条只提型号。3＋2＝5，可归属比例3÷5＝60%。其中一完整句比较两款，可拆两子句展示，原句分母仍为5而非6，不用分句提高反馈覆盖率。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
