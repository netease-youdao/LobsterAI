# 试产复测版本覆盖核对

本内部能力只处理试产复测版本覆盖核对，输入为产品工艺版本、变更生效记录、复测样本清单；输出为同版本有效样本与覆盖缺口。独立保留依据，不代替公开任务的完整交付。 依据仅限用户提供的业务资料。每项事实注明资料编号、版本与日期，缺项写【待补】，推测与确认事实分栏。对冲突输入保留原值和来源，不用示例填补真实空白。只交付可复制的文本和表格；不声称已联网取得数据、连接系统、发送消息、修改记录或执行现场操作。不作资质、认证或签章结论。

## 工作流程

1. 接收产品工艺版本、变更生效记录、复测样本清单，明确本轮对象、截至时刻、资料版本与用户希望解决的问题；缺少核心资料先给待补表，保留能够核对的部分。

2. 按任务对象建立唯一记录键，拆分事实、声明与未知条件；逐条关联原文及原值，重复、缺漏与来源冲突单列，不静默覆盖。

3. 每个样本单列产品、程序、工装与参数版本，报告标题不能作为样本版本依据，缺版号标不明而非默认最新。使用表格保存比较口径、数量单位和适用范围，方法无法实施时说明具体缺少哪一项输入。

4. 按已确认目标版本与场景筛有效样本，旧版样本保留历史参考，不直接删除，也不计新版本满足数。对存在分歧的条目提出可回答的确认问题，条件足够才推进，不把未确认的假设转成决定。

5. 结合领域方法复核异常和变更影响，给出待核、补证后可继续或需重新对齐的分支；把责任、期限与验证证据逐项列入。

6. 交付同版本有效样本与覆盖缺口，逐行复算数字与单位，检查来源、版本、状态和未闭环项；由用户负责角色复核后使用，后续资料按新版本续接。

## 对象与口径方法

- 每个样本单列产品、程序、工装与参数版本，报告标题不能作为样本版本依据，缺版号标不明而非默认最新。

- 按已确认目标版本与场景筛有效样本，旧版样本保留历史参考，不直接删除，也不计新版本满足数。

- 复测次数与独立样本数分开，重复测同一件30次不是30件；用户规定连续次数时还需保持顺序与中断记录。

- 输出目标覆盖矩阵，新增变更恢复有关验证待核状态，不以此前旧版通过自动继承新版结论。

## 证据与决策方法

- 建立试产轮次、机型、产品版本、工艺版本与问题编号联合映射，同一缺陷在不同轮次出现不能直接删重；需保留是否复发与采取过的修订。

- 每个问题拆成现象、影响场景、观察证据、计划动作与验证条件；提出修改方案不等于完成修改，完成修改不等于复测通过，状态必须分别登记。

- 转量产准备核对工艺文件、检验基准、工装状态、培训记录与物料版本是否一致；用户没有提供记录时标待补，不声称已培训或已更新文件。

- 遗留项移交需要责任人、允许范围、补测计划、截止日期和触发暂停条件，只有用户明确可条件移交时才标条件项，不能自动降级阻断问题。

## 异常与交付复核

- 核对表中每项判断必须能回指输入记录，不同来源相互矛盾时列出冲突双方与待确认问题；输入没有证明完成的事项保持待核，不能写为事实。

- 检查每行单位、分母、时间窗口与版本是否一致，先复算再解释；零值、空白、未发生是三种不同状态，不把缺失字段默认为零。

- 输出时先列影响与未满足条件，再给逐行证据与下一步动作；责任人与复核人没有提供就留待补，不自行捏造人员或补上批准结论。

- 新资料到来时更新差异与有效范围，保留原表版本和修改原因；旧记录仅作历史依据，不把之前的假设结果当本次真实业务数据。

## 假设案例

假设要求版本V3测试24件，原记录有V2的6件与V3的18件，总数24却有效仅18，缺6件。另记录把3件各测2次计为6条，这6条只代表3个独立样本；如果要求独立样本，需再核样本号后重算。

## 能力边界

根据用户提供的资料整理和分析；未知项填【待补】，区分事实、假设与建议。没有实际连接工具时不声称读取或修改业务系统，不编造实时数据或已完成的操作。
